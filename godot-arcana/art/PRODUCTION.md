# 분수 광장 제작 기록

## 2026-10-28 · 원래 아르카나 일러스트의 도시 디자인 적용

사용자는 기존 게임의 `assets/scenes/arcana-plaza.png`와 `assets/map-arcana-downtown-v2.png`를 확인하고 같은 느낌의 게임 세상을 요청했습니다. 이번 작업은 기존 광장·아카데미·포탈·남문·상점 실내에 원본의 건축과 색을 연결하는 범위입니다. 지역·서버 기능을 늘리거나 배치 장면을 다시 생성하지 않았습니다.

### 제작 명세와 구현

- 디자인 기준은 기존 일러스트 두 장입니다. 저해상도 정사영의 실제 3D 모델과 저장된 `scenes/plaza.tscn`의 원점·문 위치·축척을 사용하며, 문과 기존 인물을 함께 놓아 비교합니다. 인물의 고정 디자인과 이동·출입·저장·충돌 규칙을 이번 작업에서 교체하지 않았습니다.
- `scripts/pixel3d_models.gd`의 건물을 파란 기와·밝은 석재·금빛 능선과 처마·아치창·지붕창·첨탑으로 수정했습니다. 상점은 보라색 차양과 포션 간판, 식당은 파랑·상아색 차양, 여관은 보라색 초승달 간판을 사용합니다. 아카데미는 쌍첨탑·천문 돔·망원경을, 포탈은 금빛 테두리·보라색 아치·푸른 면을 사용합니다.
- 분수는 원래 도심 지도의 **푸른 구체와 금색 천체 고리**로 변경했습니다. 기존 원형 수반, 반경 2.25, 로컬 Z=-0.7, 네 방향 낙수와 물 무늬의 시각 시계는 유지했습니다. 앞선 독립 수정 분수 시안은 원본 파일로 남겼으며 현재 도시의 분수 기준은 천체 고리입니다.
- 석재 화단·창가 꽃·금빛 등불·파란 깃발과 남문 탑·성벽의 색을 공유합니다. 광장과 길의 기존 영역 안에는 상아색 석판, 분수 둘레의 가는 금빛 원과 드문 파랑·금색 마름모를 넣었습니다. 실내에는 같은 아치창·석재·보라 깃발을 연결했습니다.
- 월드용 64색 원본은 `art/source/arcana-world-64.gpl`입니다. 기존 2D 자산의 `arcana-64.gpl`과 출력 PNG는 재추출하지 않았습니다. `scripts/build-arcana-palette.py`가 새 원본에서 1024×32 LUT와 화면 셰이더를 함께 생성하며 `bake-arcana-art.py --palette-only`도 이 빌더를 사용합니다. 팔레트는 완성된 월드 텍스처에 한 번 적용하고 HUD는 제외합니다.
- 원본 외곽선의 역할별 강도와 공통 픽셀 단위는 이어갑니다. 금속·석재·꽃은 실제 모델 재질이며, 큰 일러스트를 한 장의 이동 배경으로 붙이지 않았습니다. 기존 모델·렌더러 편집 전 사본은 `.runtime/godot/royal-city-before/`에 보관했습니다.

### 확인한 결과와 남은 확인

- 실제 Godot GPU 렌더에서 [광장](reference/pixel3d-plaza.png), [천체 고리 분수](reference/pixel3d-fountain.png), [도심 전체](reference/pixel3d-city-overview.png), [실내](reference/pixel3d-interior.png)의 색과 형태를 확인했습니다. 광장·실내 출력은 384×824입니다. 도심 전체는 게임 카메라를 바꾸지 않고 넓은 검토용 카메라로 출력한 768×824입니다.
- Godot import와 Web export를 완료해 `/godot/` 산출물을 갱신했습니다. 같은 작업 공간에서 들어온 표시 경로 변경은 보존하고, 오프라인 렌더 도구의 출력 뷰포트와 문자열 경로의 이름 충돌을 수정했습니다.
- 이번 작업에서 브라우저 조작·플레이 테스트·모바일 성능 측정은 하지 않았습니다. 사용자가 직접 확인할 경로는 새로고침 후 광장의 파란 지붕·보라 차양·천체 분수, 상점 출입, 포탈·아카데미 방향 이동과 기존 가림입니다. 원본 일러스트 수준의 장식 밀도나 최종 미술 승인을 완료한 것으로 표시하지 않습니다.

아래 항목은 이전 작업의 제작 이력입니다. 현재 도시 디자인은 이 항목과 `ARCANA_ART_GUIDE.md`의 현재 디자인 절을 우선합니다.

## 2026-10-27 · 움직임과 지면 보완

사용자가 제시한 World of Anterra 화면을 도트 월드의 미술 방향 참조로 삼습니다. 높은 밀도의 식생·자연스러운 지형 경계·일관된 인물 비례를 목표로 하며, 기존 게임 자산을 복제하지 않습니다. 별도의 애니메이션풍 클라이언트를 만드는 요청이 아닙니다.

- 32×48 인물 프레임과 공통 팔레트를 유지하고 보행을 방향별 8포즈로 확장했습니다. 아틀라스는 256×384이며 정지는 방향별 2포즈입니다. 원본의 다리·소매를 나눈 합성 방식으로, 완성된 수작업 동작 원화를 대신하지 않습니다.
- 실제 이동 거리로 보행 프레임을 선택하여 벽에 막히거나 느리게 걷는 여행자가 제자리걸음을 하지 않게 했습니다. 카메라는 완만하게 따라오되 반 픽셀 월드 좌표에 고정해 도트 필터를 유지합니다.
- 지면의 풀 군락·풀잎·작은 꽃·흙의 잔돌을 같은 팔레트 안에서 보강했습니다. 16종 경계 마스크와 이웃 경계 계약은 유지합니다.
- 분수 물방울과 물결을 분수 자체의 자식 레이어에 올려 그림 뒤에 가려지지 않게 했습니다. 바람과 분수 셰이더는 게임의 시각 시계를 따르며 메뉴에서 멈춥니다.
- 불꽃 궤적·폭발·피해 숫자는 객체 위에서 그리며 숫자를 실제 적 위치에 표시합니다. 적 체력 표시는 불꽃 도착 시점에 맞춥니다. 서버의 전투 판정은 바꾸지 않습니다.
- 화면 효과 줄이기 설정에서는 카메라 지연·환경 효과·이동 입자를 생략하고 피해 숫자는 유지합니다.

자산 재출력의 규격·팔레트·알파 계약과 Godot Web 빌드를 확인했습니다. 브라우저 및 플레이 테스트는 사용자의 선호에 따라 실행하지 않았습니다. 직접 확인할 항목은 네 방향 걷기·벽 앞 정지·여행자의 느린 보행·분수 물결·메뉴의 환경 정지·파이어볼 명중입니다. 안테라 수준의 최종 미술 완성도나 모바일 성능을 검증한 상태는 아닙니다.

## 2026-10-27 · 실제 3D의 도트 렌더링

사용자가 제공한 영상과 [Never's End 개발자의 GDC 자료](https://blog.hypersect.com/how-we-draw-a-3d-sprite-world-gdc2026/)를 참고해 Godot 화면을 실제 입체 모델 기반으로 전환했습니다. 새 모델·재질·리그는 저장소의 코드로 작성했습니다. 외부 게임 모델이나 그림은 가져오지 않았습니다.

- 기본 경로 `/godot/`가 3D 장면을 사용합니다. 기존 `world.gd`는 경로·충돌·위치·상호작용을 계속 계산하고, 화면만 `pixel3d_world.gd`가 담당합니다. 카메라 레이를 지면에 교차시켜 원래 이동 좌표로 변환합니다. 기존 게임 ID와 저장 위치, 서버 API는 유지합니다.
- `pixel3d_models.gd`에 지붕·벽·문·창·화분·분수·나무·생활 소품의 실제 메시를 조립하고, 같은 재질은 합쳐 재사용합니다. 캐릭터는 `pixel3d_actor.gd`의 다리·무릎·팔·팔꿈치·머리·망토 관절을 사용합니다. 동작은 실제 이동 거리에서 계산하고 도트 모드에서 12fps 포즈와 8방향 회전으로 제한합니다.
- 월드만 물리 화면의 절반 해상도로 그리고 정확히 2배 최근접 확대합니다. HUD는 기존 해상도입니다. 홀수 크기는 한 픽셀 넘겨 그려 픽셀 폭이 불균일해지지 않게 합니다. 카메라·인물 뿌리는 화면 픽셀 단위로 맞춥니다. 짧은 이동에서는 카메라가 머물고 멈춘 뒤 따라잡는 표류를 만들지 않습니다.
- 정사영 카메라, 단계 명암, 메시 외곽선, 실제 방향광 그림자를 사용합니다. 화면에서 물체의 깊이를 얇게 눌러 앞뒤를 정하되, 조명·그림자 패스는 원래 3D 형상을 유지합니다. 현재 고정 카메라의 지면 Z 정렬이며 발표의 AABB 관계 그래프·순환 해결 전체를 구현한 것은 아닙니다.
- 메뉴의 **3D 원본 비교 / 도트 화면으로**는 같은 3D 장면의 해상도와 포즈 제한을 전환합니다. 비교할 때 모델·게임 상태·카메라의 월드 범위는 유지됩니다.

### 적용과 확인

- 침엽수의 완전한 원뿔 네 개를 높이와 방향이 어긋난 가지 층으로 바꾸고, 활엽수는 크기·위치가 다른 잎 덩어리로 구성했습니다. 나무는 인물 옆에서 작은 장난감처럼 보이지 않도록 높이와 수관 비례도 보완했으며, 뿌리·기존 위치·충돌 계약은 유지합니다.
- `pixel3d.gdshader`에 재질별 픽셀 붓 자국을 추가했습니다. 모델 공간에서 고정된 무늬를 사용하며 그림자 감쇠도 단계로 구분합니다. 기와·나무결·돌·옷·잎이 같은 평면 무늬를 공유하지 않습니다.
- 도트 모드의 색 제한은 3D 월드 뷰포트 내부의 2D CanvasLayer에서 처리합니다. `pixel3d_palette.gdshader`는 기존 공통 64색에서 가까운 색을 선택하며, 별도 루트 HUD를 덮지 않고 입력을 받지 않습니다. 메뉴의 원본 3D 비교에서는 이 처리를 끕니다.
- `python scripts/bake-arcana-art.py --palette-only`는 공통 팔레트에서 색 제한 셰이더를 다시 생성합니다. 기존 전체 자산 재출력에도 같은 과정이 포함됩니다.
- [광장](reference/pixel3d-plaza.png), [나무와 인물의 비례](reference/pixel3d-garden.png), [실내](reference/pixel3d-interior.png)를 실제 Godot 오프라인 GPU 렌더로 확인했습니다. 384×824 광장에는 62색이 쓰였으며 모두 공통 64색에 속합니다. 무늬와 팔레트의 화면 비교 후 웹 export를 갱신했습니다.

사용자의 열린 게임 탭은 조작하지 않았습니다. 실제 이동 중의 가독성·가림·모바일 성능과 사용자 미술 승인은 남아 있습니다. 정지 화면 확인만으로 최종 미술 완료를 선언하지 않습니다.

- `scripts/sprite_actor.gd`는 카메라를 향하는 그림판에 대기 두 포즈와 걷기 여섯 포즈를 표시합니다. 실제 이동 거리가 걷기 진행을 결정하고, 카메라/이동의 매 프레임 갱신은 유지합니다. 알파를 잘라 불투명 깊이에 참여시키며, 기존 월드와 같은 발 위치 기반 깊이·잉크·접지 그림자를 적용합니다.
- `pixel3d_world.gd`의 주인공만 새 클래스를 씁니다. 기존 여행자·상점 NPC·게임 판정과 저장 상태는 유지했습니다. `arcana_placement.gd`의 주인공 미리보기에도 같은 클래스를 연결했으며 사용자 `scenes/plaza.tscn`은 수정하지 않았습니다.
- 작은 얼굴이 절반 해상도에서 지워지는 것을 확인해 기본 도트 출력 밀도를 높였습니다. 전체 화면의 정수 픽셀 단위와 별도 HUD, 현재 도시 팔레트 처리는 유지합니다. 개발용 고해상도 스타일 후보 폴더는 웹 내보내기에서 제외했습니다.
- 자산 변환 계약(32프레임·46색·이진 알파), Godot import/Web export, 실제 GPU의 [광장](reference/pixel3d-plaza.png)·[실내](reference/pixel3d-interior.png)·[모든 방향/걷기 포즈](reference/hero-b45-rendered-poses.png)를 확인했습니다. 렌더 검수 첫 실행은 출력 뷰포트와 경로 변수의 이름 충돌로 중단됐고, 해당 충돌이 해소된 소스로 한 번 재실행해 성공했습니다.

플레이 테스트는 사용자가 직접 진행하는 선호에 따라 브라우저 탭을 조작하지 않았습니다. 확인할 항목은 새로고침 후 앞/뒤/좌/우 이동, 멈췄을 때 대기 복귀, 나무·건물 뒤에서의 가림, 상점 출입, 기존 진행 유지 및 실기기 FPS입니다. 선택한 원화의 모든 세부가 모든 화면 크기에 동일하게 보장되거나 최종 사용자 미술 승인이 끝났다고 표시하지 않습니다.

## 2026-10-28 · 주인공을 실제 관절형 3D 모델로 전환

사용자의 ‘캐릭터도 3D로’ 요청에 따라 B 비례와 기존 의상을 바탕으로 `scripts/hero_actor.gd`를 제작했습니다. 기존 2D 인물 시트는 보존합니다.

- 약 1.95단위 높이의 머리·얼굴·밤색 앞머리/옆머리·청록 외투·어깨 망토·셔츠·허리띠·가방·부츠를 입체 메시로 구성했습니다. 외투·망토는 단면을 잇는 메시이며 앞머리는 끝이 가늘어지는 덩어리로 정리했습니다. 머리·몸통·어깨·팔꿈치·엉덩이·무릎의 이름 있는 관절이 있습니다.
- 실제 이동 방향에 맞춰 8방향으로 회전하고, 기존 이동 거리·시각 시계를 사용해 보행과 대기를 계산합니다. 발을 지면에 맞추고 인물 전체의 기준점으로 가림·외곽선을 정렬합니다. 기존 저장·충돌·캐릭터 시작 위치는 유지합니다.
- 게임 주인공과 Godot의 hero 배치 미리보기는 같은 클래스를 사용합니다. `scenes/characters/hero.tscn`은 독립 모델 확인용 장면입니다. 사용자 광장 배치 파일은 재생성하거나 덮어쓰지 않았습니다.
- Godot import/Web export와 실제 GPU의 광장·방향별 보행 렌더를 확인했습니다. [정면·대각·측면·후면](reference/hero-3d-turntable.png)은 실제 모델을 회전해 렌더한 결과입니다. 재출력은 `pwsh -File scripts/render-hero3d.ps1`입니다. 모델은 1차 제작이며 최종 미술 승인은 사용자 확인으로 남깁니다.
- 도트 출력·카메라 확대·주인공 추적은 유지했습니다. 실제 플레이 중 모든 가림·출입·모바일 성능 검수는 이번 모델 렌더 확인에 포함하지 않습니다.

## 2026-10-28 · 편집 화면과 게임의 건물 재질 통일

편집용 `arcana_placement.gd`가 게임의 ShaderMaterial을 단색 StandardMaterial3D로 치환해 지붕·석재·목재 무늬와 단계 명암·발광이 사라지던 경로를 제거했습니다. 같은 재질을 복제하고 `editor_preview`만 켜서 자유 시점에 맞는 실제 깊이를 유지합니다. 편집 광장의 낮 조명·주변광·그림자 설정도 현재 게임과 맞췄습니다. 저장된 배치와 건물 모델은 수정하지 않았습니다.

편집 뷰포트에는 게임의 깊이 압축·카메라용 외곽선·정수 확대·64색 후처리가 없으므로 최종 출력은 F6/F5에서 확인합니다. 기존 문서의 ‘편집용 일반 3D 재질’ 설명은 이 항목으로 대체합니다. Godot import/Web export로 소스 연결을 확인하며, 사용자의 열린 편집기·게임을 조작하는 시각 검증은 수행하지 않았습니다.

## 2026-10-28 · 분수 아래 석재의 경계 보완

사용자가 도트 화면에서 아래 벽돌의 색과 경계가 사라지는 점을 지적했습니다. 분수 전용 석재 재질에 실제 20개 돌 배치를 따르는 회갈색 줄눈과 측면 명암을 넣고, 윗돌 아래 얇은 그늘과 기단의 색을 보강했습니다. 넓은 윗면은 밝게 남기되 가장 밝은 돌색의 반복을 줄였습니다. 월드 팔레트·다른 건물 재질·분수 배치·충돌 영역은 수정하지 않았습니다.

실제 Godot GPU 도트 렌더에서 [분수 경계](reference/pixel3d-fountain.png)를 확인하고 Web export를 완료했습니다. 확대 이미지는 현 카메라에서 수반 기단까지 포함하도록 자르기 범위를 보완했습니다. 사용자의 열린 게임은 조작하지 않았으며 실제 플레이·기기 성능 확인은 실행하지 않았습니다.

## 2026-10-28 · 풍선처럼 보이던 나무 수관 개선

사용자가 구체를 매단 듯한 나무 형태를 지적해 `scripts/pixel3d_models.gd`의 나무 세 종을 수정했습니다. 원래 아르카나 도심 일러스트의 식생과 현재 공통 도트 출력·인물 축척을 기준으로 합니다.

- 잎에 쓰던 구체를 닫힌 비대칭 메시로 교체했습니다. 얕은 윗면, 잎끝과 홈이 있는 외곽, 어두운 아랫면이 이어지며 작은 잎가지가 바깥 실루엣을 나눕니다. 덩어리별 교대 원색과 검은 외곽선은 제거하고 기존 초록·청록 팔레트와 잎 재질을 사용합니다.
- 참나무는 낮게 갈라지는 굵은 가지와 넓게 이어진 수관, 자작나무는 좁고 높은 수관·밝은 줄기·엇갈린 수피 자국, 침엽수는 바깥으로 처지는 가지와 위로 갈수록 좁아지는 잎층으로 구분했습니다. 줄기와 가지는 끝으로 갈수록 가늘어지고 밑동에는 뿌리를 붙였습니다.
- 기존 나무의 지면 원점과 성장 배율(가로 1.15, 높이 1.55), `scenes/plaza.tscn`의 사용자 배치·회전·충돌 영역을 유지합니다. 편집기와 런타임은 같은 모델 함수를 사용합니다.
- [세 종과 주인공의 비교 렌더](reference/trees-3d-study.png)는 실제 Godot GPU에서 게임의 조명·64색 후처리·2배 최근접 표시로 출력했습니다. 재출력: `pwsh -File scripts/render-godot-pixel3d-art.ps1 -Trees`. `tools/render_trees.gd`는 미술 확인 전용이며 저장 데이터나 사용자의 열린 게임을 조작하지 않습니다.

소스 제작·정지 미술 렌더·Godot import/Web export를 완료했습니다. 실제 광장 배치에서의 미술 승인·이동 중 가림·실기기 성능은 사용자의 플레이 확인으로 남깁니다.
