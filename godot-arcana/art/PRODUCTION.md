# 분수 광장 제작 기록

## 2026-10-28 · 실제 시작 장면의 광장 인스턴스 추가 이동 제거

사용자의 첨부 화면에서 분수 본체는 원무늬보다 아래에 있고 물방울은 본체 위의 빈 공간에 남아 있었습니다. 실제 `main.tscn`의 Plaza 인스턴스에 `Transform3D(...,0,-2,1)`이 저장되어 전체 모델만 Y=-2, Z=+1 이동한 것이 원인입니다. 원무늬·물방울·충돌은 광장 내부의 배치 좌표를 사용하므로 이 인스턴스 이동을 따르지 않았습니다. 이전 오프라인 검토는 `plaza.tscn`만 직접 읽어 시작 장면의 추가 Transform을 놓쳤습니다.

- `main.tscn`에서 Plaza 인스턴스의 추가 Transform을 제거했습니다. `plaza_layout.gd.normalize_coordinate_frame()`와 `world.gd`의 초기화·배치 재로드에서도 광장 루트를 단위 좌표계로 정규화합니다. 기존 자식 노드의 건물·분수·캐릭터 배치는 유지합니다. 개별 배치는 계속 `plaza.tscn` 안에서 편집합니다.
- `render_pixel3d_preview.gd`가 실제 `main.tscn`을 인스턴스화하고 그 안의 Plaza를 가져와 게임과 같은 World 초기화로 렌더하도록 수정했습니다. 메인 스크립트의 서버 연결·플레이 부트는 실행하지 않습니다. 이제 시작 장면에만 있는 인스턴스 설정도 확인 경로에 포함합니다.
- 밑면 원형 충돌과 단일 중심은 유지합니다. 이번 수정은 본체만 이동시켰던 상위 인스턴스 좌표를 바로잡은 것입니다. 앞선 화면 높이 보정으로 이 문제를 해결했다고 판단했던 기록은 잘못된 원인 판단이었습니다.

실제 시작 장면을 읽은 GPU 렌더와 Godot import·Web export를 완료했습니다. `http://127.0.0.1:3000/godot/index.pck` 응답의 SHA-256이 최신 로컬 산출물과 일치하는 것도 확인했습니다. 기존 열린 브라우저를 조작하거나 플레이하지는 않았습니다. 새로고침 후 적용된 화면에서 본체·물방울·원무늬·충돌을 확인할 수 있습니다.

## 2026-10-28 · 분수 중심 통합과 실제 원형 충돌

이전 화면 높이 보정 이후에도 사용자가 중심 어긋남과 분수 밖의 잘못된 충돌을 지적했습니다. 이전의 높이 0.62 역투영 보정을 폐기하고 모델·바닥 장식·충돌의 원점을 함께 정리했습니다. 아래의 이전 화면 중심 보정 기록은 현행 구현이 아닙니다.

- `scripts/fountain_spec.gd`의 로컬 중심 (0,0,0)과 밑면 반경 2.25를 공유합니다. 모델 내부의 Z=-0.7 오프셋을 제거하고, 저장된 분수 Transform을 기존 오프셋만큼 옮겨 실제 보이는 세계 위치는 유지했습니다. 현재 저장 원점은 (36,0,28.925)입니다. 석재·수면 무늬·낙수·물방울도 새 모델 원점을 사용합니다.
- 분수의 예전 사각형 `collision_footprint`를 장면에서 제거했습니다. `arcana_placement.gd`는 fountain 종류의 사각형 값을 사용하지 않고 동일한 Transform으로 원형 충돌을 계산합니다. `world.gd`의 직접 이동과 경로 탐색은 이 원형 판정을 공유하며 실내 진입·복귀·배치 재로드 때도 함께 관리합니다. 이동·회전·비균일 배율은 역변환한 로컬 원으로 판정하고 기존 발 간격 3픽셀을 적용합니다. 원무늬 전체나 사각형 모서리를 막지 않습니다.
- 편집기의 주황색 충돌 표시도 같은 원을 사용하고, 분수에는 사각형 충돌 편집 항목을 숨깁니다. 분수 위치 변경 시 바닥 원무늬는 같은 지면 중심을 다시 읽습니다. 별도의 높이 기반 중심은 없습니다.
- GPU 검토용 [충돌 경계 렌더](reference/pixel3d-fountain-collision.png)는 실제 `world.gd`에 설치된 원형 충돌에서 경계를 읽어 게임 화면 위에 표시합니다. 이 표시와 중심 십자는 오프라인 검토용이며 게임 화면에는 연결하지 않습니다. 실제 플레이·브라우저 조작은 별도로 실행하지 않았습니다.

Godot import·Web export를 완료했으며 최종 GPU 렌더에서 실제 충돌 경계가 분수 밑면에 맞는 것을 확인했습니다. 사용자가 확인할 항목은 새로고침 후 분수 둘레와 원무늬 위의 통행, 밑면 앞에서 정지, 편집기로 옮겨 저장한 뒤 모델·원무늬·충돌이 함께 이동하는지입니다.

## 2026-10-28 · 분수와 바닥 원무늬의 화면 중심 정렬

사용자가 분수가 바닥 원무늬 중앙에 보이지 않는다고 지적했습니다. 기존 원무늬는 지면의 수반 원점과 동심이었지만, 실제로 보이는 높이 0.62의 수반 테두리는 고정 정사영에서 위로 투영되어 간격이 달라 보였습니다.

- `plaza_layout.gd`가 분수의 전체 Transform으로 수반 테두리 중심 `(0,0.62,-0.7)`을 구하고, 게임 카메라의 기울기로 지면에 역투영한 `mosaic_center`를 셰이더에 전달합니다. 카메라 기울기는 렌더러와 같은 상수를 사용합니다. 수반·광장 지면의 원점과 충돌, 도로 위치를 옮기지 않고 장식 원무늬의 화면상 중심만 맞췄습니다.
- `pixel3d.gdshader`의 금색 원·파란 테세라·방사형 장식은 이 중심을 사용합니다. 큰길의 마름모와 전체 광장 포장은 기존 지면 중심을 유지합니다. 편집기에서 분수를 이동·회전·확대하면 0.15초 간격으로 장식 중심도 갱신합니다. 이 보정은 게임의 고정 카메라를 기준으로 합니다.
- 실제 GPU [광장 렌더](reference/pixel3d-plaza.png)에서 수반 테두리와 원무늬의 좌우·앞뒤 간격을 확인했습니다. 플레이·브라우저 조작은 실행하지 않았습니다.

## 2026-10-28 · 중앙 광장의 밀집 해소와 도시 구획 정리

요청은 분수 주변에 모인 건물과 소품을 떨어뜨리고 실제 도시처럼 공간을 정돈하는 것입니다. 원래 아르카나의 파란 지붕·밝은 석재·금색 장식과 천체 분수 디자인은 이어갑니다. 공유 배치 장면 `scenes/plaza.tscn`의 기존 노드를 직접 수정했으며, 저장 장면을 코드로 재생성하지 않았습니다.

- 중앙 분수의 저장 위치는 유지하고 포장 반경을 X=9, Z=8로 설정했습니다. 상점 (24.5,24), 식당 (49.5,24), 여관 (24.5,40), 북쪽 포탈 (24.5,12), 아카데미 (49.5,12), 동쪽 회랑 포탈 (52,38)로 나눴습니다. 좌표는 3D X/Z 단위입니다. 문 위치와 충돌은 원래 노드의 자식·로컬 값을 그대로 따라갑니다.
- 건물·소품·캐릭터 시작 위치 31개와 도심 나무 17그루를 이동했습니다. 벤치·화단·가로등은 광장 외곽, 상자·통·작업대·차양은 서쪽 작업 마당, 배달 소품은 식당 옆에 묶었습니다. 광장 중심과 네 방향 접근로를 비우고 나무는 작은 녹지와 가로수 위치로 정리했습니다. 기존 외곽 숲과 남문·평원 전환은 유지합니다.
- 큰길·동서 길·진입 골목·건물 앞마당의 포장 영역 17개를 장면 루트의 `paved_areas`에 저장했습니다. `plaza_radii`와 함께 편집기에서 수정할 수 있습니다. `plaza_layout.gd`가 같은 영역을 3D 지면 셰이더와 보존된 2D 타일 분류에 전달합니다. 분수 주변의 포장과 금빛 원은 수반의 실제 중심을 사용합니다. 가로등 광원도 저장된 물체 위치를 따라가며 배치 재로드 시 갱신합니다.
- 주인공 시작점은 (36,34.5), 여행자의 배회 기준은 (29,33.5)입니다. 오프라인 렌더 도구도 하드코딩된 옛 좌표 대신 장면에서 읽은 시작 위치를 사용합니다. 게임 기능·서버 장소 ID·소지품·저장은 변경하지 않았습니다.
- 실제 Godot GPU의 [광장](reference/pixel3d-plaza.png)과 [도심 전체](reference/pixel3d-city-overview.png)에서 건물과 분수의 간격, 앞마당·골목 연결과 외곽 배치를 확인했습니다. 도심 전체는 넓은 검토 카메라의 렌더이며 게임 카메라를 축소한 것이 아닙니다. 이전 배치 사본은 `.runtime/godot/city-layout-before/`에 보관했습니다.

Godot import와 Web export를 완료해 `/godot/` 산출물을 갱신했습니다. 북쪽 중앙길이 교차로에서 끝나도록 정리한 최종 배치의 GPU 렌더도 확인했습니다. 브라우저 조작·실제 플레이·모바일 성능 측정은 실행하지 않았습니다. 사용자가 직접 확인할 항목은 새로고침 후 넓어진 광장, 지도에서 상점·식당·여관으로 이동과 출입, 북쪽 시설·남문 연결입니다. 정지 렌더만으로 실제 경로 이동을 확인했다고 표시하지 않습니다.

## 2026-10-28 · 원래 아르카나 일러스트의 도시 디자인 적용

사용자는 기존 게임의 `assets/scenes/arcana-plaza.png`와 `assets/map-arcana-downtown-v2.png`를 확인하고 같은 느낌의 게임 세상을 요청했습니다. 이번 작업은 기존 광장·아카데미·포탈·남문·상점 실내에 원본의 건축과 색을 연결하는 범위입니다. 지역·서버 기능을 늘리거나 배치 장면을 다시 생성하지 않았습니다.

### 제작 명세와 구현

- 디자인 기준은 기존 일러스트 두 장입니다. 저해상도 정사영의 실제 3D 모델과 저장된 `scenes/plaza.tscn`의 원점·문 위치·축척을 사용하며, 문과 기존 인물을 함께 놓아 비교합니다. 인물의 고정 디자인과 이동·출입·저장·충돌 규칙을 이번 작업에서 교체하지 않았습니다.
- `scripts/pixel3d_models.gd`의 건물을 파란 기와·밝은 석재·금빛 능선과 처마·아치창·지붕창·첨탑으로 수정했습니다. 상점은 보라색 차양과 포션 간판, 식당은 파랑·상아색 차양, 여관은 보라색 초승달 간판을 사용합니다. 아카데미는 쌍첨탑·천문 돔·망원경을, 포탈은 금빛 테두리·보라색 아치·푸른 면을 사용합니다.
- 분수는 원래 도심 지도의 **푸른 구체와 금색 천체 고리**로 변경했습니다. 기존 원형 수반, 반경 2.25, 로컬 Z=-0.7, 네 방향 낙수와 물 무늬의 시각 시계는 유지했습니다. 앞선 독립 수정 분수 시안은 원본 파일로 남겼으며 현재 도시의 분수 기준은 천체 고리입니다.
- 석재 화단·창가 꽃·금빛 등불·파란 깃발과 남문 탑·성벽의 색을 공유합니다. 광장과 길의 기존 영역 안에는 상아색 석판, 분수 둘레의 가는 금빛 원과 드문 파랑·금색 마름모를 넣었습니다. 실내에는 같은 아치창·석재·보라 깃발을 연결했습니다.
- 월드용 64색 원본은 `art/source/arcana-world-64.gpl`입니다. 기존 2D 자산의 `arcana-64.gpl`과 출력 PNG는 재추출하지 않았습니다. `scripts/build-arcana-palette.py`가 새 원본에서 1024×32 LUT와 화면 셰이더를 함께 생성하며 `bake-arcana-art.py --palette-only`도 이 빌더를 사용합니다. 팔레트는 완성된 월드 텍스처에 한 번 적용하고 HUD는 제외합니다.
- 원본 외곽선의 역할별 강도와 공통 픽셀 단위는 이어갑니다. 금속·석재·꽃은 실제 모델 재질이며, 큰 일러스트를 한 장의 이동 배경으로 붙이지 않았습니다. 기존 모델·렌더러 편집 전 사본은 `.runtime/godot/royal-city-before/`에 보관했습니다.

### 확인한 결과와 남은 확인

- 실제 Godot GPU 렌더에서 [광장](reference/pixel3d-plaza.png), [천체 고리 분수](reference/pixel3d-fountain.png), [도심 전체](reference/pixel3d-city-overview.png), [실내](reference/pixel3d-interior.png)의 색과 형태를 확인했습니다. 광장·실내 출력은 384×824입니다. 도심 전체는 게임 카메라를 바꾸지 않고 넓은 검토용 카메라로 출력한 768×824입니다.
- Godot import와 Web export를 완료해 `/godot/` 산출물을 갱신했습니다. 같은 작업 공간에서 들어온 표시 경로 변경은 보존하고, 오프라인 렌더 도구의 출력 뷰포트와 문자열 경로의 이름 충돌을 수정했습니다.
- 이번 작업에서 브라우저 조작·플레이 테스트·모바일 성능 측정은 하지 않았습니다. 사용자가 직접 확인할 경로는 새로고침 후 광장의 파란 지붕·보라 차양·천체 분수, 상점 출입, 포탈·아카데미 방향 이동과 기존 가림입니다. 원본 일러스트 수준의 장식 밀도나 최종 미술 승인을 완료한 것으로 표시하지 않습니다.

아래 항목은 이전 작업의 제작 이력입니다. 현재 도시 디자인은 이 항목과 `ARCANA_ART_GUIDE.md`의 현재 디자인 절을 우선합니다.

## 2026-10-27 · 실제 3D의 도트 렌더링

사용자가 제공한 영상과 [Never's End 개발자의 GDC 자료](https://blog.hypersect.com/how-we-draw-a-3d-sprite-world-gdc2026/)를 참고해 Godot 화면을 실제 입체 모델 기반으로 전환했습니다. 새 모델·재질·리그는 저장소의 코드로 작성했습니다. 외부 게임 모델이나 그림은 가져오지 않았습니다.

- `pixel3d_models.gd`에 지붕·벽·문·창·화분·분수·나무·생활 소품의 실제 메시를 조립하고, 같은 재질은 합쳐 재사용합니다. 캐릭터는 `pixel3d_actor.gd`의 다리·무릎·팔·팔꿈치·머리·망토 관절을 사용합니다. 동작은 실제 이동 거리에서 계산하고 도트 모드에서 12fps 포즈와 8방향 회전으로 제한합니다.
- 월드만 물리 화면의 절반 해상도로 그리고 정확히 2배 최근접 확대합니다. HUD는 기존 해상도입니다. 홀수 크기는 한 픽셀 넘겨 그려 픽셀 폭이 불균일해지지 않게 합니다. 카메라·인물 뿌리는 화면 픽셀 단위로 맞춥니다. 짧은 이동에서는 카메라가 머물고 멈춘 뒤 따라잡는 표류를 만들지 않습니다.
- 정사영 카메라, 단계 명암, 메시 외곽선, 실제 방향광 그림자를 사용합니다. 화면에서 물체의 깊이를 얇게 눌러 앞뒤를 정하되, 조명·그림자 패스는 원래 3D 형상을 유지합니다. 현재 고정 카메라의 지면 Z 정렬이며 발표의 AABB 관계 그래프·순환 해결 전체를 구현한 것은 아닙니다.
- 메뉴의 **3D 원본 비교 / 도트 화면으로**는 같은 3D 장면의 해상도와 포즈 제한을 전환합니다. 비교할 때 모델·게임 상태·카메라의 월드 범위는 유지됩니다.

### 적용과 확인

- 침엽수의 완전한 원뿔 네 개를 높이와 방향이 어긋난 가지 층으로 바꾸고, 활엽수는 크기·위치가 다른 잎 덩어리로 구성했습니다. 나무는 인물 옆에서 작은 장난감처럼 보이지 않도록 높이와 수관 비례도 보완했으며, 뿌리·기존 위치·충돌 계약은 유지합니다.
- `pixel3d.gdshader`에 재질별 픽셀 붓 자국을 추가했습니다. 모델 공간에서 고정된 무늬를 사용하며 그림자 감쇠도 단계로 구분합니다. 기와·나무결·돌·옷·잎이 같은 평면 무늬를 공유하지 않습니다.
- 도트 모드의 색 제한은 3D 월드 뷰포트 내부의 2D CanvasLayer에서 처리합니다. `pixel3d_palette.gdshader`는 기존 공통 64색에서 가까운 색을 선택하며, 별도 루트 HUD를 덮지 않고 입력을 받지 않습니다. 메뉴의 원본 3D 비교에서는 이 처리를 끕니다.
- `python scripts/bake-arcana-art.py --palette-only`는 공통 팔레트에서 색 제한 셰이더를 다시 생성합니다. 기존 전체 자산 재출력에도 같은 과정이 포함됩니다.
- [광장](reference/pixel3d-plaza.png), [나무와 인물의 비례](reference/pixel3d-garden.png), [실내](reference/pixel3d-interior.png)를 실제 Godot 오프라인 GPU 렌더로 확인했습니다. 384×824 광장에는 62색이 쓰였으며 모두 공통 64색에 속합니다. 무늬와 팔레트의 화면 비교 후 웹 export를 갱신했습니다.

사용자의 열린 게임 탭은 조작하지 않았습니다. 실제 이동 중의 가독성·가림·모바일 성능과 사용자 미술 승인은 남아 있습니다. 정지 화면 확인만으로 최종 미술 완료를 선언하지 않습니다.

## 2026-10-28 · 캐릭터 경계와 그림자 선명도 보정

완료 조건은 기존 Blender 인물·게임 카메라·절반 해상도/최근접 확대를 유지하면서 캐릭터 바깥에 원본 1픽셀 경계를 만들고, 그림자의 옅은 경계 띠와 거리 소실을 줄이는 것입니다. 기준은 `ARCANA_ART_GUIDE.md`의 역할별 외곽선이며 모델·배치·진행 데이터는 이번 수정 범위에 포함하지 않습니다.

- `blender_hero.gd`와 `hero_skinned_ink.gdshader`: 월드 단위 .008 법선 확장을 제거했습니다. 같은 메시·스킨·뼈대를 쓰는 네 개의 실루엣을 화면 상하좌우 한 픽셀씩 이동합니다. 잉크는 공통 `#253c40`이고, 게임에서는 인물 전체 뒤의 발 기준 깊이에 놓아 내부 옷/관절을 덧칠하지 않습니다. 외곽선은 그림자를 만들지 않습니다.
- `pixel3d.gdshader`와 `hero_painted.gdshader`: 그림자 감쇠의 중간 단계를 제거해 경계에 흐린 띠가 생기지 않게 합니다. 면의 셀 명암과 페인트 텍스처는 유지합니다. 프로젝트의 태양 그림자는 Hard 필터와 32비트 깊이를 사용합니다.
- 게임과 편집 광장의 태양에 같은 설정을 적용합니다. 카메라의 지면 중심 거리는 약 32단위인데 기존 그림자가 28~35단위에서 사라졌으므로, 범위를 60단위까지 늘리고 거리 페이드를 제거했습니다. normal bias는 2에서 .6으로 낮춰 가느다란 그림자가 물체에서 떨어지는 정도를 줄입니다. 그림자 설정의 의미는 [Godot DirectionalLight3D](https://docs.godotengine.org/en/4.5/classes/class_directionallight3d.html)와 [ProjectSettings](https://docs.godotengine.org/en/4.5/classes/class_projectsettings.html)를 확인했습니다.

웹 산출물은 기존 Godot 내보내기 경로로 갱신합니다. 사용자의 테스트 선호에 따라 GPU 미술 렌더·브라우저 조작·플레이 테스트는 실행하지 않았으며, 정지/보행/방향 전환 중 경계와 발밑 그림자의 최종 시각 확인은 남아 있습니다. 기존 기준 PNG는 수정 전 렌더이므로 이번 결과를 입증하는 이미지로 사용하지 않습니다.


## 2026-10-28 · 머리에서 바닥으로 드리운 그림자 보정

사용자가 지적한 대상은 머리 표면의 명암이 아니라 바닥에 투영된 머리 그림자입니다. 열린 게임의 화면을 이동·새로고침 없이 읽었으며 머리 방향의 투영이 작은 가지처럼 갈라지는 모습을 확인했습니다.

`blender_hero.gd`에서 보이는 메시와 그림자용 메시를 분리했습니다. 몸·얼굴은 원본 스킨과 같은 뼈대를 쓰는 그림자 전용 메시로 투영하며, `Chestnut_hair`/`Hair_highlight`의 개별 머리카락은 그림자를 만들지 않습니다. 대신 머리 뼈대에 붙인 16분할 타원체가 머리카락의 큰 부피만 투영합니다. 머리 뼈대의 1.43 높이와 머리카락의 약 2.0 높이에 맞춘 반지름 .24/높이 .50의 전용 형상입니다. 보이는 머리카락·얼굴·외곽선과 원본 Blender 파일은 유지합니다.

그림자 전용 메시에는 표준 불투명 재질을 써서 화면 정렬용 깊이 압축과 분리하고 실제 광원 방향·지면·뼈대 애니메이션을 따릅니다. 웹 내보내기로 적용하며 플레이 테스트와 수정 후 게임 화면 확인은 실행하지 않습니다.


## 2026-10-28 · 쿼터뷰 카메라와 정면 비교

사용자의 쿼터뷰 요청에 따라 기본 카메라를 수평 45도 대각선 정사영으로 설정합니다. 기존 높이·내려다보는 각도·확대율·도트 출력과 저장된 광장 배치는 유지합니다. 메뉴에서 ‘정면 시점으로’ / ‘쿼터뷰로’를 전환하며 게임 진행이나 위치는 변경하지 않습니다.

- `pixel3d_world.gd`는 카메라 방향으로 회전한 지면 격자에 인물과 추적 중심을 스냅합니다. 정면에서 쓰던 월드 X/Z 스냅으로 대각선 픽셀이 흔들리는 경로를 피합니다.
- `world.gd`에서 키보드와 조이스틱을 합친 뒤 화면 축을 지면 축으로 한 번만 변환합니다. `main.gd`의 기존 조이스틱 선행 변환은 제거합니다. 클릭 이동은 기존 카메라 광선과 지면의 교차점을 사용하고, 계산된 경로점은 다시 회전하지 않습니다.
- 인물·건물 표면과 외곽선 셰이더의 발 기준 깊이 순서를 고정 Z축 대신 카메라 지면 방향의 내적으로 계산합니다. 정면 시점에서는 기존 순서와 같으며 대각선 시점에서는 X/Z 양쪽을 반영합니다. 실제 그림자용 지오메트리는 기존 광원을 따릅니다.

기존 Godot Web 내보내기로 적용합니다. 사용자의 테스트 선호에 따라 열린 브라우저 조작·플레이 테스트·GPU 미술 렌더는 실행하지 않습니다. 실제 화면 구도, 이동/클릭, 건물 뒤 가림은 사용자 확인으로 남깁니다. 기존 기준 PNG는 이번 쿼터뷰를 보여 주는 결과물이 아닙니다.

## 2026-10-28 · 선택한 백발 단발 미소녀 2번을 3D 주인공으로 연결

사용자는 일본 애니메이션풍 백발 미소녀 후보의 가운데 2번을 선택하고, 도트 화면에서도 캐릭터가 읽히며 나무상자 같은 형태를 피하는 모델을 요청했습니다. 확정 원화는 저장소 루트 `art-studies/arcana-hero/white-bob-heroine/white-bob-candidates-v1.png`입니다.

- `scripts/blender/build_heroine.py`로 별도의 여성 원본을 제작했습니다. 진주빛 백발 단발과 옆으로 흐르는 앞머리, 보랏빛 눈, 하늘색 숄, 상아색 드레스와 남색 리본, 짙은 스타킹과 회갈색 부츠를 구성했습니다. 이전 남성 원본을 덮어쓰지 않았습니다.
- 모델은 연속된 소매·스타킹, 부드러운 얼굴과 둥근 머리, 퍼지는 주름 치마와 곡면 부츠를 사용합니다. 확대 검수에서 발견한 어깨의 돌출, 끊겨 보이는 무릎, 각진 앞코를 수정했습니다. 보존된 원본은 70,408정점 / 139,624삼각형이고 게임용 복사본은 28,000삼각형으로 줄였습니다.
- 23개 뼈대에 대기/걷기 애니메이션을 포함하며, 네 개의 치마 제어와 좌/우 머리카락 및 리본이 움직입니다. 실제 이동 거리로 기존 보행 진행을 계산하고, 고개를 약간 들어 위쪽 게임 카메라에서 얼굴이 덜 가리게 했습니다.
- 원본: `art-studies/arcana-hero/white-bob-heroine/blender/heroine.blend`. 모델: `art/models/heroine/heroine.glb`. 연결: `scripts/blender_hero.gd`, 확인용 장면 `scenes/characters/heroine.tscn`. 사용자 `scenes/plaza.tscn`의 배치와 서버 진행/저장/충돌은 수정하지 않았습니다.
- 실제 게임 크기 검수에서 백발과 피부가 그늘에서 짙게 뭉치는 것을 확인했습니다. 주인공의 페인트 재질에만 머리·피부·드레스/눈 하이라이트별 보정광을 설정했습니다. 세계 조명, 고정 팔레트, 도트 확대 단위와 카메라 줌은 유지했습니다.
- Blender 확대 렌더는 원본 옆 `heroine-beauty.png`입니다. 실제 Godot GPU의 [게임 해상도 확대](reference/pixel3d-character-detail.png)와 [네 방향 걷기](reference/hero-3d-rendered-poses.png), Godot import / Web export를 확인했습니다. 브라우저 플레이·모바일 성능·모든 가림과 시설 출입 검수는 실행하지 않았습니다.

원화의 세밀한 표정과 자수가 도트 화면에서 그대로 남는다고 간주하지 않습니다. 최종 미술 승인은 사용자의 게임 화면 확인으로 남깁니다.
