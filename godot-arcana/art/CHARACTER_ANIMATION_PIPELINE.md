# 도트 캐릭터 일관성과 8방향 애니메이션 파이프라인

승인된 캐릭터의 외형을 유지하면서 자세와 동작을 확장합니다. **원본 편집 → 핵심 자세 → 중간 자세 → PixelPen 보정 → 비교 검수 → 내보내기**를 기본 경로로 사용합니다. 이 문서는 모든 도트 캐릭터의 공통 절차이며, 아래 명세는 현재 아르카나 주인공의 적용 사례입니다.

## 현재 기준과 제작 경계

- 실제 연결은 scripts/pixel3d_world.gd → scripts/heroine_run.gd → art/export/heroine-run-reference-v15/의 기본 네 시트입니다. 다른 작업에서 추가한 대시 시트와 기본 의상 외의 Blender fallback은 이번 명세 밖의 경로입니다.
- 출력 규격·활성 시트·주소·전환 경계는 [animation-pipeline.json](source/heroine/animation-pipeline.json) 버전 2가 관리합니다. 규격 숫자나 색을 다른 문서에서 별도로 갱신하지 않습니다.
- 디자인 기준은 사용자가 다시 선택한 전신 달리기 원화와 이후 명시적 수정 사항입니다. [기준 묶음](source/heroine/identity-v1/identity.json)은 승인 근거, 고정 특징, 방향별 비교 사본, 팔레트와 해시를 연결합니다.
- 실제 편집은 [run-reference-v15](source/heroine/run-reference-v15/README.md)의 pixelpen/에서 합니다. 잠긴 비교 사본과 편집 중인 원본을 구별합니다. 활성 연결·구조 검사 통과·최종 사용자 미술 승인은 서로 다른 상태입니다.
- 이번 명세의 관리 대상은 방향별 대기 4·달리기 8·시전 6프레임과 정면 벤치 8프레임, 총 **152개 동작 프레임**입니다. 달리기 시트 마지막 행의 대기 보조 셀 8개는 별도입니다.
- 이번 정비는 문서·명세·도구 범위입니다. 새 미술, 현재 시트 교체, 런타임 수정과 웹 배포를 포함하지 않습니다.

보존된 Skeleton2D, Blender, run-v1, motion-v2와 fullbody 버전은 과거 제작·비교 자료입니다. 파일이 존재하거나 과거 문서에 “최신”이라고 적혔다는 이유로 현재 원본을 대체하지 않습니다. 다른 캐릭터는 해당 캐릭터의 승인 기준과 명세를 등록하며 주인공의 외형·팔레트를 복사하지 않습니다.

## 1. 기준 묶음 등록과 변경

기준 묶음에는 디자인 승인 이미지와 후속 수정, 편집 원본, 방향별 전신/보이는 얼굴 비교 프레임, 외형 특징, 출력 규격 및 원본→시트→표시기 연결을 기록합니다.

주인공은 백발 단발·보랏빛 눈·하늘색 숄·밝은 드레스·작은 손·가는 손목을 보존합니다. 피부는 잠긴 공통 팔레트의 지정 재질색을 사용하고, 거절된 코 주변 금색 반점·얼굴 전체 단색화·범용 눈 복제를 되돌리지 않습니다. 색의 정확한 값은 기준 묶음의 팔레트를 따릅니다.

- identity-v1/references/는 현재 출력의 방향별 전신 프레임을 바이트 그대로 복사한 비교 사본입니다. 이 사본 등록은 새로운 미술 승인이 아닙니다. 정면 얼굴을 뒷방향에 억지로 붙이지 않습니다.
- lockedFiles는 승인 이미지, 비교 사본, 팔레트의 SHA-256을 보관합니다. 편집 대상 PixelPen 파일을 잠긴 해시 목록에 넣지 않습니다.
- 기준 변경은 사용자의 명시적 디자인 변경 지시에 따라 새 identity 버전과 변경 이유·승인 근거를 기록한 후 명세의 참조를 바꿉니다. 검사 실패를 없애기 위한 자동 해시 갱신은 하지 않습니다.
- 기존 registration.json의 팔레트는 편집 원본의 색 인덱스 해석에 사용합니다. 잠긴 기준 팔레트와 정확히 일치해야 하며, 별도의 색 재추출이나 근사 매핑을 하지 않습니다.
- 새 동작은 기존 PixelPen을 별도 후보 폴더로 복사하여 편집합니다. 같은 외형·규격의 후보는 명시적 원본/출력 인자를 사용하고, 프레임 수·방향·팔레트가 달라지면 후보 명세도 별도로 등록합니다.

## 2. 원본 편집 중심의 제작 순서

1. **동작을 정의합니다.** 방향, 지지 발, 손의 접촉 대상, 준비·주동작·회복 자세와 상태 진입/복귀를 정합니다. 장수보다 자세의 타당성을 먼저 확보합니다.
2. **같은 방향의 기준에서 핵심 자세를 편집합니다.** 머리·목·어깨·몸통의 연결과 전신 비례를 함께 맞춥니다. 머리만 교체하거나 다른 방향의 신체를 가로로 잘라 합치지 않습니다.
3. **필요한 중간 자세만 보탭니다.** 접지·회수·체중 이동·반대팔의 연결을 유지합니다. 발 미끄러짐을 숨기려고 실제 이동 속도를 바꾸지 않습니다.
4. **PixelPen에서 프레임을 보정합니다.** 공통 팔레트, 원본 픽셀 밀도와 외곽선, 여분 손발, 관절 틈, 옷의 가림을 수정합니다. 원본과 수동 편집을 보존합니다.
5. **기준/후보와 전후 프레임을 비교합니다.** 같은 방향·배율에서 원본 크기와 최근접 확대를 함께 보며 대기→동작→대기까지 확인합니다.
6. **확인한 저장본만 내보냅니다.** 프레임별 수정 내용과 실제 보정 범위, 남은 차이를 남깁니다. 단순 파일 변환이나 PixelPen 파일 생성만으로 보정 완료라고 보고하지 않습니다. PixelPen 편집이 불가능하면 미완료로 명시합니다.

### 공격 동작과 스킬 이펙트 설계

프레임 수보다 준비→공격→회복의 핵심 자세·실루엣과 타이밍을 먼저 완성합니다. 준비 자세는 힘과 방향을 읽을 수 있게 유지하고, 공격 순간은 빠르게 전환하며, 마무리 자세와 잔광으로 동작을 정리합니다. 모든 프레임을 같은 시간 표시하는 것을 목표로 삼지 않습니다. PixelPen의 고정 셀 시간에서는 필요한 자세의 셀 반복으로 체류 시간을 표현하고, 편집 타이밍과 실제 게임의 발사·타격 시점을 구별합니다.

- 지지 발의 접지와 등록 기준, 몸의 부피, 무기 길이를 유지합니다. 의도한 원근 단축·공중 이동·공격 궤적과 우발적인 크기 흔들림을 구별합니다.
- 빠른 동작에는 필요한 검기·잔상·늘어난 궤적을 별도 효과로 설계합니다. 이를 위해 캐릭터의 확정 외형이나 비례를 임의로 바꾸지 않습니다.
- 캐릭터 동작, 발사/검기, 적의 피격 섬광, 흩어지는 조각과 잔광의 시작·최대 강도·소멸 시점을 함께 정합니다. 효과가 손·무기·공격 방향과 맞고 타격 순간이 읽혀야 합니다.
- 대표 공격 하나를 캐릭터 동작부터 피격·잔광까지 완성하여 후속 스킬의 품질 기준으로 삼습니다. 장수만 늘리거나 효과를 더 겹치는 것으로 완성도를 판단하지 않습니다.

참고 자료는 메이플스토리 월드의 공식 [애니메이션 제작](https://maplestoryworlds-creators.nexon.com/en/docs?postId=595)과 [스킬 이펙트](https://maplestoryworlds-creators.nexon.com/en/docs?postId=70) 문서입니다. 위 기준은 아르카나에 적용할 일반 제작 원칙이며 메이플스토리 본편 개발팀의 내부 제작 공정이 공개·확인된 것으로 해석하지 않습니다.
### 고정 특징과 허용 움직임

| 유지할 것 | 자세에 따라 달라질 수 있는 것 |
| --- | --- |
| 얼굴 인상·눈매·머리 형태와 부피 | 머리 위치, 원근 단축, 목·어깨와 함께 움직이는 자세 |
| 체형·손과 신발 크기·관절 연결 | 관절 각도, 지지·공중·앉기 자세, 부분 가림 |
| 의상 구조·장식의 소유 방향·재질색 | 주름·치맛단·머리카락의 후행 움직임 |
| 픽셀 밀도·카메라·등록 축척 | 동작에 따른 외접 크기와 접촉 위치 |

머리 좌표나 외접 크기를 모든 프레임에서 같게 만들지 않습니다. 비대칭 장비·의상이 있으면 무조건 좌우 반전하지 않습니다. 앉기는 좌석 접촉점, 공중 자세는 동작별 기준점을 따로 기록하며 모든 발을 동일 좌표에 강제로 붙이지 않습니다. 관절을 가리려고 팔 전체를 굵게 만들거나 Y좌표 범위로 몸을 잘라내지 않습니다.

### AI 초안 사용 규칙

AI가 필요하면 승인 전신·같은 방향의 기준·동작 설명·변경 금지 특징을 함께 제공합니다. 매 프레임 독립 생성이나 직전 생성 결과만을 참조한 연쇄 생성을 기본 제작 경로로 사용하지 않습니다. 생성 시트는 재료이며 승인 외형에 맞춘 PixelPen 보정과 검수가 끝난 뒤 내보냅니다.

작업 지시에는 아래를 채웁니다.

~~~text
캐릭터 / 기준 identity / 승인 이미지:
작업할 방향 / 동작 / 핵심 자세:
지지 발 / 손·무기·가구 접촉 / 진입·복귀:
유지할 얼굴·전신·의상 특징:
허용하는 자세·가림·주름 변화:
편집 원본 / 후보 출력 / 실제 수정 프레임:
기준 비교 결과 / 미완료 항목 / 사용자 승인 여부:
~~~

문제가 있으면 해당 재질·자세·방향으로 돌아갑니다. 새 동작에 맞추려고 기준을 바꾸거나 전체 프레임을 재생성하지 않습니다.

## 3. 명세와 도구 계약

animation-pipeline.json의 경로는 저장소 루트 기준입니다.

| 필드 | 책임 |
| --- | --- |
| identity | 디자인 기준, 잠긴 파일 해시, 방향별 비교 사본과 팔레트 참조 |
| source / exportDirectory | 현재 편집 폴더, 등록 정보, PixelPen 폴더와 산출물 위치 |
| atlases | 방향, 프레임 수, 원본 이름, 격자/명시적 셀 주소, 표시기 상수 |
| authoringTiming / runtime | 저장된 편집 타이밍과 실제 게임의 거리·시간·상태 타이밍 구분 |
| auxiliary | 동작 수에서 제외하는 호환용 셀의 출처 |
| boundaries | 정확히 일치해야 하는 중립 진입·복귀 프레임만 지정 |

현재 필수 경계는 모든 방향의 대기→시전 시작, 시전 마지막→대기와 정면 벤치 서기→대기입니다. 모든 이웃 프레임이나 전체 실루엣에 픽셀 동일성을 요구하지 않습니다. 새 동작의 경계가 의도적으로 다르면 연결 포즈를 설계한 뒤 명세를 갱신합니다.

PixelPen 1.1.4는 타임라인 셀마다 1 / animation_fps를 사용하며 같은 프레임을 반복한 셀도 유지합니다. 내보낸 SpriteFrames는 이 순서·fps·loop를 사용합니다. 게임의 달리기 거리 위상, 대기 호흡 간격, 시전 발사 시점과 벤치 상태 시간은 표시기에 남아 있습니다. runtime.evidence는 해당 코드가 바뀌었을 때 검토를 요구하는 정적 근거이며 게임 실행 검증을 대신하지 않습니다.

## 4. 편집 반영과 확인

저장소 루트에서 실행합니다. 기존 동기화와 같은 Python/Pillow 환경을 사용하며 도구를 자동 설치하지 않습니다.

~~~powershell
# PixelPen 저장본을 명세의 현재 원본에서 내보냅니다. 게임 자산 출력이 필요할 때만 실행합니다.
python scripts/sync-heroine-fullbody.py

# 같은 기준을 쓰는 원본/출력 지정: 두 인자를 반드시 함께 지정합니다.
python scripts/sync-heroine-fullbody.py --source run-reference-v15 --export heroine-run-reference-v15

# 다른 프레임 구성·기준을 쓰면 별도 명세를 지정합니다.
python scripts/sync-heroine-fullbody.py --contract <저장소-내-후보-명세.json>

# 읽기 전용 검사. 사용자에게 실행 검증을 요청받았을 때 실행합니다.
npm.cmd run art:animation:validate
~~~

검사 명령도 -- --contract 옵션을 지원합니다. Node 진입점은 공통 Python 검사기를 실행하며 PYTHON 환경 변수로 실행 파일 경로를 지정할 수 있습니다.

동기화는 기준·모든 PixelPen 파일·팔레트·프레임 수·레이어·필수 경계를 확인한 후 산출물을 메모리에서 준비합니다. 입력 오류가 있으면 출력 쓰기를 시작하지 않습니다. 쓰기 중 파일 시스템 오류는 이미 교체한 산출물까지 되돌리는 트랜잭션이 아니므로, 원인을 해결한 뒤 다시 동기화합니다. 편집 원본과 잠긴 기준은 쓰지 않으며 최초 제작 스크립트도 실행하지 않습니다.

시트와 SpriteFrames, 프레임 비교판, 방향별 네이티브 타이밍 GIF, 원본 해시가 있는 native-package-audit.json을 출력합니다. GIF는 10ms 단위의 편집용 미리보기이며 실제 게임의 타이밍 증거가 아닙니다. SpriteFrames는 과거 파일을 복사하지 않습니다. 현재 게임은 달리기 SpriteFrames만 읽으며 나머지 세 리소스는 편집용 출력입니다. 명령은 런타임 연결·웹 빌드·배포를 수행하지 않습니다.

현재 보존된 heroine-run.tres에는 과거 14fps가 있고 저장된 달리기 PixelPen은 12fps입니다. 파이프라인 정비 시 기존 산출물을 교체하지 않았으므로 검사는 이 불일치를 보고할 수 있습니다. 자산 반영을 요청받아 명시적으로 동기화하면 편집 원본의 타이밍으로 갱신됩니다. 거리 기반 게임 속도를 바꾸는 조치는 아닙니다.

### 구조 검사와 시각 검수

검사기는 잠긴 기준의 해시, 원본 팔레트/레이어/크기/타이밍, 동작 수, 시트 색/알파/셀/원본 일치, 필수 전환 경계, SpriteFrames 주소·타이밍, 런타임 참조를 확인합니다. 오류에는 대상 파일·클립·프레임 또는 픽셀 위치를 표시합니다. 정상적인 머리 이동·가림·앉기 자세는 자체 오류로 판정하지 않습니다.

표시기에 추가된 미등록 시트는 미검사 경고로 출력하며 이번 명세의 통과 범위에 포함하지 않습니다.

결과는 **구조 통과/실패**, **시각 검토 필요**, **최종 미술 승인 기록**으로 분리합니다. 팔레트 일치나 실루엣 해시만으로 캐릭터 인상·자연스러운 움직임을 승인하지 않습니다.

직접 시각 검수할 항목:

- 같은 방향의 기준과 비교했을 때 얼굴 인상·머리 부피·전신 크기·의상 구조가 유지되는지
- 머리·목·어깨가 연결되고 손발이 중복되지 않는지
- 접지·손/무기/좌석 접촉과 가림이 동작에 맞는지
- 대기→달리기→시전→대기, 앉기→일어나기에서 크기·색·형태가 갑자기 바뀌지 않는지

테스트·게임·브라우저 검증은 [작업 원칙](../../AGENTS.md)의 사용자 선호를 따릅니다. 문서·참조·필요한 구문 검사만 기본 수행하며 사용자 요청 없이 열린 게임을 조작하지 않습니다.

## 5. 후속 제작과 보존 경로

독립 걷기, 출발·정지·회전, 교체 장비 레이어, 머리·망토 관성은 명세의 stages로 관리합니다. 문서화하거나 보존 자산이 있다는 이유로 활성 구현 완료로 표시하지 않습니다.

후속 상태는 idle → start → walk/run → stop → idle과 turn, cast/attack 후 복귀를 목표로 합니다. 입력·이동을 시각 전환 때문에 늦추지 않습니다. 방향 변경은 보행 위상을 유지하고, 다른 클립으로 전환할 때 좌우 접지·passing 위상과 가변 지속 시간을 함께 고려합니다. 없는 클립은 기존 동작을 사용하고 미완료 상태를 남깁니다.

장비 레이어는 같은 방향·클립·위상·접촉 기준을 사용합니다. 의상의 실제 불투명 영역으로 몸을 가리고, 손·무기 접촉과 앞뒤 전환을 등록합니다. 보조 관성은 승인된 소수의 도트 형태 선택으로 표현하며 자유 회전·비균등 확대를 기본으로 사용하지 않습니다.

Skeleton2D 재출력과 Blender 오프라인 출력은 해당 원본을 대상으로 별도 요청받았을 때만 사용하는 보존 경로입니다. [기존 원본 안내](source/heroine/README.md)의 수동 장면·PNG·workshop·SpriteFrames 보존 규칙은 계속 적용합니다. 현재 PixelPen 원본을 그 결과로 자동 대체하지 않습니다.

벤치 런타임의 world.gd 상태 처리와 pixel3d_world.gd의 일반 pose 전 set_bench_pose(), pose 후 apply_bench_pose() 순서는 유지합니다. 이는 이동·시전·대기 시트의 상태를 보존하기 위한 기존 계약입니다.
