# Godot 8방향 캐릭터 애니메이션 파이프라인

첨부 설계의 8방향·상태 머신·보행 위상·전환 포즈·장비 레이어·보조 관성을 아르카나 제작 순서로 적용합니다. 이후 캐릭터 동작 작업은 이 문서를 따릅니다. 기존 승인 디자인과 이동·충돌·저장 계약은 유지합니다.

## 현재 연결과 구현 상태

실제 게임 진입점은 `scripts/pixel3d_world.gd` → `scripts/heroine_run.gd`입니다. `scenes/characters/heroine.tscn`의 보존된 `heroine_sprite.gd`와 구별합니다. 3D 월드의 빌보드에 2D 시트를 표시하므로 첨부의 CharacterBody2D 예제를 그대로 삽입하지 않습니다. 기존 월드가 이동을 처리하고 표시기는 자세를 선택합니다. Phaser로 이전하지 않습니다.

기계 판독 계약은 `source/heroine/animation-pipeline.json`입니다.

| 항목 | 현재 상태 | 후속 제작 조건 |
| --- | --- | --- |
| 8방향 | 방향당 이동 8장·대기 4장(호흡·깜빡임) | S, SE, E, NE, N, NW, W, SW 순서 유지 |
| 보행 위상 | 실제 이동 20좌표마다 한 주기, 방향 변경에도 유지 | 걷기·달리기 분리 시 공통 접지 위상 지정 |
| 걷기/달리기 분리 | 같은 이동 시트를 사용 | 독립 클립과 대응 접지 자세 필요 |
| 시전 | 방향당 4장, 이동 위에 우선 표시 | 공격별 클립은 별도 등록 |
| 출발·정지·회전 | 활성 시트에는 없음 | 전환 포즈 제작 후 연결 |
| 장비 레이어 | 기본 의상은 통합 시트, 다른 의상은 기존 fallback | 활성 시트와 공통 포즈의 레이어 연결 필요 |
| 망토·머리 관성 | 별도 형태 선택 미연결 | 방향별 3~5개 후행 포즈 제작 필요 |

보존된 Skeleton2D 원본과 SpriteFrames에는 대기 4·걷기 24·정지·회전 프레임이 있지만 활성 8프레임 시트와 외형·주소·주기가 다릅니다. 자산의 존재만으로 활성 런타임 연결 완료라고 판단하지 않습니다. 기본 의상과 다른 의상의 표시 품질 차이도 검수합니다.

## 제작 순서

### 1. 공통 규격 등록

승인 원화, 방향 순서, 96×136 캔버스, 발 (48,116), 64픽셀/월드 단위, 팔레트와 레이어 소유를 기록합니다. 기본 카메라는 정면형 3/4입니다. 첨부의 대기 4·걷기 6·달리기 8·공격 6프레임은 신규 제작 예산 예시이며 기존 프레임 수를 강제로 바꾸는 규칙이 아닙니다. 새 디자인은 기존 컨셉 승인 절차를 따르고 단순 오류 수정에는 승인을 다시 요구하지 않습니다.

### 2. 공통 포즈 → 도트 출력 → 수동 보정

현재 Skeleton2D·Bone2D·Polygon2D·AnimationPlayer 원본을 우선 재사용합니다. Blender는 필요할 때 공통 리깅에서 같은 8방향으로 오프라인 출력하는 선택지입니다. 런타임 3D 캐릭터 전환과 구별합니다. 프레임마다 독립적인 생성 이미지를 제작하지 않습니다.

`source/heroine/README.md`의 재출력 절차를 따릅니다. 수동 native 장면·PNG·workshop.json·SpriteFrames 타이밍을 보존하고 프레임별 도트 보정을 다시 적용합니다. 신체를 가로선으로 잘라 다른 방향과 합치지 않습니다. 고정 길이 관절·작은 손·가는 손목·신발별 발목 소유를 유지합니다.

### 3. 상태 전환과 보행 주기

목표 상태는 idle → start → walk/run → stop → idle, 이동 중 turn, attack/cast와 복귀입니다. 전환 조건·중단 조건·완료 후 복귀를 명시적인 상태로 관리합니다. 초기에는 GDScript 상태 머신과 프레임 표시기로 충분하며 필요할 때 AnimationPlayer/AnimationTree를 검토합니다.

입력과 실제 이동은 즉시 반응하고 시각 전환이 이동을 지연시키지 않게 합니다. 최대 이동 3칸/초와 작은 입력의 비례 속도를 보존합니다. 클립이 없으면 기존 idle/이동으로 대체하고 없는 전환을 구현 완료로 기록하지 않습니다.

이동 클립 전환과 방향 변경에서는 정규화 위상을 유지합니다. 좌/우 접지·passing 위상을 공통 명세로 둡니다. 가변 프레임 지속 시간은 누적 지속 시간으로 환산하며 단순 프레임 번호를 복사하지 않습니다. AnimatedSprite2D 경로에서는 `set_frame_and_progress()`를 사용하고 현재 atlas 표시기에서는 위상을 프레임 주소로 변환합니다.

출발·정지는 짧은 전용 포즈로 연결합니다. 회전은 45°·90°·180° 패턴을 필요한 방향에 재사용하되 비대칭 장비는 무조건 미러링하지 않습니다. 기존 8방향이나 이동 속도를 줄여 제작량을 맞추지 않습니다.

### 4. 교체 가능한 장비 레이어

개념 순서는 shadow → cape/weapon-back → body → clothes → hair/arms-front → weapon-front → effects입니다. 현재 팔·숄의 앞뒤 관계는 기존 계약을 따릅니다. 모든 파츠는 같은 방향·클립·위상·발 기준을 사용합니다.

손과 무기의 접촉점, 무기가 몸 앞뒤로 이동하는 프레임을 등록합니다. 옷의 실제 불투명 영역으로 가리고 Y좌표 범위로 몸을 잘라 가리지 않습니다. 기본 의상·비대칭 장비·대표 의상 조합에서 정렬과 가림을 확인합니다.

### 5. 보조 관성

회전·가속의 스프링/감쇠 결과를 승인된 3~5개 도트 형태 선택에 사용합니다. 몸체 보행 위상과 충돌은 변경하지 않습니다. 망토·머리 파츠의 자유 회전·비균등 확대를 피하고 연출 감소 설정에서는 중립 자세를 사용합니다.

## 실행 명령과 검증

저장소 루트에서 `npm.cmd run art:animation:validate`를 실행합니다. 현재 활성 두 시트의 크기·8방향 주소·비어 있지 않은 프레임·이진 알파와 런타임 등록을 읽기 전용으로 검사하고 미완료 단계도 출력합니다. 이 검사는 실루엣 연속성·손발 접촉·자연스러운 움직임을 증명하지 않습니다.

원본 수정 종류에 맞는 명령만 사용합니다.

- 보존된 공통 뼈대 변경: `pwsh -File scripts/rebuild-heroine-skeleton.ps1`
- 현재 run-v1 PixelPen 편집 반영: `python scripts/sync-heroine-run.py`
- 새 시트 최초 패키징: `scripts/package-heroine-run.py`, `scripts/package-heroine-cast.py`. 기존 편집본 덮어쓰기 여부를 확인하고 필요한 대상만 실행합니다.
- 웹 적용: 자산 검사 후 `pwsh -File scripts/build-godot-arcana.ps1`

완료 증거는 기본 카메라에서 방향 변경, 좌/우 접지, 출발·정지, 이동 중 시전과 복귀, 대표 의상 조합의 실제 출력입니다. 발 미끄러짐·손 접촉·실루엣 연속성을 확인합니다. 정지 렌더와 프레임 검사는 브라우저 플레이와 구별합니다. 별도 요청 없이 사용자의 열린 게임을 조작하지 않습니다.

## 이번 도입 범위

제작 규칙·활성 자산 계약·읽기 전용 검사 명령을 추가했습니다. 현재 두 시트의 총 104프레임이 등록 검사를 통과했습니다. 새 전환 그림, 독립 걷기 클립, 장비 레이어의 활성 시트 통합, 관성 포즈는 후속 제작 항목입니다. 이번 문서화로 게임 런타임이나 웹 배포를 교체하지 않았습니다.

## 2026-10-28 · 공원 벤치와 여관 소파

승인된 `source/heroine/bench-v1/approved-concept.png`를 기준으로 앉기·휴식·일어나기 8포즈를 `export/heroine-bench-v1/heroine-bench.png`에 등록했습니다. 방향은 기존 정면 빌보드 가구에 맞춘 S 한 방향입니다. `world.gd`가 접근·앉기·휴식·일어나기 상태를 관리하고, `pixel3d_world.gd`는 일반 pose 전 `set_bench_pose()`, pose 후 `apply_bench_pose()`를 호출합니다. 이 순서는 별도 갱신되는 이동/시전/대기 시트의 텍스처·격자·위상을 보존하기 위한 계약입니다. 자세별 축척·발 기준·재제작은 `source/heroine/bench-v1/README.md`를 따릅니다. 기본 의상에 적용하며 기존 Blender fallback의 의상별 앉기는 제작되지 않았습니다.
