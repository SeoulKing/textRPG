## 현재 팔 구조와 표시 순서

공통 제작 순서와 활성 시트의 구현 범위는 [캐릭터 애니메이션 파이프라인](../../CHARACTER_ANIMATION_PIPELINE.md)을 따릅니다. 등록 계약은 이 폴더의 `animation-pipeline.json`, 검사 명령은 저장소 루트의 `npm.cmd run art:animation:validate`입니다.

팔이 치마 뒤로 사라지는 오류를 수정했습니다. arm-방향-left/right.png는 어깨부터 손까지 이어지는 상완·긴 소매·전완·커프·손 원본입니다. bare-arm PNG는 상의가 없는 조합의 피부 원본입니다. arm-joints.json은 방향별 어깨/팔꿈치/손목 기준점입니다. 원래 몸체와 옷에 붙어 있던 짧은 팔·손 조각은 출력에서 제거하고 새 팔 두 개만 사용합니다.

arms-back은 몸통/치마 뒤, arms-front는 옷 앞·숄 아래입니다. 정면/뒷면에서는 두 전완이 읽히게 하고 측면/대각선은 가까운 팔과 먼 팔을 나눕니다. 상완·전완은 로컬 위치와 scale을 고정하고 회전 키로 보행 반대 움직임을 만듭니다. 기존 다리 길이/신발 연결은 유지합니다. 새 팔 레이어를 프레임 도트 패널에서 고치거나 왼쪽/오른쪽 부품 버튼으로 원본을 열 수 있습니다. 일반 출력은 rebuild-heroine-skeleton.ps1입니다.

## 현재 다리 규칙 · 고정 길이 회전 관절

허벅지15·정강이12픽셀을 고정하고 Thigh/Knee/Ankle의 위치 트랙은 고정 오프셋, scale은(1,1)입니다. 두 마디 IK로 도달 가능한 발 위치를 구한 뒤 뼈 회전만 출력합니다. 발 목표가 멀면 다리를 늘리지 않고 관절의 도달 범위로 제한합니다. 신발은 발목 회전의 반대를 적용해 지지 중 바닥 방향을 유지합니다. 다리 메시도 전체를 늘이는 웨이트 대신 허벅지/정강이를 각각 강하게 고정하고 관절 주변만 좁게 연결합니다.

옆모습 신발은 기존 겹친 원본에서 뒤쪽 신발 조각을 제거하고 한 발목·한 밑창으로 다시 정리했습니다. 좌우 원본의 발목 위치를 실제 뼈에 맞추고 각 변형의 신발 메시 수는2개, 각 메시의 유일한 소유 뼈는 서로 다른 AnkleL/AnkleR입니다. 이전 원본은 art-studies/arcana-reference-v1/before-fixed-legs/에 보존합니다. fixed-leg-contract.json과 native-rig-audit.json이 길이/연결 계약과 실제 검사를 기록합니다. scripts/fix-heroine-leg-rig.py는 이번 일회성 이행 기록이며 일반 재출력은 아래 rebuild 명령을 사용합니다.

# 주인공 공통 2D 스켈레톤과 도트 원본

현재 제작 원본은 **skeletal/**이며, Godot Skeleton2D·Bone2D·Polygon2D·AnimationPlayer로 동작을 제작합니다. 아래 이전 제작 기록보다 이 절차를 우선합니다. 출력은96×136·발(48,116)·공통64픽셀/단위·8방향입니다. 기본 방향별36장(대기4·걷기24·정지각4)의 주소는 보존하고, 정지 회전64장을 마지막에 추가해 총352장·16×22아틀라스를 사용합니다.

## 편집과 재출력

1. 하단 **주인공 도트 → 공통 뼈대**로 선택한 방향의 scenes/rig-방향.tscn을 엽니다. 실제17개 Bone2D와 가중치가 지정된 Polygon2D입니다. AnimationPlayer에서 idle·walk·stop_left/right·turn_left/right를 선택해 자세와 타이밍을 편집하고 장면을 저장합니다. 골반에서 척추·목·머리와 좌우 팔다리가 연결됩니다. 얼굴/머리는 강하게 고정하고 신발은 각 발목 뼈에 연결합니다.
2. **PixelPen 원본**으로 skeletal/의 공통 그림을 엽니다. 목·어깨·허리·골반의 숨겨진 안쪽도 그려 겹침을 유지합니다. body-upper는 출력 보조이며 몸체 수정은 body PNG에서 합니다. 좌우 다리는 skeletal/leg-방향-left/right.png, 신발은 parts/의 독립 원본입니다. 파일 패널에서 해당 PNG를 PixelPen으로 Import하고 같은 위치로 Export합니다.
3. 원본이나 뼈대를 수정한 뒤 **뼈대 재출력**을 누릅니다. 숨김 프로세스에서 실제 Godot GPU로 모든 의상 레이어를 같은 포즈에서 출력한 후 도트 시트를 갱신합니다. 하단에 완료/실패를 표시합니다. native 장면의 수동 수정은 보존하고 generated.tscn은 비교 원본으로 갱신합니다.
4. 특정 프레임의 도트는 작업실에서 직접 칠하고 지웁니다. **저장 + 시트 반영**은 workshop.json의 좌표 수정을 이미 출력된 뼈대 프레임 위에 적용합니다. 원본/뼈대 수정 후에는3번이 먼저 필요합니다. 이전 프레임 겹쳐보기·되돌리기와 전체 조립 미리보기를 지원합니다.
5. 로컬 게임은 재실행, 웹은 Web export 후 반영됩니다.

명령줄: `pwsh -File scripts/rebuild-heroine-skeleton.ps1`
웹: `pwsh -File scripts/build-godot-arcana.ps1`
오프라인 실제 게임 렌더: `pwsh -File scripts/render-arcana-reference.ps1 -NaturalWalk`
검사: `python scripts/validate-character-quality.py`, native rig inspector, `node scripts/check-heroine-rig.cjs`

## 연결부와 보존 기준

모든 레이어는 같은 방향·같은 프레임을 사용합니다. 머리/몸통/다리를 화면 가로선으로 잘라 다른 방향의 그림으로 합치지 않습니다. 목과 골반은 실제 도트를 보강했고, 다리와 몸통은 겹침 여유를 둔 가중 메시로 연결합니다. 발목 끝의 웨이트를 신발과 일치시켜 종아리 사이 틈을 막습니다. source joint-patches.json은 원본309픽셀 보강, frame-corrections.json과 workshop.json은 출력 후 목둘레/허리의 작은 구멍 보정을 기록합니다. 팔과 몸 사이, 두 다리 사이의 의도한 공간은 메우지 않습니다.

일반 보행 위상은 실제 이동20좌표마다 순환합니다. 최대 이동3칸/초를 유지하고 방향 전환으로 보행을 초기화하지 않습니다. 정지 회전은별도 전신 프레임입니다. 미세한 머리 기울기와 발목 회전도 native AnimationPlayer의 트랙입니다. 런타임은 뼈대를 실시간 렌더하지 않고 보정된 도트 프레임을 표시합니다.

skeletal/scenes/의 수동 장면과 workshop.json을 보존합니다. generated.tscn/.tres는 자동 비교 원본입니다. 기존 SpriteFrames의 수동 타이밍은 유지하고 새 회전 클립만 추가합니다. 이전 JS 변형기와 기존 masters/·parts/ 자료는 보존 기록이며 현재 뼈대 출력으로 대체됩니다. 최초 준비 스크립트는 기존 skeletal PNG를 덮어쓰지 않습니다.

외형/가림9시트의 압축 전 크기는157.8MiB입니다. 원본/편집 장면은 웹에서 제외합니다. 실제 모바일 성능과 브라우저 플레이는 사용자 확인 항목입니다.

## 공통 그림: PixelPen

Godot 4.5.1에 맞춰 공식 PixelPen v1.1.4(MIT)를 설치했습니다. 최신 버전을 임의로 덮어쓰지 않습니다. 네이티브 확장이므로 첫 설치 후 에디터 재시작이 필요할 수 있습니다.

1. 하단 **주인공 도트**에서 방향·레이어를 선택하고 **PixelPen 원본**을 누릅니다. 원본 PNG의 전체 경로가 클립보드에 복사됩니다.
2. PixelPen의 Import에서 해당 PNG를 엽니다. 펜·지우개·선택 도구로 수정하고 투명 배경과 캔버스 크기를 유지합니다.
3. 같은 `masters/레이어-방향.png`로 PNG Export합니다. PixelPen 편집 프로젝트도 이 폴더 아래 별도로 저장할 수 있습니다.
4. **저장 + 시트 반영**을 누릅니다. 기존 Node/Sharp가 필요하며 오류는 하단 상태에 표시됩니다.

masters/의 64개 PNG가 공통 원본입니다. 초기 원화를 매번 새로 생성하지 않습니다. 내보내기 시 공통 팔레트에 맞춰 정리하므로 팔레트 밖 색은 가까운 색으로 바뀝니다.

## 특정 자세: 주인공 도트 패널

방향·동작·레이어·프레임을 고른 뒤 왼쪽 클릭으로 칠하고 오른쪽 클릭으로 지웁니다. **이전 프레임**은 앞 자세를 흐리게 겹쳐 보여 줍니다. 오른쪽은 기본 의상의 조립 결과입니다. 되돌리기/다시 하기와 재생을 지원합니다. 프레임 번호는 0부터 시작합니다.

수정 좌표는 workshop.json의 `레이어/방향/동작/프레임` 키 아래 보존됩니다. `x,y: #rrggbb`는 색, `.`은 지우기입니다. 마스크도 같은 방식으로 편집합니다. 다른 프로그램에서 원본 JSON이 바뀌면 덮어쓰기 대신 다시 읽도록 안내합니다. 원본 다시 읽기는 미저장 수정을 버립니다.

**저장 + 시트 반영**은 마스터와 프레임 좌표를 함께 읽어 아틀라스를 갱신합니다. 게임 로컬 실행은 재실행, 웹은 Web export 후 반영됩니다. 출력된 hero-*.png를 직접 고치면 재출력 때 사라지므로 원본이나 패널을 수정합니다.

## Godot 기본 동작·바닥 관리

- **SpriteFrames** 버튼은 art/resources/heroine_frames.tres를 엽니다. 프레임 순서·상대 지속시간은 실제 게임에도 사용합니다. 실제 게임의 걷기 전체 속도는 이동 거리 기준이며 preview FPS를 바꿔도 이동 속도는 바뀌지 않습니다.

## 보행 규칙과 의상 가림

motion.json은 지지 비율·보폭·발 높이·팔·옷 지연·정착 시간을 관리합니다. 기준 지지 비율은 0.6(양발 지지 총 20%), 앞뒤 발 이동 ±24원본 픽셀입니다. 한 주기 이동 거리는 20내부 좌표=1.25칸입니다. 최대 3칸/초에서 주기는 약 0.417초이며 실제 이동량에 연동됩니다. 제자리에서 발만 빠르게 돌리거나 애니메이션에 맞추어 이동 속도를 낮추지 않습니다.

치마 밑단은 다리 변형을 따라 늘어나지 않게 처리합니다. 신발 가림은 반대 다리의 정강이를 지우지 않도록 발을 제외한 몸체와 비교합니다. 드레스는 상/하의 슬롯을 함께 차지하고 숄·신발은 독립입니다. 수동 마스크 수정은 이 자동 결과 위에 적용됩니다.

재출력: `node scripts/build-arcana-reference-art.cjs --hero-only`
웹: `pwsh -File scripts/build-godot-arcana.ps1`
오프라인 렌더: `pwsh -File scripts/render-arcana-reference.ps1 -NaturalWalk`
자산 확인/GIF: `python scripts/validate-character-quality.py`

288프레임의 외형·가림 9개 시트는 압축 전 약 129.1MiB입니다. 모바일 실제 성능은 별도 확인 항목입니다. 에디터 플러그인과 이 원본 폴더는 웹 패키지에서 제외합니다.

## 전신 보행 수정 · 좌우 독립 부품

parts/의 body·boots-taupe·boots-navy는 8방향마다 left/right의 완전한 다리·신발 원본입니다. rig.json에 무릎·발목·밑창 연결점을 보관합니다. 한 장의 신발을 중앙에서 나누거나 옆모습 일부를 잘라 사용하는 처리는 제거했습니다. 몸체/신발 레이어를 고른 뒤 작업실의 왼쪽 다리/신발·오른쪽 다리/신발 버튼으로 PixelPen 경로를 복사할 수 있습니다. 수정한 PNG는 재출력 시 보존합니다.

무릎의 구간별 변형, 지지 다리 쪽 골반 이동, 어깨 반대 움직임과 머리 안정화를 적용합니다. 방향 전환은 상체/머리/하체가 각기 보행의 같은 위상에서 자세를 선택하도록 합성합니다. 기본 8방향 자세를 시간차로 연결하며, 별도 각도의 회전 원화를 추가한 것은 아닙니다. 인접 방향은0.12초, 큰 회전은0.24초, 머리는 상체보다 먼저 향합니다. 이미지 투명도 혼합은 사용하지 않습니다.

신발 한 짝씩의 768개 방향/프레임 조합은 node scripts/check-heroine-rig.cjs로 형태 면적 보존을 검사합니다. 전체 실루엣이 연결되었다는 검사만으로 신발의 잘림이 없다고 판단하지 않습니다. 원본과 각 신발이 단독으로 움직이는 결과를 함께 확인합니다.

현재 편집기가 PixelPen의 shadow DLL을 잡고 있어 원본 프로젝트의 별도 가져오기가 실패할 경우, scripts/export-fixed-legs.ps1은 addons/에디터 플러그인을 제외한 새 런타임 사본을 만들어 원본 설정을 보존한 채 Web export합니다. 사본 위치는 .runtime/godot/fixed-legs-stage-path.txt에 기록합니다. 렌더 도우미의 -ProjectPath로 이 사본을 검수할 수 있습니다. 일반 편집과 뼈대 원본은 계속 원본 프로젝트에서 관리합니다.

승인 원화의 작은 손과 단정한 팔 실루엣을 복원합니다. 공통 17개 Bone2D는 유지하고, 양팔을 위팔·아래팔·소맷단·손의 8개 Polygon2D로 나눴습니다. 팔을 한 장의 넓은 메시로 늘이지 않고 위팔은 Shoulder, 아래팔은 Elbow, 소맷단/손은 Wrist에 강하게 고정합니다. 두 연결부는 같은 원본 도트를 2픽셀 겹쳐 그리며 내부에 검은 절단선을 추가하지 않습니다. 정면 기준 어깨(35,54)/(61,54), 팔꿈치(33,65)/(63,65), 손목(34,76)/(62,76)입니다. 걷는 동안 골 길이와 부품 크기는 고정됩니다.

실제 편집 원본은 skeletal/arm-{upper,fore,cuff,hand}-{방향}-{left,right}.png, 맨팔은 bare-arm-으로 시작합니다. arm-joints.json과 arm-parts.json에 연결 정보를 기록합니다. 전체 arm-{방향}-{좌우}.png는 분할 전 채색 참고본입니다. prepare-heroine-arms.py는 초기 원본 제작용이며 일반 재출력에서는 실행하지 않습니다. 따라서 이후 각 조각의 수동 도트 수정은 보존됩니다.

주인공 도트 패널의 arms 레이어에서 위팔/아래팔/소맷단/손을 고르고 왼쪽·오른쪽 부품 버튼으로 PixelPen 경로를 복사합니다. 같은 PNG로 Export한 뒤 **뼈대 재출력**을 누릅니다. 공통 뼈대 버튼으로 방향별 네이티브 장면을 열어 관절과 AnimationPlayer를 편집할 수 있습니다. 새 원본이 발견되면 팔 생성 메시만 갱신하며 몸·다리 메시와 다른 수동 애니메이션 트랙은 유지합니다.
