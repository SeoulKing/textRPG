# 슬라임 도트 원본

`slime.pixel.json`이 편집 원본입니다. AI로 장면마다 새 이미지를 생성하지 않습니다. 도트 한 칸은 팔레트 문자 한 개이며, 같은 레이어를 모든 동작이 공유합니다. PNG와 SpriteFrames는 이 원본에서 출력한 게임용 파일입니다.

- 캔버스: 64×80, 발 기준 (32,74). 위쪽 투명 여백은 점프를 위한 공간입니다.
- 축척: 64도트 = 월드 1단위 = 논리 타일 16좌표. 한 칸의 지면 점유 크기는 1×1입니다. 캔버스 전체를 지면 타일 크기로 해석하지 않습니다.
- 팔레트: 기존 월드 팔레트의 7색(투명 포함 8개 기호), 1도트 외곽선, 이진 알파, 최근접 표시. 외부 미술 프로그램이나 유료 플러그인은 필요하지 않습니다.
- 디자인: 초록 젤리·작은 눈·둥근 꼭지·덩어리 광택. 사용자가 요청한 메이플 슬라임의 인상에서 출발한 첫 후보이며, 최종 외형 승인은 별도입니다.

## 고도에서 도트 수정

1. 프로젝트를 다시 열면 하단 **슬라임 도트** 패널을 사용할 수 있습니다. 보이지 않으면 프로젝트 설정 → 플러그인에서 **슬라임 도트 작업실**을 켭니다.
2. 동작과 프레임을 고르고 **재생**, **이전 프레임**으로 동작을 봅니다. 프레임 번호는 0부터입니다.
3. **공통: body/crest/shine/face_normal/face_blink/face_angry/face_hurt**를 선택하면 원본 레이어를 수정합니다. 같은 부위가 모든 동작에 반영됩니다. 오른쪽 미리보기는 선택한 동작의 합성 결과입니다.
4. **현재 프레임 수정**은 최종 프레임의 특정 (x,y)에만 보정을 기록합니다. 공통 레이어 위에 적용되므로 기존 보정은 공통 원본을 바꿔도 유지됩니다.
5. 팔레트를 고른 뒤 왼쪽 클릭/드래그로 칠하고 오른쪽으로 지웁니다. **되돌리기/다시 하기**는 획 단위로 작동합니다.
6. **저장 + 시트 반영**으로 JSON·PNG·SpriteFrames를 갱신합니다. **파일 다시 읽기**는 미저장 편집을 버리고 디스크 원본으로 돌아갑니다. 외부에서 원본이 바뀌면 덮어쓰지 않고 다시 읽기를 안내합니다.
7. 실행 중인 게임은 다시 실행해야 새 텍스처가 반영됩니다. 웹은 `scripts/build-godot-arcana.ps1`로 내보낸 뒤 새로고침합니다.

팔레트의 `.`은 투명입니다. `layers.body[y][x]`를 직접 수정하거나 `patches["hop/5"]["32,40"] = "h"`처럼 특정 프레임의 좌표만 바꿀 수도 있습니다. 프레임 보정을 원본 상태로 되돌리려면 해당 좌표의 patch 항목을 삭제합니다. `animations`에는 변형 키와 FPS를 보존합니다. 캔버스 크기·발·팔레트 기호를 바꾸려면 런타임 규격도 함께 수정해야 합니다.

## 동작

| 동작 | 프레임 | FPS | 용도 |
| --- | ---: | ---: | --- |
| idle | 24 | 16 | 호흡·눈깜빡임, 1.5초 루프 |
| hop | 28 | 24 | 준비 압축 → 이륙 → 정점 → 착지 → 복원 |
| prepare | 16 | 20 | 공격 3초 전부터 몸 낮추기 |
| attack | 24 | 24 | 공격 직전 도약과 착지·복원 |
| hit | 10 | 24 | 파이어볼 명중 시 짧은 반동 |
| death | 18 | 20 | 납작해짐 → 고정 패턴으로 도트 소멸 |

총 120프레임, 1024×640 아틀라스입니다. 보간은 포즈 수치에만 적용하며 도트는 정수 좌표와 최근접 표본으로 출력합니다. 최종 3D 스케일을 늘여서 도트를 흐리게 만들지 않습니다. 같은 게임 시계를 사용하고 전투 일시정지를 따르며, 효과 감소에서는 정지 프레임을 사용합니다. 파이어볼의 기존 0.3초 비행 지연과 전투 체력·공격 규칙은 유지합니다.

## 파일과 재출력

- 원본: `art/source/monsters/slime.pixel.json`
- 공통 컴파일러/편집 패널: `addons/pixel_workshop/`
- 게임용 시트/표준 Godot SpriteFrames: `art/export/monsters/slime.png`, `slime.tres`
- 월드용 2D 그림 표시: `scripts/slime_sprite.gd`, `art/resources/slime_sprite.gdshader`
- 재사용 장면: `scenes/monsters/slime.tscn`
- 서버 없이 F6으로 볼 비교 장면: `scenes/monsters/slime_preview.tscn` (1×1 타일, 기본 hop; Slime의 Preview Animation으로 동작 선택)
- 원본 기반 GIF/프레임판/실제 월드 비교: `art/reference/slime/`

고도 콘솔에서 `--headless --path godot-arcana --script res://tools/bake_slime.gd`로 다시 출력할 수 있습니다. PNG를 처음 출력한 뒤에는 Godot 가져오기를 완료해야 합니다. `python scripts/export-slime-preview.py`는 기존 시트를 GIF와 비교판으로 변환합니다. `tools/render_slime.gd`는 현재 월드·주인공과 함께 오프라인 GPU 이미지를 출력하며 게임 진행이나 저장을 변경하지 않습니다.

제작 시 프레임 비교판과 실제 월드의 한 칸/주인공 크기 비교를 확인했고 Godot 가져오기·Web 내보내기를 완료했습니다. 편집 패널의 실제 마우스 조작과 서버 전투 플레이는 사용자 확인으로 남깁니다.

## 명암 경계 보정 · 2026-10-28

- 몸통의 직선 분할·수평 그림자 띠를 곡면을 따르는 4단계 명암으로 보정했습니다. 기존 팔레트·외곽 마스크·얼굴·꼭지·발 기준·동작과 프레임별 patch는 보존합니다.
- 상단 광택은 왼쪽 위의 작은 반사 덩어리로 정리하고 십자 반짝임을 제거했습니다. 아래 반사도 몸체 가장자리의 짧은 곡선으로 제한합니다.
- `scripts/refine-slime-shading.py`는 공통 body/shine 좌표만 갱신하는 재현용 레시피입니다. 실행하면 해당 두 레이어의 수동 채색을 다시 쓰므로 수동 편집 이후에는 필요한 부분만 적용합니다. 이전 원본·미리보기는 `art-studies/slime-shading/`에 보존했습니다.

## 노멀맵 광택 · 2026-10-29

- 사용자 요청으로 JSON의 shine 레이어를 비우고 꼭지의 고정 밝은 반사점도 주변 색으로 정리했습니다. 원래 PNG와 조명용 시트 모두 이 원본에서 재출력합니다. 게임은 shine 레이어를 제외한 slime-lit.res와 slime-surface.res를 함께 사용합니다. 프레임별 수동 patch는 유지합니다.
- surface RGB는 화면 오른쪽/위/앞 방향의 법선을 0~1로 인코딩하고, A는 광택 강도입니다. 몸통·꼭지의 곡면 근사에 원본 포즈의 스케일·기울기를 적용합니다. 실제 3D 모델에서 베이크한 법선은 아닙니다.
- 눈·외곽선의 잉크색은 광택을 억제합니다. 소멸 동작은 광택도 함께 줄이며, 색 시트와 동일한 프레임 좌표를 사용합니다.
- 편집 패널의 저장 + 시트 반영에서 두 조명 리소스도 다시 생성됩니다. 조명 리소스만 생성하려면 Godot에서 --headless --path godot-arcana --log-file <쓰기 가능한 로그 경로> --script res://tools/bake_slime_lighting.gd를 사용합니다.
- slime_sprite.gdshader의 gloss_strength(기본 0.48), gloss_sharpness(40)로 강도와 반사점 크기를 조절합니다. 낮의 약한 기본 광택과 공유 등불·화염 광원을 사용합니다.
- 노멀맵 연결 후 웹 빌드를 완료했고 godot-web/index.html 및 index.pck에 반영했습니다. 실제 화면 품질·플레이는 사용자 확인 대상으로 남깁니다.
