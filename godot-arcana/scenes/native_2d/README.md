# 아르카나 네이티브 2D

현재 활성 플레이 표시기는 `scripts/native_2d_world.gd`입니다. `main.tscn`은 이 폴더의 `plaza.tscn`을 도시 배치 원본으로 사용합니다. 기존 3D 장면은 보관 원본이며 기본 실행·웹 패키지의 표시 장면으로 사용하지 않습니다.

## 편집 기준

- 도시·실내·상점·플레이어는 원본 픽셀의 가로·세로 비율을 보존하고 노드 Scale (1, 1)을 사용합니다.
- 논리 게임 좌표 16은 원본 표시 64픽셀입니다. 변환은 `native_2d_coordinates.gd`를 기준으로 하며 세로 압축은 없습니다.
- 도시의 수동 배치 166개, 문 위치, 충돌과 입구 정보를 이관했습니다. 도시 바닥은 `Ground/PaintedFloor`에서 기존 3D의 도시 좌우 원화·분수 모자이크와 포장·정원 마스크를 2D 셰이더로 합성합니다. 64×64 타일 레이어는 보존하되 숨기며, 상점의 반 칸 타일은 32×32입니다.
- 도시의 Placements 아래 개별 배치 노드 Position은 접지점(원본 표시 픽셀)입니다. Visual Offset과 논리 충돌·상호작용·출입·등록 Transform은 해당 접지점의 로컬 좌표이며, Position을 옮기면 표시와 게임 판정이 같은 이동을 따릅니다. 그림 자식 `Visual`을 직접 옮긴 기존 배치도 그 이동을 판정에 반영합니다. 논리 좌표는 표시 픽셀의 1/4입니다.
- 기존 배치의 확대는 파생 이미지에 반영했습니다. 파생 이미지는 `art/export/native-2d/`의 압축 리소스로 공유합니다. 원본 미술은 보존합니다.
- 여관과 학교 1·2층의 개별 Sprite2D도 Position을 기존 접지점으로 두고, metadata/foot은 스프라이트 로컬 좌표입니다. 여관 조명은 가구의 자식으로 로컬 위치를 보정했습니다. 바닥 러그는 점유 면의 중심을 사용하고 바닥·타일맵·식당 합성 배경은 기존 격자 기준을 유지합니다. 실내의 논리 충돌·상호작용은 기존 inn_lobby.gd·academy_interior.gd의 방 좌표를 유지합니다.
- 도시 성벽, 여관, 학교 1·2층과 식당은 별도 2D 장면입니다. 사냥 공간은 같은 야외 장면의 남쪽 구역과 논리 이동을 유지합니다.

## 성벽 타일 편집

도시의 `Walls`는 승인된 전체 성곽에서 추출한 조각을 사용하는 기본 `TileMapLayer`입니다.
`wall_assembled_demo.tscn`은 원형, `wall_assembled_expanded_demo.tscn`은 확장형 편집 예제입니다.
**Walls → TileMap → Patterns**에서 직선·모서리·입구 또는 성곽 전체를 골라 배치합니다.
24개 조각과 전체 배치2개를 등록했으며, 그림은 여러 칸에 걸쳐도 삭제 기준은 조각의 기준 칸입니다.
편집 간격·미술 원본·재출력은 [승인 성곽 조립 안내](../../art/source/walls/assembled-v1/README.md)를 따릅니다.
이전 Terrain Connect 성벽은 보존 이력이며 현재 활성 성벽이 아닙니다.

## 표시와 게임 연결

플레이어의 기존 달리기·대기·시전·대시·착석 프레임 및 타이밍, 슬라임의 전투 프레임, 분수·포털·안내원 애니메이션을 2D로 표시합니다. 캐릭터 그림 자체를 늘리지 않습니다. 카메라와 캐릭터는 최종 화면 픽셀 격자에 맞춥니다.

전투 조준·투사체·충격·데미지 숫자·적 체력 표시·퀘스트 표시·다른 플레이어·이름표는 네이티브 2D 표시기와 연결합니다. 3D 비교 메뉴는 기본 메뉴에서 제거했습니다. 서버 API·저장 ID·논리 이동 규칙은 유지합니다.

게임 판정은 `world.gd`와 서버가 담당합니다. 배치 노드의 `registered_transform`은 과거 출입 방향과 충돌을 보존하는 기하 데이터이며, 3D 렌더 노드를 생성하지 않습니다. 전투 내보내기는 이 2D 장면의 저장 데이터를 읽습니다.

## 이관 도구와 확인 범위

`tools/export_native_2d_city.gd`, `export_native_2d_rooms.gd`, `export_native_2d_walls.gd`, `finish_native_2d_layout.gd`, `export_native_2d_restaurant.gd`는 최초 이관용입니다. 기존 2D 편집 장면을 자동 재생성하거나 덮어쓰지 않습니다. 정상 빌드는 이 도구들을 실행하지 않습니다.

웹 빌드는 `scripts/sync-godot-export-resources.py`로 실행 스크립트의 참조를 포함하고, `tools/verify_web_pack.gd`로 원본 프로젝트를 참조하지 않는 별도 환경에서 PCK의 스크립트·장면을 확인합니다. 소스 가져오기 성공만으로 웹 패키지의 완전성을 판단하지 않습니다.

브라우저에서 도시 이동과 상점·여관 진입 및 도시 복귀를 확인했습니다. `tools/review_native_2d_scenes.gd`의 실제 GPU 출력으로 도시·상점·여관·학교 두 층·식당을 검토했고, 각 표시 장면의 Node3D 수가 0임을 확인했습니다. 학교 계단 이동·전투·다른 플레이어 동시 접속은 이번 화면 복구 검증 범위에 포함하지 않았습니다.

식당 표면 변환 오류만 고칠 때는 `export_native_2d_restaurant.gd -- --repair-texture`를 사용합니다. 편집된 장면은 보존하고 표면 리소스만 갱신하며, 면의 실제 깊이와 Godot의 시계 방향 앞면을 사용합니다. 셰이더 전용 외곽선 복제 메시를 표면 이미지에 중복으로 굽지 않습니다.

## 도시 산책 구역

`plaza.tscn`의 `Placements/WalkingQuarter`는 자식 편집을 켠 `city_walk_quarter.tscn` 인스턴스입니다. 광장에서 `StreetDetails`의 소품과 `Residents`의 주민을 각각 선택해 위치를 편집할 수 있으며, 광장에 저장한 변경은 해당 인스턴스에 적용됩니다. 주민의 산책 경로는 별도의 Route 속성입니다. 각 소품은 편집기 묶음으로 설정되어 화면에서 선택하면 부모가 선택됩니다. 부모 이동과 기존 `Visual`의 위치 이동은 충돌·상호작용에 반영됩니다. 이미지의 크기 변경은 충돌 영역을 자동으로 바꾸지 않습니다. 원본 여행자 프레임은 그대로 재사용하며 네이티브 노드 Scale은(1,1)입니다. `native_2d_city_life.gd`는 주민의 로컬 산책·관찰 대화·바람·나비·등불을 담당하고 기존 이동·충돌 지도를 재사용합니다. 주민은 서버의 계정이나 보상을 만들지 않습니다.

골목의 최종 배치와 웹 패키지 미술 출력은 [도심 명세](../../../art-studies/regions/arcana-city-center/brief.md)의 ‘걸으며 둘러보는 도시’를 따릅니다. 위치 변경 후에는 `build-arcana-online.ps1`이 combat/online 충돌을 함께 내보내며, 로컬 제공에는 raw/gzip 파일을 함께 갱신하는 `publish-plaza-build.ps1`을 사용합니다. 최초 제작용 `author-once.cjs`로 수동 편집 씬을 재생성하지 않습니다.
