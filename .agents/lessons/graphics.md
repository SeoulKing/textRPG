# 그래픽과 화면 학습 메모

[학습 메모 색인으로 돌아가기](../LESSONS.md). 현재 작업에 해당하는 항목만 확인합니다. 각 행의 재검토 조건을 함께 적용합니다.

| 범위 | 관찰 또는 실패 지문 | 다음 결정 | 재검토 조건 |
| --- | --- | --- | --- |
| 지도 일러스트 선호 | 사용자는 사람 없는 쿼터뷰 지도와, 육각형 안에 글자 대신 대표 건물을 넣은 통일된 월드맵을 선호합니다. 학교 안에서도 선택지 메뉴가 아니라 내부 타일 지도로 이동하기를 원합니다. 건물에 들어가면 내부 맵을 기본으로 보여 주고, 왼쪽 아래 월드맵 버튼으로 상위 지도를 여는 폴더 같은 계층 구조를 선호합니다. 위치를 레지스트리와 이웃 링크에만 추가하면 기존 저장에서는 `known_<locationId>`가 없어 지도에서 숨겨질 수 있습니다. | 현실과 마법세계는 같은 육각 좌표와 목적지 선택·이동 방식을 공유합니다. 아르카나 도심은 중앙 분수와 주변 여섯 칸을 하나의 통합 일러스트로 만들고 내부 육각 경계는 숨깁니다. 건물·길·바닥을 같은 그림에서 제작해 시점과 축척을 맞추며, 장소별 투명 선택 영역은 유지합니다. 사냥터는 남문 바깥에 둡니다. 도심 밖의 개별 객체는 투명 배경과 공통 지면을 사용하고, 바닥은 건물 축척에 맞춥니다. 객체 전체를 타일 안에 맞춰 자르지 않으며 사람·글자는 넣지 않습니다. 현재 위치는 점 대신 금색 테두리로 표시합니다. 선택한 목적지는 파란색 테두리와 목록의 선택 표식으로 구분합니다. 새 고정 지역을 추가할 때 `normalizeExplorationKnowledge`의 발견 조건과 기존 저장에서 이를 다시 계산하는 경로를 함께 확인합니다. | 사용자가 지도 형태·글자·투영·위치 표기·군중 표현을 다시 지정할 때 지도 노출이 발견 플래그를 사용하지 않도록 구조가 바뀔 때 |
| 반응형 화면과 모바일 기준 | 사용자는 모바일 기준으로 갤럭시 S24 울트라의 `384 × 824` CSS 픽셀을 지정했고, 큰 화면에서도 창 크기에 맞는 반응형 출력을 요청했습니다. | `384 × 824`는 모바일 배치의 기준으로 사용하며 게임 비율을 이 크기에 고정하지 않습니다. Godot는 `canvas_items`와 `expand`로 창 비율에 맞게 월드를 확장하고 HUD·메뉴는 읽기 좋은 폭을 유지합니다. 도트 월드의 최종 확대는 정수 배율을 유지합니다. 실제 테스트는 별도 요청 시에만 수행합니다. | 사용자가 고정 화면비나 새로운 기준 기기·UI 배율을 지정할 때 |
| 장면 그래픽 방향 | 현실 생존 본편의 숲 이미지는 연필·목탄 방향입니다. 별도로 Godot 아르카나는 밝고 생활감 있는 마법도시와 깊은 숲의 도트 아트, 분수 광장 우선 제작으로 확정됐습니다. 사용자는 분수 바닥 정렬처럼 실제 원본의 접지·중심·밑면 투영을 측정해 게임 장면에 맞추는 방식을 앞으로의 디자인 기본으로 요청했습니다. | 사용자는 파이어볼의 불씨 응축·발사·회복과 공격 방향별 캐릭터 모션을 함께 제작한 결과를 칭찬하고, 앞으로도 같은 방식으로 작업하라고 요청했습니다. 스킬 연출은 승인 시안에 맞춰 캐릭터 자세·공격 방향·손 위치·효과 타이밍을 함께 연결하고, 생성 시트의 여분 손 같은 해부 오류를 정리한 뒤 실제 게임 장면의 오프라인 렌더로 정렬을 확인합니다. 새 미술은 실루엣·접지점·타원 비율을 실측하고 기존 자산과 같은 장면에서 중심·평면·시점·타일 접합을 맞춥니다. 보정 근거를 등록 명세와 빌더에 보존하고 실제 배포 패키지·서버 제공 파일까지 확인하되 브라우저 확인과 구분합니다. 본편 숲에는 `assets/scenes/forest-pencil-charcoal.png`, Godot 아르카나에는 `ARCANA_ART_GUIDE.md`와 `godot-arcana/art/source/`를 사용해 세계별 기준을 구별합니다. 사용자는 World of Anterra를 미술 참조로, 제공한 Never End 기술 영상을 실제 3D 도트 렌더링 적용 지시로 확정했습니다. 기본 Godot 화면은 새 3D 렌더러를 사용하고 기존 2D 월드는 이동·충돌·게임 진행을 유지합니다. 광장 미술이 완성되기 전 지역·기능을 확장하지 않으며 큰 장면 한 장의 축소로 게임 자산을 대신하지 않습니다. 사용자는 개발자와 같은 Godot 장면을 직접 보며 배치하기를 원합니다. 광장 배치는 사용자와 같은 Godot 장면인 `godot-arcana/scenes/plaza.tscn`을 원본으로 수정하고, 코드로 장면을 재생성해 사용자 편집을 덮어쓰지 않습니다. Godot 정지 렌더도 실제 `main.tscn`의 Plaza 인스턴스를 읽어 시작 장면의 Transform 오버라이드까지 포함합니다. `plaza.tscn`만 읽은 렌더는 본체와 지면·충돌이 어긋나는 실행 장면 문제를 놓칠 수 있습니다. 광장 루트는 단위 좌표계로 유지하고 자식 배치만 옮깁니다. 로컬 자동 반영은 장면 저장 기준이며 웹은 내보내기가 필요합니다. 사용자는 Blender 조작을 에이전트에게 맡기고 프로젝트 안의 공식 포터블을 사용하기로 했습니다. 현재 사용자는 첨부 원화 오른쪽 아래 인게임처럼 그림 느낌의 2D 자산과 가까운 구도를 선택했고, 현재 분수의 퀄리티를 유지하도록 지정했습니다. 보존된2D 자산은 생성 원화를 보존하고 godot-arcana/art/source/heroine/skeletal/의 보강 PNG와 native Skeleton2D·17Bone2D·Polygon2D·AnimationPlayer 장면에서 도트로 출력한96×136·발(48,116)·8방향 레이어입니다. 원본의 관절 안쪽을 실제로 채운 뒤 같은 포즈를 출력하고 workshop.json으로 프레임 틈을 보정합니다. 머리/몸통/다리를 이미지 가로선으로 잘라 다른 방향과 합치는 방식은 사용하지 않습니다. 사용자는 현재 나무의 도트 품질을 전체 기준으로 지정했습니다. 캐릭터는 같은 64칸/단위에서 머리·얼굴·옷을 명확한 색 덩어리로 구분하며, 초기 원화는 hero-*-clusters-v2.png이며 현재 편집 원본은 skeletal/입니다. 보존된2D 보행은 실제 이동 20좌표(1.25칸)마다24자세를 순환하며 최대3칸/초를 유지합니다. 기본288프레임 주소 뒤에 정지회전64장을 추가한352프레임입니다. 다리는 허벅지15/정강이12픽셀의 로컬 위치와 scale(1,1)을 고정하고 회전 키만 사용합니다. Skeleton2D를 사용해도 관절 위치 트랙을 움직이면 고무처럼 늘어나므로 실제 관절 간 거리와 신발별 단독 발목 소유를 검사합니다. 옆모습 신발 PNG 자체에 두 신발이 겹쳐 있지 않은지도 별도로 확인합니다. 팔은 arms-front/back으로 전완·커프·손을 옷 앞/몸통 뒤에 나누고 숄은 상완을 덮습니다. 새 팔을 추가할 때 기존 몸체/옷에 붙은 소매·손 조각을 함께 제거해 팔이 늘어나거나 중복되지 않게 합니다. arm-joints.json의 방향별 어깨/팔꿈치/손목과 고정 길이 회전 키를 사용하며 naked 조합에는 arms-bare를 씁니다. skeletal/의 PNG와 수동 native 장면, workshop.json, 수동 SpriteFrames/TileSet을 재출력 시 보존합니다. 뼈대 변경은 scripts/rebuild-heroine-skeleton.ps1로 출력하고 프레임 좌표 수정만 할 때는 Node 시트 갱신을 사용합니다. 의상 가림은 실제 옷의 불투명 픽셀이 덮는 곳만 사용하고 목/허리를 Y좌표 범위로 지우지 않으며 신발 가림이 반대 다리를 지우지 않게 발 없는 몸체와 비교합니다. heroine_sprite.gd가 옷과 몸체 가림을 조립하며 기본 정면뷰·전체 줌 4·공통 64칸/단위·약 220픽셀 표시를 사용합니다. 분수 모델·공유 셰이더·조명·LUT와 사용자 plaza.tscn은 보존하고 새 자산을 맞춥니다. 과거 Blender/64×80 베이크는 보존 자료이므로 현재 자산을 과거 출력으로 되돌리지 않습니다. 실제 GPU 증거는 art/reference/reference-scene/이며 브라우저 플레이 확인과 구별합니다. 현재 주인공은 사용자가 고른 청순한 일본 애니메이션풍 백발 단발 후보 2번입니다. 의상 교체용 2D 시안은 몸·머리·상의·하의·신발·숄을 분리해 부위별 자유 조합을 지원합니다. 원화 드레스는 상의·하의를 함께 점유하고 가림 마스크는 공통 몸체에만 적용합니다. 새 의상과 동작에는 방향별 자산과 가림 검수가 필요합니다. 사용자는 굵고 벌어진 소매와 큰 손 때문에 체형이 부풀어 보이는 것을 강하게 원치 않습니다. 관절 틈은 겹쳐 그린 안쪽 도트와 세분화한 부품으로 채우며, 팔 전체를 굵게 만들어 가리지 않습니다. 어깨·팔꿈치를 몸 가까이 두고 원화의 작은 손·가는 손목을 같은 배율의 전후 렌더로 확인합니다. 하늘색 숄·흰 드레스·보랏빛 눈을 보존하고 상자형 몸통이나 끊긴 관절 대신 곡면과 연속 스킨으로 제작하며, 확대 렌더와 실제 도트 해상도 가독성을 함께 확인합니다. 아르카나 이동은 조이스틱 최대 입력에서 내비게이션 격자 초당 3칸을 기준으로 하며, 작은 입력에는 비례 속도를 유지합니다. 보행 애니메이션 주기를 맞추기 위해 이동 자체를 느리게 바꾸지 않습니다. 향후 개발·미술·조작 검수는 정면 시점을 기준으로 하며 쿼터뷰는 비교 기능으로 유지합니다. 사용자는 모션 개선에서 프레임 수보다 각 자세의 타당성(좌우 지지·회수·체중 이동·반대팔·착지)을 우선합니다. 장수를 먼저 정하지 말고 동작이 어긋난 키포즈부터 고치고 필요한 사이 자세만 보탭니다. 도트 애니메이션은 매 프레임 이미지를 새로 생성하기보다 공통 팔레트·레이어 원본과 프레임별 도트 좌표 수정을 보존하며 Godot에서 직접 편집하는 방식을 선호합니다. 사용자는 실시간 뼈대 변형보다 선명한 도트를 우선하여 공통 뼈대 제작→도트 출력→프레임 보정을 선택했습니다. 검사 통과와 자연스럽게 연결된 실루엣의 육안 확인을 구별하며, 신발 검사는 실제 native GPU 결과를 실제 Bone2D 변환과 비교합니다. 가림 효과는
