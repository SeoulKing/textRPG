# 그래픽과 화면 학습 메모

[학습 메모 색인으로 돌아가기](../LESSONS.md). 현재 작업에 해당하는 항목만 확인합니다. 각 행의 재검토 조건을 함께 적용합니다.

| 범위 | 관찰 또는 실패 지문 | 다음 결정 | 재검토 조건 |
| --- | --- | --- | --- |
| 지도 일러스트 선호 | 사용자는 사람 없는 쿼터뷰 지도와, 육각형 안에 글자 대신 대표 건물을 넣은 통일된 월드맵을 선호합니다. 학교 안에서도 선택지 메뉴가 아니라 내부 타일 지도로 이동하기를 원합니다. 건물에 들어가면 내부 맵을 기본으로 보여 주고, 왼쪽 아래 월드맵 버튼으로 상위 지도를 여는 폴더 같은 계층 구조를 선호합니다. 위치를 레지스트리와 이웃 링크에만 추가하면 기존 저장에서는 `known_<locationId>`가 없어 지도에서 숨겨질 수 있습니다. | 현실과 마법세계는 같은 육각 좌표와 목적지 선택·이동 방식을 공유합니다. 아르카나 도심은 중앙 분수와 주변 여섯 칸을 하나의 통합 일러스트로 만들고 내부 육각 경계는 숨깁니다. 건물·길·바닥을 같은 그림에서 제작해 시점과 축척을 맞추며, 장소별 투명 선택 영역은 유지합니다. 사냥터는 남문 바깥에 둡니다. 도심 밖의 개별 객체는 투명 배경과 공통 지면을 사용하고, 바닥은 건물 축척에 맞춥니다. 객체 전체를 타일 안에 맞춰 자르지 않으며 사람·글자는 넣지 않습니다. 현재 위치는 점 대신 금색 테두리로 표시합니다. 선택한 목적지는 파란색 테두리와 목록의 선택 표식으로 구분합니다. 새 고정 지역을 추가할 때 `normalizeExplorationKnowledge`의 발견 조건과 기존 저장에서 이를 다시 계산하는 경로를 함께 확인합니다. | 사용자가 지도 형태·글자·투영·위치 표기·군중 표현을 다시 지정할 때 지도 노출이 발견 플래그를 사용하지 않도록 구조가 바뀔 때 |
| 반응형 화면과 모바일 기준 | 사용자는 모바일 기준으로 갤럭시 S24 울트라의 `384 × 824` CSS 픽셀을 지정했고, 큰 화면에서도 창 크기에 맞는 반응형 출력을 요청했습니다. | `384 × 824`는 모바일 배치의 기준으로 사용하며 게임 비율을 이 크기에 고정하지 않습니다. Godot는 `canvas_items`와 `expand`로 창 비율에 맞게 월드를 확장하고 HUD·메뉴는 읽기 좋은 폭을 유지합니다. 도트 월드의 최종 확대는 정수 배율을 유지합니다. 실제 테스트는 별도 요청 시에만 수행합니다. | 사용자가 고정 화면비나 새로운 기준 기기·UI 배율을 지정할 때 |
| 장면 그래픽 방향 | 같은 주인공의 제작 이력과 과거 활성 경로가 여러 문서에 섞여 현재 지시와 충돌한 적이 있습니다. | 현행 기준은 docs/roles/CHARACTER_ART.md와 WORLD_BUILDING.md, 실제 main.tscn 호출을 먼저 확인합니다. 미술 파일명에 heroine이 있어도 소품·NPC가 공유하는 셰이더일 수 있으므로 이름만으로 삭제하지 않습니다. 사용자 저장 배치·Transform·충돌을 유지하고, 제작 원본·합성 결과·게임 연결·체감 승인을 구분합니다. | 사용자가 확정 캐릭터·렌더러·공동 편집 방식을 다시 지정하거나 실제 활성 연결이 변경될 때 |

| 도심 바닥 표현 | 사용자는 반복 사각 타일·일반 자갈 바닥을 거절하고, 바닥을 기존 나무·가로등의 디테일에 맞춘 마법도시 디자인으로 요청했습니다. 1536×1024를72×56월드에 늘리면 약21/18픽셀 밀도로 기존64픽셀 기준과 어긋납니다. | 승인된 상아색·청금 인레이·천체/별자리 원본과 현행 ARCANA_ART_GUIDE.md를 따릅니다. 파일 크기만 늘리지 말고 실제 가져온 텍스처/월드 범위로 밀도를 계산하고, 나무·가로등이 함께 보이는 가까운 실제 렌더로 확인합니다. 현재 청금 방향은 유지하고 구역별로 디테일을 보강하며, 품질 참조는 기존 분수 바로 둘레의 art/export/fountain-paving/mosaic-ring.png입니다. 전체 디자인을 다시 바꾸지 않고 재질별 마감을 작은 구역부터 같은 근접 장면으로 확인합니다. | 사용자가 다른 도시 분위기·반복 소재·새 픽셀 밀도를 명시적으로 선택할 때 |

| 일반 캐릭터 비율 | 사용자는 주인공·메이의 승인 비교 비율을 일반 인물의 기본으로 지정했습니다. 전체 키만 맞추고 머리·몸통 비율이 다른 결과는 거절했습니다. | 새 캐릭터는 ARCANA_ART_GUIDE.md의 일반 캐릭터 확정 비율과 보존 기준 이미지를 먼저 확인합니다. | 사용자가 특별한 키·체격을 지정하거나 기본 비율을 변경할 때 |

| 벤치와 생활 소품 동선 | 사용자는 벤치 앞 화단 때문에 앉을 수 없는 배치를 지적했습니다. 장식은 자연스러운 옆·뒤 또는 정원 가장자리에 두기를 원합니다. | 벤치 위치를 옮기거나 충돌을 끄기 전에 화단·울타리·테이블 등 가리는 소품을 재배치합니다. 앉는 지점(+Z0.5)과 캐릭터 충돌 여유, 앞 접근 공간을 먼저 비우며 저장 장면의 표시와 충돌을 함께 갱신합니다. | 사용자가 화단으로 둘러싼 비접근 장식 벤치나 별도의 접근 방향을 명시할 때 |
| 월드 이름표와 UI 스냅 | Godot 4.5.1은 Control 위치를 렌더러에 전달할 때 로컬 정수로 다시 반올림하며 get_transform에는 이 반올림이 나타나지 않습니다. 물리 픽셀로 맞춘 뒤 UI 배율로 나눈 위치도 다시 흔들릴 수 있습니다. | 비정수 UI 배율에서 월드 표식을 정렬할 때는 Panel/Label의 내부 위치를 고정하고 Node2D 부모를 이동해 물리 픽셀 정렬을 유지합니다. viewport 전체 GUI 스냅을 바꾸기 전에 이 국소 경로를 확인합니다. 근거는 4.5.1 Control::_update_canvas_item_transform과 Node2D::_update_transform입니다. | 엔진 버전·GUI 스냅 설정이 바뀌거나 이름표를 월드 안에서 직접 렌더하도록 바꿀 때 |

| 자산 점유와 제작 방법 | 사용자는 개발용 점유 그리드와 모든 월드 자산의3/4 투영·제작 방법 통일을 요청했습니다. | ARCANA_ART_GUIDE.md와 godot-arcana/art/ASSET_AUTHORING_METHOD.md를 적용합니다. | 사용자가 투영·격자·화풍을 변경할 때 |

| 네이티브 2D와 정사각형 픽셀 | 사용자는 상점뿐 아니라 도시·실내·사냥 공간 전체를 실제 2D로 개발하고 노드 Scale (1, 1)을 사용하도록 확정했습니다. | 현재 원본은 godot-arcana/scenes/native_2d/와 shop_2d.tscn입니다. 세로 압축이나 3D 빌보드로 되돌리지 않고 편집기와 게임의 동일 배치 및 최종 화면 픽셀 정렬을 유지합니다. 사용자가 특히 좋아한 여관의 기존 가구·벽·바닥 디테일과 분위기를 실내 품질 기준으로 보존합니다. | 사용자가 표시 방식이나 픽셀 규격을 다시 지정할 때 |
| 캐릭터 아틀라스 접합 선호 | 사용자는 파츠 연결부의 눈에 띄는 표시를 원치 않습니다. | 생성·보정 전에 ARCANA_ART_GUIDE.md의 「캐릭터 파츠 아틀라스의 자연스러운 접합」을 적용합니다. | 사용자가 별도 관절 표시용 도해를 명시할 때 |
