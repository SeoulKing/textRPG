| Content Studio runtime source | Published Studio data can come from the configured database and differ from the tracked `content/content-studio.json` seed. | Test Studio synchronization with an injected or loaded published registry; do not treat the local seed as evidence of the live value. | Reconsider when deployment no longer uses `PostgresContentStudioStore` or published data is exported back into the tracked seed. |
| 로컬 콘텐츠 검증 | 일반 셸에서는 `npm.cmd`가 PATH에 없고, 번들 `pnpm.cmd`는 번들 Node 경로를 PATH에 추가해야 실행됩니다. `tsx`가 `uv_os_get_passwd returned ENOMEM`으로 중단되어도 번들 Node로 `tsc` 컴파일 후 생성된 `game/data/registry.js`의 `validateContent()`를 직접 호출하는 경로는 정상 동작합니다. | `tsx`의 같은 `ENOMEM`을 반복하지 않고, `.tmp-validate` 아래로 컴파일해 콘텐츠 검증과 필요한 로직 스모크 테스트를 실행합니다. | 셸 PATH가 정상화되거나 새 런타임에서 메모리 오류 없이 `tsx`가 실행될 때 |
| 브라우저 검증 | 현재 `package.json`에는 Playwright 의존성이 없어 독립 Playwright 스크립트가 `ERR_MODULE_NOT_FOUND: playwright`로 실패하고, Chrome headless/CDP는 관리형 셸의 프로세스 권한과 페이지 타깃 시작에 좌우됩니다. 반면 Codex의 열린 인앱 브라우저는 `cua_repl`의 기존 탭 연결, DOM 조회와 `tab.screenshot()`으로 화면 확인이 가능합니다. 확인용 새 탭 생성이 시간 초과되어도 탭 목록에 로드가 완료되어 있으면 그 탭을 연결해 계속 진행할 수 있습니다. | 웹의 새로고침 후 첫 동작 끊김은 네이티브 노드 생성 시간 감소만으로 해결됐다고 판단하지 않습니다. 시전·비행·명중 단계 각각에서 처음 그리는 셰이더·캐릭터 텍스처·글꼴이 사전 렌더 범위에 포함됐는지 확인하고 실제 웹 증상 해소와 구별합니다. 오프라인 GPU 미술 렌더와 Web export 성공만으로 실제 브라우저 반영이나 시각적 개선을 확인했다고 보고하지 않습니다. 반영 차이 지적 시 실제 탭 화면과 서버 제공 파일의 해시·Cache-Control을 확인하고, 해상도·카메라 차이와 수정 부족을 캐시 문제와 구별합니다. 테스트 실행은 사용자가 직접 합니다. 명시적 요청이 없으면 사용자의 열린 탭을 조작하거나 새로고침하지 않습니다. 기술적으로 브라우저 확인이 필요해 사용자가 요청한 경우에만 한 세션에서 확인하며 독립 Playwright나 Chrome 프로세스를 관성적으로 재호출하지 않습니다. | 인앱 브라우저 연결 자체가 실패하거나 사용자가 Chrome/독립 실행 환경을 명시할 때 |
| 로컬 서버 재시작 | 관리형 PowerShell에서는 `Start-Process`가 `Path`/`PATH` 중복으로 실패할 수 있고, 권한을 올린 `Stop-Process`는 실제 종료보다 먼저 반환될 수 있습니다. 서버는 시작할 때만 `.env`와 `.env.local`을 읽으므로 실행 후 키를 추가·변경하면 기존 프로세스에는 반영되지 않습니다. 또한 관리형 기본 샌드박스에서 띄운 Node 서버의 외부 `fetch`는 `cause.code: EACCES`로 차단될 수 있지만, 동일 설정을 네트워크 권한으로 실행하면 Gemini 모델 조회와 생성이 정상 동작합니다. | 컴파일된 `.server-dist/server.js` 실행은 빌드만으로 메모리의 모듈이 갱신되지 않습니다. 응답 스키마 변경 후 구 화면으로 돌아가면 실행 서버의 시작 시각과 실제 새 필드를 확인합니다. 새 빌드를 먼저 만든 뒤 정확한 3000번 리스너 PID만 종료하고, `netstat`으로 포트가 빈 것을 확인합니다. `Start-Process`가 같은 오류로 막히면 `cmd start "" /B`로 번들 Node와 로그 리디렉션을 실행하고, 반환값 대신 새 리스너 PID와 브라우저 상태 동기화로 성공을 판정합니다. `.env` 변경 시 3000번 포트의 기존 서버를 재시작하고, 기본 실행의 Gemini 테스트가 `fetch failed`이면 Node 단발 연결의 `cause.code`를 확인합니다. `EACCES`일 때만 서버를 네트워크 권한이 있는 숨김 프로세스로 다시 띄운 뒤 `/api/gemini/test` 실제 생성 성공으로 판정합니다. | PowerShell 환경변수 중복이 해소되거나 서버가 `tsx watch`처럼 자동 재시작 방식으로 실행될 때 서버가 `.env`를 런타임에 다시 읽도록 바뀌거나 관리형 기본 샌드박스에 외부 네트워크 권한이 제공될 때 |
| 게임 엔진 웹 빌드 | Godot export의 .tscn/.tres는 remap되므로 FileAccess.file_exists(원본 경로)가 false여도 ResourceLoader.exists는 true입니다. 소스 GPU 렌더에는 보이던 지면 타일이 웹에서 빠진 원인이었습니다. 6000.0.26f1 에디터는 수동 설치되어 Hub의 `install-modules`가 `No modules found for this editor`로 실패하고, 공식 WebGL 설치 파일은 Windows 관리자 확인이 필요합니다. 기본 샌드박스의 Unity 배치 실행은 라이선스 IPC 연결에 실패할 수 있지만, 네트워크 권한이 있는 실행에서는 6000.6.3f1의 WebGL 빌드가 성공했습니다. Godot의 custom Web 템플릿은 thread_support=false 설정과 별개로 선택되며, 일반 web_release.zip을 지정하면 SharedArrayBuffer / crossOriginIsolated 오류로 로딩이 멈춥니다. Windows PowerShell 5의 ProcessStartInfo.ArgumentList는 null이어서 Blender/GPU 실행 도우미가 실패하지만 번들 pwsh에서는 실행됩니다. Godot 4.5.1의 FontVariation은 문자열 wght 키가 실행 시 무시되어 가변 글꼴이 기본 굵기 100으로 표시됐지만 정수 OpenType 태그는 정상 적용됐습니다. PixelPen1.1.4 편집기의 종료 리소스 오류는 창의 지연 로드·정적 상태 해제 패치로 해결해 원본 프로젝트 가져오기/내보내기가 성공했습니다. recovery-mode는 네이티브 타입을 꺼 PixelPenImage/PixelPenCPP 구문 오류가 나므로 이 문제의 대체 경로로 쓰지 않습니다. | 공용 fixed-legs-import.log도 다른 빌드에 점유되어 쓰기가 실패할 수 있으므로 동시 빌드에서는 stage뿐 아니라 로그와 웹 출력까지 작업별 고유 경로로 분리하고, 완료된 PCK만 공용 경로에 반영합니다. 패키지 리소스 존재 여부는 ResourceLoader.exists로 판단하고 파일 타임스탬프 폴링은 편집기에 한정합니다. 내보낸 게임의 누락은 실제 PCK 로딩으로 확인합니다. 관리자 확인이 불가능하면 WebGL 모듈이 있는 에디터로 프로젝트 복사본을 빌드해 원본 버전을 유지합니다. Unity 배치 빌드는 `Start-Process -Wait -PassThru -WindowStyle Hidden`으로 완료 코드와 산출물을 확인합니다. Godot 단일 스레드 웹 빌드는 같은 버전의 web_nothreads_release.zip을 사용합니다. Blender와 GPU 실행 도우미는 `pwsh -File`로 실행합니다. 동시 작업에서는 공유 stage 포인터뿐 아니라 공용 웹 PCK도 다른 내보내기로 덮일 수 있으므로 작업별 고유 stage·출력 경로를 사용합니다. 전용 PCK에서 대상 셰이더/텍스처를 확인한 뒤 공용 경로에 반영하고 서버 제공 파일 해시를 맞춥니다. 공용 PCK가 메모리맵되어 덮어쓰기가 거부되면 같은 폴더의 임시 PCK를 만든 뒤 File.Replace로 원자 교체하고 이전 파일을 보존합니다. 실행 중인 편집기나 사용자 게임을 종료하지 않으며, 일반 덮어쓰기 재시도는 파일 잠금이 해제됐을 때만 합니다. Godot GPU 미술 출력은 기본 user:// 로그 경로에서 충돌할 수 있으므로 scripts/render-godot-pixel3d-art.ps1로 작업 폴더의 APPDATA·LOCALAPPDATA·--log-file을 사용합니다. 공식 export_templates.tpz에서 해당 ZIP 엔트리만 바이트 범위로 받아도 빌드할 수 있으며, 이 다운로드 서버는 suffix 범위 대신 파일 크기에 따른 명시적 범위가 필요합니다. 새 PNG의 사전 로드는 .import가 없을 때 has no resource loaders로 실패할 수 있으므로 먼저 Godot 가져오기를 완료한 뒤 연결합니다. 오류 후 가져오기가 완료되어 캐시가 생긴 경우에만 한 번 다시 실행합니다. 가변 HUD 글꼴에는 wght=2003265652, tnum=1953396077의 정수 태그를 쓰고 실제 화면의 굵기로 확인합니다. PixelPen은 Godot4.5.1에서1.1.4를 고정하고 종료 정리 패치를 보존합니다. 열린 에디터가 ~libpixelpen shadow DLL을 잡으면 별도 Godot 가져오기/내보내기가 복사 실패·종료 리소스 오류를 낼 수 있습니다. 이 경우 원본 설정/열린 에디터를 건드리지 않고 scripts/export-fixed-legs.ps1의 애드온 없는 런타임 사본을 사용하며, 에디터를 닫거나 shadow DLL 충돌이 해소됐을 때 일반 경로를 다시 확인합니다. export_presets.cfg로 에디터 플러그인/원본을 제외하며 PCKv3 파일 목록·extension_list에서 네이티브 확장 제외를 확인합니다. 플러그인 자체 해결이 불가능하고 런타임이 addons를 참조하지 않는 경우에만 임시 복사본에서 에디터 플러그인을 제외해 내보냅니다(템플릿은 절대 경로). 동일 SHA256의 WASM 등 엔진 파일이 열려 있으면 재복사하지 않고 건너뜁니다. 변경된 웹 파일만 같은 폴더 임시 파일과 File.Replace로 원자 교체하며 사용자 브라우저를 종료하지 않습니다. | 6000.0.26f1에 WebGL 모듈이 설치되거나 기본 샌드박스의 Unity 라이선스 IPC가 정상화될 때 Godot의 웹 템플릿 변형·이름 또는 다운로드 서버가 바뀌면 다시 확인합니다. FontVariation의 문자열 태그가 실제 렌더러에서 지원되는 버전으로 바뀌면 재검토합니다. 편집기 플러그인의 Web 내보내기 문제가 해결되거나 런타임이 addons를 참조하면 이 대체 경로를 재검토합니다. |
