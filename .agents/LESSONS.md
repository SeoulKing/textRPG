| 로컬 콘텐츠 검증 | 일반 셸에서는 `npm.cmd`가 PATH에 없고, 번들 `pnpm.cmd`는 번들 Node 경로를 PATH에 추가해야 실행됩니다. `tsx`가 `uv_os_get_passwd returned ENOMEM`으로 중단되어도 번들 Node로 `tsc` 컴파일 후 생성된 `game/data/registry.js`의 `validateContent()`를 직접 호출하는 경로는 정상 동작합니다. | `tsx`의 같은 `ENOMEM`을 반복하지 않고, `.tmp-validate` 아래로 컴파일해 콘텐츠 검증과 필요한 로직 스모크 테스트를 실행합니다. | 셸 PATH가 정상화되거나 새 런타임에서 메모리 오류 없이 `tsx`가 실행될 때 |

| 로컬 서버 재시작 | 관리형 PowerShell에서는 `Start-Process`가 `Path`/`PATH` 중복으로 실패할 수 있고, 권한을 올린 `Stop-Process`는 실제 종료보다 먼저 반환될 수 있습니다. 서버는 시작할 때만 `.env`와 `.env.local`을 읽으므로 실행 후 키를 추가·변경하면 기존 프로세스에는 반영되지 않습니다. 또한 관리형 기본 샌드박스에서 띄운 Node 서버의 외부 `fetch`는 `cause.code: EACCES`로 차단될 수 있지만, 동일 설정을 네트워크 권한으로 실행하면 Gemini 모델 조회와 생성이 정상 동작합니다. | 새 빌드를 먼저 만든 뒤 정확한 3000번 리스너 PID만 종료하고, `netstat`으로 포트가 빈 것을 확인합니다. `Start-Process`가 같은 오류로 막히면 `cmd start "" /B`로 번들 Node와 로그 리디렉션을 실행하고, 반환값 대신 새 리스너 PID와 브라우저 상태 동기화로 성공을 판정합니다. `.env` 변경 시 3000번 포트의 기존 서버를 재시작하고, 기본 실행의 Gemini 테스트가 `fetch failed`이면 Node 단발 연결의 `cause.code`를 확인합니다. `EACCES`일 때만 서버를 네트워크 권한이 있는 숨김 프로세스로 다시 띄운 뒤 `/api/gemini/test` 실제 생성 성공으로 판정합니다. | PowerShell 환경변수 중복이 해소되거나 서버가 `tsx watch`처럼 자동 재시작 방식으로 실행될 때 서버가 `.env`를 런타임에 다시 읽도록 바뀌거나 관리형 기본 샌드박스에 외부 네트워크 권한이 제공될 때 |
