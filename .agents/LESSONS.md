# Project Lessons

작업 시작 시 공통 항목과 아래 표의 관련 주제만 읽습니다. 주제 파일 전체가 길면 항목 이름으로 검색하고 해당 행만 확인합니다. 모든 주제 파일을 한꺼번에 읽지 않습니다.

## 주제별 메모

| 작업 | 파일 | 항목 |
| --- | --- | --- |
| 실행·빌드·브라우저·API·게시 데이터 | [실행 환경](lessons/runtime.md) | Studio 실제 데이터, 콘텐츠 검증, 브라우저, 서버 재시작, 엔진 웹 빌드, API 응답 필드 |
| 게임 규칙·서사·선택지·기존 저장 | [게임 규칙과 서사](lessons/gameplay.md) | 재고, 시스템 노트, NPC, 전투 표시, 속말, 선택지 UI, 서사 연속성, 저장 콘텐츠, 서술 시점 |
| 지도·반응형 화면·미술 제작 | [그래픽과 화면](lessons/graphics.md) | 지도 선호, 모바일 기준, 장면·캐릭터 제작과 활성 연결 |

세부 규격과 승인 상태는 대상 가이드·명세에서 확인합니다. 이 메모에는 다음 도구 선택이나 사용자 선호 판단을 바꾸는 항목만 유지합니다.

## 공통 항목

| 범위 | 관찰 또는 실패 지문 | 다음 결정 | 재검토 조건 |
| --- | --- | --- | --- |
| 사용자 선호 | 실패한 방법을 반복하면 토큰과 시간이 낭비됩니다. 사용자는 앞으로 테스트를 직접 진행하겠다고 했습니다. | 같은 실패 지문은 전제 조건 변화 없이 재시도하지 않고, 필요한 최소 검증만 수행합니다. 별도 요청이 없으면 테스트를 실행하지 않고, 작업 완료 후 직접 확인할 행동과 기대 결과를 짧은 체크리스트로 알려줍니다. | 사용자가 더 강한 검증이나 재시도를 명시적으로 요청할 때 사용자가 특정 테스트 실행을 명시적으로 요청할 때 |
| Git 게시 | 사용자는 이 저장소에서 GitHub CLI 대신 기존 Git HTTPS 인증으로 현재 브랜치에 직접 커밋·푸시하는 방식을 선호하며, 이 경로는 정상 동작합니다. | 푸시 요청 시 실제 프로젝트 변경만 명시적으로 스테이징하고 `.codex-local-server.*.log` 같은 런타임 로그는 제외한 뒤 `git commit` 및 `git push -u origin <현재 브랜치>`를 사용합니다. PR은 명시 요청 때만 생성합니다. | HTTPS Git 인증이 실패하거나 사용자가 PR 생성을 명시적으로 요청할 때 |
| Windows 재분석 경로 쓰기 | 이 작업 공간의 지역 데이터와 테스트 경로는 기본 apply_patch에서 path contains a reparse point로 막혔습니다. | 파일 경로와 치환 기준을 확인한 뒤 승인된 PowerShell ReadAllText/WriteAllText로 수정합니다. 같은 기본 쓰기 실패는 반복하지 않습니다. | 작업 공간의 경로 구성이나 샌드박스 정책이 바뀔 때 |
