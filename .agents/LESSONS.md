# Project Lessons

다음 작업의 도구 선택을 바꾸는 항목만 유지합니다.

| 범위 | 관찰 또는 실패 지문 | 다음 결정 | 재검토 조건 |
| --- | --- | --- | --- |
| Content Studio runtime source | Published Studio data can come from the configured database and differ from the tracked `content/content-studio.json` seed. | Test Studio synchronization with an injected or loaded published registry; do not treat the local seed as evidence of the live value. | Reconsider when deployment no longer uses `PostgresContentStudioStore` or published data is exported back into the tracked seed. |
| 사용자 선호 | 실패한 방법을 반복하면 토큰과 시간이 낭비됩니다. | 같은 실패 지문은 전제 조건 변화 없이 재시도하지 않고, 필요한 최소 검증만 수행합니다. 무료 Gemini 호출을 아껴야 하므로 평소 검증에는 모의 응답을 사용하고, 실제 생성 검증은 사용자가 요청한 경우에만 필요한 최소 횟수로 수행합니다. 실제 호출 때는 같은 요청의 원문 trace와 입력 문맥도 함께 보관해 검사 실패를 재호출 없이 분석합니다. | 사용자가 더 강한 검증이나 재시도를 명시적으로 요청할 때 |
| 재고 노드 설계 | 사용자는 내용물이 비어도 남는 보관함과, 모두 수집하면 장소·진입 선택지가 사라지는 더미를 서로 다른 종류로 봅니다. | 보관함은 `depletionBehavior: "remain"`을 유지하고, 소진 시 사라질 더미에만 `"disappear"`를 지정합니다. 숲·강의 반복 채집에는 횟수 제한을 두지 않고 시간·기력·도구 비용을 유지하며, 벌목·낚시처럼 장소를 찾는 주된 행동은 입장 직후 제공합니다. | 사용자가 재생성·리필되는 세 번째 재고 노드 유형을 요구할 때 |
| 시스템 노트 | 아이템 획득 칩은 기존 게임 문법인 `+수량 아이템명` 순서를 사용하며, 문자열 조립 대신 `systemNoteEntries`의 `item` delta로 저장해야 초록색 칩과 현재 아이템명을 일관되게 적용할 수 있습니다. | 노트는 현재 `.scene-story-block` 안에서 서사의 끝과 16px 간격으로 배치해 스크롤용 최소 높이가 노트를 밀어내지 않게 합니다. 보상 시스템 노트는 중앙 포매터를 통해 `+1 캔 음식 / +1 진통제`처럼 만들고 `+캔 음식 1개`나 `캔 음식 1개` 같은 자유 문자열을 새로 만들지 않습니다. | 사용자가 시스템 노트 표기 규칙 자체를 변경할 때 |
| NPC 대화 | 선택별 선행 문단이 결과와 어긋나고, NPC 반응과 다음 선택을 분리하면 한 턴에 두 호출이 필요합니다. | NPC 반응·다음 답변 세 개·짧은 속말을 한 요청으로 받고 클릭 중에는 속말만 표시합니다. 실제 선택한 말과 반응은 결과에서 연결하며, 속말을 NPC가 들은 대사로 취급하지 않습니다. 부분 실패는 유효한 본문을 유지하고 잘못된 선택·속말만 로컬 보완합니다. | 사용자가 역할별 분리 생성이나 선행 서사 방식을 다시 명시할 때 |
| Git 게시 | 기존 Git HTTPS 인증을 사용합니다. 사용자 배포 대상은 `render.yaml`의 `codex/region-content-structure`이며, 기본 브랜치 `master`나 현재 작업 브랜치가 배포 대상이라고 추정하면 안 됩니다. | 푸시 전에 배포 목적과 설정의 대상 브랜치를 확인합니다. 실제 프로젝트 변경만 명시적으로 스테이징하고 런타임 로그는 제외합니다. 작성자 설정이 없으면 직전 저장소 커밋의 확인된 작성자를 명령 단위 `-c user.name`·`-c user.email`로 사용합니다. 배포 요청은 기존 배포 브랜치에 이력을 보존해 반영하고 푸시하며, 별도 브랜치 푸시만으로 배포됐다고 보고하지 않습니다. PR은 명시 요청 때만 생성합니다. | 배포 설정 또는 사용자가 지정한 대상 브랜치가 바뀌거나 HTTPS Git 인증이 실패할 때 |
| 로컬 콘텐츠 검증 | 현재 셸에서는 Node와 npm.cmd가 실행되지만, tsx는 여전히 uv_os_get_passwd returned ENOMEM으로 중단됩니다. tsc로 컴파일한 콘텐츠 검증과 Node 내장 테스트는 정상 실행됩니다. | PATH 복구만을 재시도 조건으로 삼지 않습니다. .tmp-validate 아래로 필요한 TypeScript 테스트를 컴파일해 node --test로 실행하고, 서버 반영은 기존 build 산출물을 사용합니다. HTML에서 module로 불러오는 app-api.js는 package.json의 commonjs 설정과 다르므로, import가 있으면 Get-Content -Raw app-api.js를 node --input-type=module --check에 전달해 구문을 검사합니다. | 런타임이 바뀌고 node:os의 userInfo() 호출이 정상 동작함을 확인했을 때 |
| 브라우저 검증 | 현재 `package.json`에는 Playwright 의존성이 없어 독립 Playwright 스크립트가 `ERR_MODULE_NOT_FOUND: playwright`로 실패하고, Chrome headless/CDP는 관리형 셸의 프로세스 권한과 페이지 타깃 시작에 좌우됩니다. 반면 Codex의 열린 인앱 브라우저는 Browser 플러그인의 `browser-client`로 연결·조작·실측이 확인되었습니다.  인앱의 네이티브 window.confirm 뒤에는 CDP 입력·포커스 명령이 시간 초과되고 getJsDialog()도 undefined일 수 있습니다. | 사용자가 열어 둔 로컬 화면 검증은 인앱 브라우저 탭을 연결해 새로고침하고, 내장 Playwright API로 DOM·치수·화면을 한 세션에서 확인합니다. 독립 Playwright나 Chrome 프로세스를 관성적으로 재호출하지 않습니다.  검증용 게임 재시작은 확인 창이 없는 홈의 새 게임 흐름을 사용합니다. 확인 창 뒤 입력·포커스가 함께 막히면 재연결·닫기를 반복하지 않고 API/클라이언트 테스트로 전환하며 미확인 범위를 구분합니다. | 인앱 브라우저 연결 자체가 실패하거나 사용자가 Chrome/독립 실행 환경을 명시할 때  네이티브 확인 창이 getJsDialog()에 노출되거나 막힌 탭이 실제로 닫혀 초기 화면에서 다시 시작할 수 있을 때 |
| 모바일 기준 해상도 | 사용자는 이 게임을 모바일 중심으로 설계하며 갤럭시 S24 울트라 기준의 `384 × 824` CSS 픽셀을 기본 화면 크기로 지정했습니다. | 별도 해상도 요청이 없으면 UI 구현과 인앱 브라우저 검증을 `384 × 824` 뷰포트에서 우선 수행하고, 더 좁은 화면에서도 가로 넘침이 없는지 함께 고려합니다. | 사용자가 새로운 기준 기기나 해상도를 지정할 때 |
| 장면 그래픽 방향 | 기존 거처는 생활형 16비트 픽셀 디오라마 방향이며, 사용자는 숲 장소 이미지를 《디스 워 오브 마인》 분위기의 연필 스케치·목탄 그림으로 교체하기로 확정했습니다. | 후속 장소 이미지 교체 시 `assets/scenes/forest-pencil-charcoal.png`를 새 화풍의 기준으로 참고합니다. 기존 거처의 픽셀 애니메이션은 별도 변경 요청 범위에 따라 판단합니다. | 사용자가 다른 화풍을 선택하거나 장소별 스타일을 따로 지정할 때 |
| 로컬 Gemini 연결 | 서버는 시작할 때만 `.env`와 `.env.local`을 읽으므로 실행 후 키를 추가·변경하면 기존 프로세스에는 반영되지 않습니다. 또한 관리형 기본 샌드박스에서 띄운 Node 서버의 외부 `fetch`는 `cause.code: EACCES`로 차단될 수 있지만, 동일 설정을 네트워크 권한으로 실행하면 Gemini 모델 조회와 생성이 정상 동작합니다. | `.env` 변경 시 3000번 포트의 기존 서버를 재시작하고, 기본 실행의 Gemini 테스트가 `fetch failed`이면 Node 단발 연결의 `cause.code`를 확인합니다. `EACCES`일 때만 서버를 네트워크 권한이 있는 숨김 프로세스로 다시 띄운 뒤 `/api/gemini/test` 실제 생성 성공으로 판정합니다. | 서버가 `.env`를 런타임에 다시 읽도록 바뀌거나 관리형 기본 샌드박스에 외부 네트워크 권한이 제공될 때 |
| 로컬 서버 재시작 | 관리형 PowerShell의 `Start-Process`는 `Path`/`PATH` 중복, `Stop-Process`는 NullReference 오류 또는 종료 지연이 발생할 수 있습니다. | 새 빌드를 만든 뒤 정확한 3000번 리스너 PID와 실행 명령을 확인합니다. `Stop-Process`가 실패하면 해당 PID가 여전히 Node 리스너인지 확인한 뒤 `.NET Process.Kill()`과 `WaitForExit()`를 사용합니다. 포트 해제 후 Node `child_process.spawn`의 `detached: true`, `windowsHide: true`와 `.runtime` 로그로 같은 서버를 다시 실행하고, 실제 API 응답으로 확인합니다. | PowerShell의 해당 오류가 해소되거나 서버가 `tsx watch`처럼 자동 재시작 방식으로 실행될 때 |
| 신규 지역 발견 상태 | 위치를 레지스트리와 이웃 링크에만 추가하면 기존 저장에서는 `known_<locationId>`가 없어 지도에서 숨겨질 수 있습니다. | 새 고정 지역을 추가할 때 `normalizeExplorationKnowledge`의 발견 조건과 기존 저장에서 이를 다시 계산하는 경로를 함께 확인합니다. | 지도 노출이 발견 플래그를 사용하지 않도록 구조가 바뀔 때 |
| 선택 직후 독백 | 사용자는 미리 작성한 행동 서사가 결과 장면과 맞지 않아 탐색과 NPC 대화에서 제거하고, 계산대의 “돈이 좀 있을래나.”처럼 상황을 짚는 짧은 속말을 원합니다. | 탐색의 독백은 기존 결과 요청에서 다음 선택지와 함께 생성하고 클릭 즉시 서사 영역에 타이핑합니다. 선택지 안에는 독백을 넣지 않습니다. 숨은 물건·수량·성공·행동 완료를 단정하지 않으며, 결과 본문에는 실제 행동부터 쓰고 속말은 반복하지 않습니다. 추가 요청이나 미래 행동 결과의 사전 생성은 하지 않습니다. 구버전 NPC 선행 문단은 대화 기억의 사실 문맥에도 넣지 않습니다. | 사용자가 독백 위치나 선행 서사 방식을 다시 지정할 때 |
| 선택지 UI | 사용자는 대피소 시안을 확인한 뒤 표형 선택지의 공통 적용을 승인했습니다. 서사와 같은 배경, 행 사이 간격 없음, 얇은 구분선, 왼쪽 선택 문구·오른쪽 효과 설명을 선호합니다. | 모든 일반 게임 선택지에 공통 스타일을 사용하고 긴 문구·설명은 잘리지 않게 줄바꿈합니다. 탐색의 기본 선택지에는 방 상태 재정리나 기존 이동 메뉴와 중복되는 일반 지역 이동·귀환을 넣지 않고, 가능한 행동이 적으면 반복 행동으로 개수를 채우지 않습니다. 새 디자인 방향을 시험할 때는 한 화면에서 먼저 비교합니다. | 사용자가 다른 디자인을 요청할 때 |
| 장소 내 서사 연속성 | 사용자는 탐색의 선행 행동 서사와 결과의 어긋남을 없애고 대기를 자연스럽게 만들길 원합니다. | 선택 직후 서사 영역에 짧은 속말을 추가하고 그때 한 번만 넘깁니다. 중복 입력 잠금을 지키며, 결과는 속말 아래 같은 페이지에 이어 붙이고 다시 넘기지 않습니다. 선택지 채움 연출은 1초로 하되, LLM 응답이 먼저 준비되면 연출이 끝날 때까지 일부러 지연하지 않습니다. 선택지 대기 표시는 왼쪽에서 오른쪽으로 한 번 차오른 뒤 유지하고, 반복 쓸기·점멸 효과를 넣지 않습니다. 타이핑 건너뛰기에는 다시 스크롤하지 않습니다. 이전 문단 읽기와 숨긴 스크롤 막대는 유지합니다. | 사용자가 대기 중 본문 이동이나 장면 연결 방식을 새로 지정할 때 |
