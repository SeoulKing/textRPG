# Project Lessons

다음 작업의 도구 선택을 바꾸는 항목만 유지합니다.

| 범위 | 관찰 또는 실패 지문 | 다음 결정 | 재검토 조건 |
| --- | --- | --- | --- |
| 선택지 개수 | 사용자는 한 장면에 선택지가 길게 늘어나는 구성을 부담스럽게 느끼며, 일반적으로 3개를 선호합니다. | 장면의 핵심 선택지는 3개를 목표로 하고, 아이템·도구 등 상황별 추가 선택지를 포함해도 총 5개를 넘기지 않습니다. 웹 게임의 일반·퀘스트·제작·던전 선택지는 모두 카드 배경·둥근 외곽선·그림자 없이 얇은 구분선으로 나눕니다. 선택 가능·강조 상태도 카드 형태로 되돌리지 않습니다. Unity 게임 UI는 둥근 바깥 카드·서사 말풍선 없이 평평한 상태줄, 그림 아래 서사, 구분선 선택지로 구성합니다. 미리보기 수정 시 로컬 Unity 소스·빌드 스크립트·WebGL 산출물을 함께 맞춰 재빌드로 이전 디자인이 돌아오지 않게 합니다. | 사용자가 특정 메뉴나 장면에 더 많은 선택지가 필요하다고 명시할 때 |
| Content Studio runtime source | Published Studio data can come from the configured database and differ from the tracked `content/content-studio.json` seed. | Test Studio synchronization with an injected or loaded published registry; do not treat the local seed as evidence of the live value. | Reconsider when deployment no longer uses `PostgresContentStudioStore` or published data is exported back into the tracked seed. |
| 사용자 선호 | 실패한 방법을 반복하면 토큰과 시간이 낭비됩니다. | 같은 실패 지문은 전제 조건 변화 없이 재시도하지 않고, 필요한 최소 검증만 수행합니다. | 사용자가 더 강한 검증이나 재시도를 명시적으로 요청할 때 |
| 재고 노드 설계 | 사용자는 내용물이 비어도 남는 보관함과, 모두 수집하면 장소·진입 선택지가 사라지는 더미를 서로 다른 종류로 봅니다. | 보관함은 `depletionBehavior: "remain"`을 유지하고, 소진 시 사라질 더미에만 `"disappear"`를 지정합니다. | 사용자가 재생성·리필되는 세 번째 재고 노드 유형을 요구할 때 |
| 시스템 노트 표기 | 시스템 노트는 아이템·시간·장소·능력치·퀘스트 등 실제 상태 변화만 보여줍니다. 변화가 없는 선택지 이름이나 메뉴 이탈 문구를 대체 문구로 표시하지 않습니다. 아이템 칩은 `systemNoteEntries`의 `item` delta와 `+수량 아이템명` 순서를 사용합니다. | 시스템 노트는 이전 상태와 다음 상태의 차이에서 생성하고, 변화가 없으면 비웁니다. 보상은 중앙 포매터를 통해 `+1 캔 음식 / +1 진통제`처럼 표시합니다. | 사용자가 시스템 노트의 표시 대상이나 표기 규칙을 변경할 때 |
| NPC 선택 후 서사 | 사용자는 두 문단을 `첫 문단=행동`, `둘째 문단=배경`처럼 고정하면 단조롭게 느낍니다. | 두 문단 모두 플레이어의 말·행동·시선·거리·사물·소리를 장면에 맞게 섞고 선택지마다 순서와 호흡을 바꿉니다. 단, NPC의 새 반응은 다음 `npc_reply` 역할에 남깁니다. | 사용자가 대화 서사의 문단 수나 역할 분담을 다시 지정할 때 |
| Git 게시 | 사용자는 이 저장소에서 GitHub CLI 대신 기존 Git HTTPS 인증으로 현재 브랜치에 직접 커밋·푸시하는 방식을 선호하며, 이 경로는 정상 동작합니다. | 푸시 요청 시 실제 프로젝트 변경만 명시적으로 스테이징하고 `.codex-local-server.*.log` 같은 런타임 로그는 제외한 뒤 `git commit` 및 `git push -u origin <현재 브랜치>`를 사용합니다. PR은 명시 요청 때만 생성합니다. | HTTPS Git 인증이 실패하거나 사용자가 PR 생성을 명시적으로 요청할 때 |
| 로컬 콘텐츠 검증 | 일반 셸에서는 `npm.cmd`가 PATH에 없고, 번들 `pnpm.cmd`는 번들 Node 경로를 PATH에 추가해야 실행됩니다. `tsx`가 `uv_os_get_passwd returned ENOMEM`으로 중단되어도 번들 Node로 `tsc` 컴파일 후 생성된 `game/data/registry.js`의 `validateContent()`를 직접 호출하는 경로는 정상 동작합니다. | `tsx`의 같은 `ENOMEM`을 반복하지 않고, `.tmp-validate` 아래로 컴파일해 콘텐츠 검증과 필요한 로직 스모크 테스트를 실행합니다. | 셸 PATH가 정상화되거나 새 런타임에서 메모리 오류 없이 `tsx`가 실행될 때 |
| 브라우저 검증 | 현재 `package.json`에는 Playwright 의존성이 없어 독립 Playwright 스크립트가 `ERR_MODULE_NOT_FOUND: playwright`로 실패하고, Chrome headless/CDP는 관리형 셸의 프로세스 권한과 페이지 타깃 시작에 좌우됩니다. 반면 Codex의 열린 인앱 브라우저는 Browser 플러그인의 `browser-client`로 연결·조작·실측이 확인되었습니다. | 테스트 실행은 사용자가 직접 합니다. 명시적 요청이 없으면 사용자의 열린 탭을 조작하거나 새로고침하지 않습니다. 기술적으로 브라우저 확인이 필요해 사용자가 요청한 경우에만 한 세션에서 확인하며 독립 Playwright나 Chrome 프로세스를 관성적으로 재호출하지 않습니다. | 인앱 브라우저 연결 자체가 실패하거나 사용자가 Chrome/독립 실행 환경을 명시할 때 |
| 로컬 Gemini 연결 | 서버는 시작할 때만 `.env`와 `.env.local`을 읽으므로 실행 후 키를 추가·변경하면 기존 프로세스에는 반영되지 않습니다. 또한 관리형 기본 샌드박스에서 띄운 Node 서버의 외부 `fetch`는 `cause.code: EACCES`로 차단될 수 있지만, 동일 설정을 네트워크 권한으로 실행하면 Gemini 모델 조회와 생성이 정상 동작합니다. | `.env` 변경 시 3000번 포트의 기존 서버를 재시작하고, 기본 실행의 Gemini 테스트가 `fetch failed`이면 Node 단발 연결의 `cause.code`를 확인합니다. `EACCES`일 때만 서버를 네트워크 권한이 있는 숨김 프로세스로 다시 띄운 뒤 `/api/gemini/test` 실제 생성 성공으로 판정합니다. | 서버가 `.env`를 런타임에 다시 읽도록 바뀌거나 관리형 기본 샌드박스에 외부 네트워크 권한이 제공될 때 |
| 로컬 서버 재시작 | 관리형 PowerShell에서는 `Start-Process`가 `Path`/`PATH` 중복으로 실패할 수 있고, 권한을 올린 `Stop-Process`는 실제 종료보다 먼저 반환될 수 있습니다. | 새 빌드를 먼저 만든 뒤 정확한 3000번 리스너 PID만 종료하고, `netstat`으로 포트가 빈 것을 확인합니다. `Start-Process`가 같은 오류로 막히면 `cmd start "" /B`로 번들 Node와 로그 리디렉션을 실행하고, 반환값 대신 새 리스너 PID와 브라우저 상태 동기화로 성공을 판정합니다. | PowerShell 환경변수 중복이 해소되거나 서버가 `tsx watch`처럼 자동 재시작 방식으로 실행될 때 |
| Unity 웹 빌드 | 6000.0.26f1 에디터는 수동 설치되어 Hub의 `install-modules`가 `No modules found for this editor`로 실패하고, 공식 WebGL 설치 파일은 Windows 관리자 확인이 필요합니다. 기본 샌드박스의 Unity 배치 실행은 라이선스 IPC 연결에 실패할 수 있지만, 네트워크 권한이 있는 실행에서는 6000.6.3f1의 WebGL 빌드가 성공했습니다. | 관리자 확인이 불가능하면 WebGL 모듈이 있는 에디터로 프로젝트 복사본을 빌드해 원본 버전을 유지합니다. Unity 배치 빌드는 `Start-Process -Wait -PassThru -WindowStyle Hidden`으로 완료 코드와 산출물을 확인합니다. | 6000.0.26f1에 WebGL 모듈이 설치되거나 기본 샌드박스의 Unity 라이선스 IPC가 정상화될 때 |
| Windows 재분석 경로 쓰기 | 이 작업 공간의 지역 데이터와 테스트 경로는 기본 apply_patch에서 path contains a reparse point로 막혔습니다. | 파일 경로와 치환 기준을 확인한 뒤 승인된 PowerShell ReadAllText/WriteAllText로 수정합니다. 같은 기본 쓰기 실패는 반복하지 않습니다. | 작업 공간의 경로 구성이나 샌드박스 정책이 바뀔 때 |
| 테스트 분담 선호 | 사용자는 앞으로 테스트를 직접 진행하겠다고 했습니다. | 별도 요청이 없으면 테스트를 실행하지 않고, 작업 완료 후 직접 확인할 행동과 기대 결과를 짧은 체크리스트로 알려줍니다. | 사용자가 특정 테스트 실행을 명시적으로 요청할 때 |
| 던전 UI 정보 전달 | 사용자는 던전런의 밋밋함을 정보 전달 부족과 연결해 지적했습니다. | 현재 단계·적의 예고·대응 스킬·실제 결과를 먼저 보여주고, 선택 효과는 현재 수치와 선택 후 수치로 비교합니다. 별빛 회랑의 전투 기록과 전리품 세부 정보는 주요 행동 아래에 둡니다. 아르카나 평원 전투는 적 일러스트·이름·체력·공격 예고를 하나의 카드로 묶고, 본문에 장소명·플레이어 능력치·성장 정보·최근 전투 기록을 중복 표시하지 않습니다. 상황 설명과 전투 결과 문장은 적 카드 아래의 본문 서사 영역에 둡니다. 아르카나에서는 상단과 상태의 기력바를 경험치바로 바꾸고, 상태에 마력(마법 공격력)을 별도 수치로 표시하며 성장 요약 문구는 두지 않습니다. | 사용자가 서사 중심이나 다른 전투 화면 구성을 명시할 때 |

| 지도 일러스트 선호 | 사용자는 사람 없는 쿼터뷰 지도와, 육각형 안에 글자 대신 대표 건물을 넣은 통일된 월드맵을 선호합니다. | 현실과 마법세계는 같은 육각 좌표와 목적지 선택·이동 방식을 공유합니다. 아르카나 도심은 중앙 분수와 주변 여섯 칸을 하나의 통합 일러스트로 만들고 내부 육각 경계는 숨깁니다. 건물·길·바닥을 같은 그림에서 제작해 시점과 축척을 맞추며, 장소별 투명 선택 영역은 유지합니다. 사냥터는 남문 바깥에 둡니다. 도심 밖의 개별 객체는 투명 배경과 공통 지면을 사용하고, 바닥은 건물 축척에 맞춥니다. 객체 전체를 타일 안에 맞춰 자르지 않으며 사람·글자는 넣지 않습니다. 현재 위치는 점 대신 금색 테두리로 표시합니다. 선택한 목적지는 파란색 테두리와 목록의 선택 표식으로 구분합니다. | 사용자가 지도 형태·글자·투영·위치 표기·군중 표현을 다시 지정할 때 |
| 아르카나 전투 시간 표시 | 사용자는 적 공격 예고와 파이어볼·회피 쿨타임을 숫자 카운트다운보다 줄어드는 바로 보는 것을 선호합니다. | 바의 왼쪽을 고정하고 오른쪽 끝이 왼쪽으로 줄게 하며, 서버의 남은 시간과 일시정지를 따릅니다. 파이어볼·회피 쿨타임은 선택지 전체의 약간 진한 배경으로 표시합니다. 선택지 공통 자식 위치·레이어 규칙보다 구체적인 선택자를 사용하고 비활성 투명도로 바가 흐려지지 않게 합니다. 플레이어·적 체력 모두 빨간 현재 HP와 지연 감소하는 주황색 피해 잔상으로 구분합니다. 적 예고 문구는 3초 전부터 ‘도약 준비 중’, 1초 전부터 ‘도약 임박’만 표시하고 그전에는 비웁니다. 보라색 공격 예고 바도 3초 전부터만 표시하고, 3초 구간을 100%로 삼아 도약 순간까지 줄입니다. 회피 준비 안내는 붙이지 않습니다. 스킬 연출은 무음으로 만들고 명중 순간에 피격 모습·피해 숫자·체력 감소를 맞춥니다. | 사용자가 시간·피해 표시 방식을 다시 지정할 때 |
