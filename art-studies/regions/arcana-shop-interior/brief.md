현재 적용: **native-2d / v3 승인안** — 기본 TileMapLayer로 편집하는14×9 순수2D 상점입니다. 활성 원본과 확인 근거는 문서 하단의 제작·연결 완료 항목을 따릅니다.

## 요청과 현재 단계
- 지역 ID: arcana-shop-interior / 기존 장소 ID: `arcana_shop`.
- 요청: 승인된 상점 내부를 독립 2D 자산으로 제작하고 상인·구매·판매·수량 선택을 연결합니다. 마나 포션 썸네일을 추가합니다.
- 승인: 2026-10-29 사용자 “ㅇㅇ 이거 딱 좋다 만들어줘”. `concept-v1.png`의 내부·상인 구성을 제작 기준으로 고정했습니다.
- 현재 단계: v3 승인 기준의 순수2D 상점 제작·연결·범위별 검사 완료.
- 다음 행동: Godot의 shop_2d.tscn에서 배치를 편집하거나 main.tscn으로 상점 이동·거래 화면을 확인합니다.

- 활성 장면: `godot-arcana/scenes/shop_2d.tscn`. Node2D 루트·TileMapLayer5개·Sprite2D·Camera2D를 사용합니다. 상점 진입 중 월드 SubViewport의3D 렌더링을 끄고, 퇴장 시 기존 실외 표시기를 복원합니다.
- 실제 타일/가구30개와 TileSet 라이브러리를 제작했습니다. 벽 상단·좌우 반환부·앞벽·문턱은 연속된 경계이며, 가구는64px/월드 단위의 같은 투영에서 제작한 독립 자산입니다. 수납 선반/작은 진열대의 점유 깊이는0.5로 정리하고 실제 윗면도23px로 맞췄습니다. 카운터/작업대 깊이1은45px입니다.
- 공통 원본: 칠한 TileMap 셀 → 표시·가구 점유·충돌·상인/거래 위치·도착/퇴장 위치·바닥 도메인 → 서버 내보내기. 지운 바닥은 통행할 수 없으며 서버도 같은 연속 좌표 판정을 사용합니다.
- 편집·재출력: [PixelPen 원본과 작업 안내](../../../godot-arcana/art/source/shop-2d-v3/README.md). 루트 선택은 투영 미리보기, TileMapLayer 선택은 기본 격자 편집입니다. 수동 원본과 칠한 셀을 보존합니다.
- 가구 재질 원화: [furniture-paint.png](source/native-2d/furniture-paint.png), [프롬프트](source/native-2d/furniture-paint.prompt.txt). 원화는 재질 참조로 사용하며 원본을 통째로 축소하지 않고 각 가구의 수치상 윗면/앞면과 외곽을 고정한 뒤 PixelPen에서 마감했습니다.
- 실제 검사: 기하/수직선/연결/타일 삭제/카운터 이동/동선1289항목, 실제 World/Renderer 흐름11항목, Godot과 서버의 통행 판정3525지점 일치. 자산30개의 크기·이진 알파·팔레트·PixelPen 원본도 확인했습니다. TypeScript 타입 검사와 실제 서버 컴파일 경로를 확인했습니다.
- GPU 정지 렌더: [전체](source/native-2d/shop-2d-overview.png), [세로](source/native-2d/shop-2d-portrait.png), [근접](source/native-2d/shop-2d-close.png). 상점 자체에는3D 노드가 없습니다.
- 확인 범위: 격리된 원본 사본에서 실제 Godot 장면과 이동·표시 경로를 실행했습니다. 실제 API 거래/저장·브라우저 플레이·웹 내보내기·배포는 수행하지 않았습니다.
- 사용자가 직접 확인할 행동: main.tscn 실행 → 상점 진입 → 이동/카운터 클릭/기존 거래 창 열기 → 출구로 복귀. 웹은 별도 내보내기가 필요하고, 온라인 배치 데이터 변경은 서버 재시작 시 적용됩니다.

상점의 온라인 체크포인트가 새 장애물 안에 있으면 도착점으로 보정하며 정상 저장 위치는 보존합니다. 실제 서버 컴파일 산출물로 이 복원 경로와 통행 판정을 확인했습니다. 벽의 앞뒤 겹침 경계는 한 스트립만 픽셀을 소유해 반투명 때 이중으로 진해지지 않게 했으며, 상점에서는 실외용3D/쿼터뷰 비교 메뉴를 숨깁니다.
