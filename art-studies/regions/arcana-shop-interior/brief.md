## 요청과 현재 단계
- 지역 ID: arcana-shop-interior / 기존 장소 ID: `arcana_shop`.
- 요청: 승인된 상점 내부를 독립 2D 자산으로 제작하고 상인·구매·판매·수량 선택을 연결합니다. 마나 포션 썸네일을 추가합니다.
- 승인: 2026-10-29 사용자 “ㅇㅇ 이거 딱 좋다 만들어줘”. `concept-v1.png`의 내부·상인 구성을 제작 기준으로 고정했습니다.
- 현재 단계: 자산 제작·출입·거래 연결 완료, 사용자 플레이 확인 대기.
- 다음 행동: 게임에서 상점 진입 → 계산대 앞 상인과 상호작용 → 구매/판매 → 수량과 합계 확인 → 소지품 및 소지금 확인 → 출구로 광장 복귀.

- 확인한 기준: `godot-arcana/art/export/reference/shop-2d.png`, `godot-arcana/art/source/plaza-guide/approved-standard-proportions-4x.png`.

- 원본·프롬프트: `source/`. 계산대는 첫 시트가 인물보다 높아 별도 `counter-master.png`로 다시 제작했습니다.
- 제작: `node scripts/build-shop-interior-art.cjs`. 수동 보정 시 현재 출력·원본을 먼저 보존하며 이 명령을 무조건 재실행하지 않습니다.

- 도트 기준: 가구·상인 모두 64 원본 픽셀/월드 단위, 최근접 표시·이진 알파·기존 공통 팔레트. 독립 가구에는 크기 확대 Transform을 사용하지 않습니다.
- 상인: 96×136, 발 (48,116), 실제 인물 높이 99px. `merchant-proportions-4x.png`는 기존 두 인물과 같은 배율의 비교입니다.
- 포션 썸네일: `godot-arcana/art/export/items/mana-potion.png`, 64×64·사방 최소 8px 여백. 월드 자산과 다른 UI 캔버스이며 거래 목록·소지품·포션 퀵슬롯에 연결했습니다.
- 가구 원본 픽셀/발/자르기 영역은 manifest에서 관리합니다. 벽·바닥·보라색 러그·화분·등불은 여관의 기존 독립 자산을 재사용합니다.

- 전용 표시·충돌 기준: `godot-arcana/scripts/shop_interior.gd`.
- 기존 연결: `world.gd`의 `change_interior`, `pixel3d_world.gd`의 `_interior`, `main.gd`의 상인 상호작용.
- 입구/출구: 논리 좌표 (192,256), 입장 위치 (192,232). 광장 상점 문·outside_position·저장 장소 ID는 기존 경로를 유지합니다.
- 상인 상호작용: (192,160). 계산대·상인·진열장·전시대·화분의 바닥 점유와 방 경계에 충돌을 등록하고 중앙 진입 통로를 비웠습니다.
- 상인은 고정 남향 2D 인물이며 신규 애니메이션은 이번 범위에 포함하지 않습니다.

## 매매 규칙
- 서버 원본: `src/game/arcana-shop.ts`. 기존 `arcana_combat` 행동 흐름으로 구매·판매를 저장합니다.
- 마나 포션: 구매 100원 / 판매 40원, MP20 회복 기능 유지.
- 달빛 약초: 구매 30원 / 판매 10원.
- 비전 가루: 구매 60원 / 판매 20원.
- 마력 결정 파편: 판매 80원, 매입 전용.
- 재료의 기존 아이템 ID와 저장 인벤토리를 사용합니다. 위 목록 밖의 퀘스트·장비·현실 물품은 매입하지 않습니다.
- 거래당 1~99개, 상점 판매 재고는 상시 판매입니다. 유한 재고·날짜별 입고는 구현 범위에 포함하지 않습니다.
- 서버가 장소·전투·거래 품목·수량·소지금·보유 수량을 검증하고 소지금과 인벤토리를 함께 저장합니다.
- 구매가보다 낮은 매입가를 사용하며 마지막 물품 판매 시 수량 0의 인벤토리 키를 제거합니다.
- 기존 클라이언트용 `buy_potion` 행동은 유지합니다.

## 확인과 미확인
- 서버 TypeScript 컴파일 통과: `node node_modules/typescript/bin/tsc --outDir .server-dist --rootDir src`.
- Godot 4.5.1의 임시 런타임 사본에서 가져오기·Web 내보내기를 수행합니다. 원본 편집기 플러그인과 열린 게임은 종료하지 않습니다.
- 실제 게임 렌더러 정지 출력: `shop-overview.png`, `merchant-counter.png`. 플레이·거래 요청을 실행한 증거와 구별합니다.
- 브라우저·자동 플레이·거래 테스트는 사용자 선호에 따라 실행하지 않았습니다.
- 최종 미술 및 실제 매매·출입 확인은 사용자 확인 대기입니다.

- 최종 웹 반영: `godot-web/`와 `.server-dist/godot/`의 raw/gzip PCK 내용 일치. SHA256 `F0876FA59B59CA3BA324BB296E8F91D7B3ABEBA49EB9FD49735BBA4E0C482B82`.
- 이전 웹 파일은 `.runtime/godot/shop-build-20261029-141834/previous-web/`에 보존했습니다. 실행 중 서버의 프로세스 재시작과 실제 HTTP 제공 확인은 수행하지 않았습니다.
