# 긴 휴식과 읽기 연속성

## 플레이 흐름

임시 거처에 ‘저녁까지 쉰다’를 추가했다. 06:00부터 18:00 전까지 고를 수 있으며, 기존 15분 휴식·취침·제작·요리는 유지한다. 선택 직후 이전 본문과 선택한 줄을 남기고 ‘지금은 몸을 좀 쉬게 해 두자.’를 표시한다. 기존 500ms 대기와 입력 잠금도 적용한다.

긴 휴식은 시간을 실제로 진행시킨다. 완료된 15분 구간마다 체력과 정신력을 1씩 회복하며, 남은 5분 같은 미완료 구간에는 회복을 지급하지 않는다. 기력 소모, 부상·감염, 탈진, 다른 장소의 광원과 채집지 회복은 같은 세계 시간을 사용한다.

시작할 때 기력이 남아 있었다면 0이 되는 순간 멈춘다. 부상·감염·탈진의 단계가 증가하거나 체력이 3 이하로 떨어져도 멈춘다. 이미 체력 3 이하 또는 상태 이상 Lv3 이상인 상태에서는 긴 휴식을 시작할 수 없다. 짧은 휴식·아이템·치료 등 다음 결정을 플레이어가 내린다. 기력 0에서 다시 시작할 때는 추가 악화까지 진행할 수 있다는 안내를 표시한다.

중단되면 실제 쉰 시간과 원인만 서술한다. 저녁에 도달하지 않았는데 저녁이 되었다고 쓰지 않는다. 결과는 두 문단의 기본 서사이며 이를 위한 Gemini 요청은 없다.

## 엔진과 콘텐츠 계약

`activity.kind: rest`는 제작과 같은 실행 결과·저장·중복 방지 계약을 사용한다. 시간과 회복은 데이터에 선언하며 특정 행동 ID로 분기하지 않는다.

```json
{
  "kind": "rest",
  "startsAtHour": 6,
  "untilHour": 18,
  "recovery": { "intervalMinutes": 15, "hp": 1, "mind": 1 }
}
```

시작·종료 시각은 같은 달력 날짜 안의 구간이다. 휴식 정의의 효과 목록에는 완료 로그만 허용해 별도 시간 효과나 보상이 중복 실행되지 않도록 한다. `lastActivity`에는 예정 시간, 실제 시간, 완료/중단, 이유, 문단과 생성 시각을 남긴다. 외부 선택에 붙은 `activityRevision`으로 동일 요청의 중복 실행을 거부한다. 레시피 상세 팝업을 거치지 않고 바로 고르는 행동이다.

기존 레지스트리와 Studio 문서에는 빠진 기본 휴식 행동을 보완한다. 같은 ID의 사용자 정의와 명시적 null은 보존한다. 새 결과 필드는 선택 사항이라 기존 제작 기록과 저장을 읽을 수 있다.

결과 문단은 조회할 때 다시 생성하지 않는다. 음식을 먹는 것처럼 같은 장면에서 상태만 바꾸는 행동은 읽던 문단에 결과 칩만 이어 붙인다. 장소 이동, 제작 메뉴, 대화처럼 새로운 장면으로 넘어가면 이전 휴식 문단을 현재 장면으로 다시 제시하지 않는다.

## 검증

- 긴 휴식 테스트 7건: 실제 경과·미완료 구간, 기력 소진, 감염·탈진 악화, 체력 임계점, 임의 지역·행동 ID, 기존 저장/Studio, 서비스 중복 요청·재조회·음식 사용·장면 전환.
- 기존 작업 테스트 11건과 클라이언트의 대기·실패·선택 갱신 테스트 6건 통과. TypeScript 빌드와 JavaScript 구문 검사 완료.
- 실제 선택 목록으로 진행하는 10일 경로 3건 통과. 식사 없이 버티는 경로는 여전히 탈진으로 실패한다.
- 빈손 낚시 경로는 전체 선택 428→189회, 풍어 경로는 505→330회로 줄었다. 두 성공 경로 모두 15분 휴식 반복은 0회이며, 긴 휴식은 각각 17회·24회 사용했다.

384×824의 격리 브라우저에서 본문 유지·독백·입력 잠금·5분 뒤 기력 소진으로 인한 중단을 확인했다. 음식 사용 후 같은 방 소개가 다시 붙는 문제를 발견해 수정했고, 서비스 회귀 테스트로 문단과 장면 ID가 유지됨을 확인했다. 수정 후 브라우저 재확인은 테스트용 새 게임의 네이티브 확인 창에서 인앱 자동화가 멈춰 완료하지 못했다. 실제 Gemini나 사용자 저장은 사용하지 않았다.
