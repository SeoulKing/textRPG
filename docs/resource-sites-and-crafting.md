# 채집지 상태와 제작 준비 안내

지역의 `resourceSites`와 행동의 `resourceUse`를 조합한다. 엔진은 특정 지역·행동 이름을 분기하지 않으므로 새 채집지에도 같은 검증·저장·표시를 사용한다.

## 현재 콘텐츠

숲의 쓰러진 나무·질긴 덩굴·잔해·덤불과 강의 낚시 자리는 `unlimited: true`로 반복 작업한다. 횟수 제한, 낚시 회복 대기, 남은 횟수 표시는 없다. 기존 저장에서 소진했던 자리도 바로 이용할 수 있다.

맨손과 손도끼의 목재 3개/5개 수확, 작업 시간, 기력, 도구 내구도와 확률형 수색의 실패 가능성은 유지한다. 보관함과 강가의 가지 더미는 별도 `stockNodes`의 유한 재고이며, 수집 후 자동으로 채우지 않는다.

## 입장 직후 주요 작업

숲 벌목(맨손·손도끼)과 강 낚시에는 `resourceUse.directFromEntry`를 지정한다. 현재 구역에서 보이는 작업 대상이면 접근·관찰을 따로 선택하기 전에 작업 의도를 제공하고, 탐색 상태의 첫 작업 슬롯에 배치한다. 다른 구역의 숨은 대상이나 도구 조건을 충족하지 못한 작업은 노출하지 않는다. 명시적인 `false`는 기존 관찰 조건을 유지한다.

작업을 누르면 실제 접근·자세 변경·필요한 관찰부터 처리한 뒤 작업 비용·결과를 적용한다. 준비 도중 실패하거나 숨은 물건이 드러나면 작업 전에 멈추고, 수행한 준비와 발견만 서술한다. 접근 시간도 계산하며 서술 요청은 의도당 한 번이다. 수집 더미의 발견과 획득은 계속 별도 선택으로 남는다.

## 규칙과 저장

- 무제한 채집지는 저장된 잔량을 작업 조건으로 사용하거나 차감하지 않는다. API 선택지와 서술의 관찰 정보에도 남은 횟수·회복 시간을 보내지 않는다.
- 제한을 명시한 사용자 정의 채집지는 기존 용량·비용·회복 계산을 사용할 수 있다. 이때 조회는 순수 계산이며 폴링이나 실제 네트워크 대기는 재고와 게임 시간을 변경하지 않는다. 가득 찬 상태의 초과 회복 시간은 저축하지 않는다.
- 행동 조건을 먼저 검사한 뒤 실제 효과를 처리한다. 도구가 없거나 유한 채집지가 소진된 선택은 재료·시간을 쓰지 않는다. 생존 조건으로 중단된 작업에는 중단 이후 보상을 지급하지 않는다.
- 유한 채집지 상태는 `GameState.resourceState[locationId][siteId]`에 저장한다. 과거에 추적하지 않았던 횟수는 추측해 차감하지 않는다.
- 기존 콘텐츠의 누락된 기본 필드만 보완한다. 따라서 옛 숲·강에는 무제한 작업과 주요 행동 표시가 적용된다. 기존 아이템·진행·보관 버전 원본, 편집한 수확량·시간, 명시적인 `unlimited: false`와 `resourceUse: null`은 보존한다.
- 콘텐츠 검증은 잘못된 채집지 참조, 중복 ID, 0 이하 비용, 유한 채집지의 용량을 초과하는 비용을 거부한다.

## 제작을 위한 다음 행동

재료가 부족한 레시피에 ‘준비 방법’을 표시한다. 다녀온 지역에서 현재 확인 가능한 채집 행동, 발견한 보관함의 남은 재고, 알려진 제작 메뉴의 가공 방법을 최대 두 가지씩 보여 준다. 숨은 보관함이나 조건에 막힌 행동·레시피는 안내에 사용하지 않는다.

예를 들어 나무 판자가 부족하면 거처에서 목재를 가공하는 방법을, 끈 묶음이 부족하면 다녀온 숲의 덩굴 채집을 안내한다. 반복 채집지에는 횟수를 붙이지 않고, 유한 재고만 소진·수집 완료·회복 대기로 구분한다. 이 계산에 LLM 호출은 없다.

기존 전용 설명이 없는 새 레시피도 실제 재료 조건과 아이템 생성 효과를 사용해 상세 패널에 표시한다.

## 검증 범위

관련 테스트는 입장 직후 작업, 실제 접근 시간, 수확과 도구 소모, 새 발견 중단, 중복 요청, 기존 소진 저장의 재개, 저장·재방문, 유한 더미의 비재생, 사용자 정의 유한 채집지, 재료 안내와 생존 경로를 확인한다. 실제 Gemini 대신 모의/기본 서사를 사용한다.

관련 테스트 37개, 콘텐츠 검증과 빌드를 통과했다. 384×824 브라우저에서 숲 입장 → 즉시 벌목 → 결과와 반복 선택 유지 → 지도에서 강 이동 → 첫 낚시 선택지를 확인했다. 횟수 표시는 없고 기존 대기 중 속말과 입력 잠금은 유지된다. 가로 넘침과 실제 외부 생성 요청은 없었다.
