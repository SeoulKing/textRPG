# 채집지 상태와 제작 준비 안내

지역의 `resourceSites`와 행동의 `resourceUse`를 조합한다. 엔진은 특정 지역·행동 이름을 분기하지 않으므로 새 채집지의 ID, 용량, 시간 규칙을 콘텐츠에 추가하면 같은 검증·저장·표시를 사용한다.

## 현재 콘텐츠

| 지역 | 채집지 | 시작 작업 횟수 | 회복 |
| --- | --- | ---: | --- |
| 숲 | 쓰러진 나무 | 12 | 없음 |
| 숲 | 질긴 덩굴 | 8 | 없음 |
| 숲 | 숲에 남은 잔해 | 6 | 없음 |
| 숲 | 길가의 덤불 | 8 | 없음 |
| 강 | 낚시 자리 | 4 | 게임 시간 360분마다 1회, 최대 4회 |

한 단위는 아이템 한 개가 아니라 아직 작업할 수 있는 구간·기회다. 맨손과 손도끼는 같은 쓰러진 나무 재고에서 각각 한 번을 쓰되 기존 목재 3개/5개 수확과 도구 내구도 비용을 유지한다. 확률형 수색도 한 구간을 확인하므로 빈손인 경우 작업 횟수가 줄어든다. UI에 빈손 가능성을 표시한다.

폐허 보관함은 기존 `stockNodes`의 유한 재고를 유지하며 자동으로 채우지 않는다. 숲의 용량은 첫 생존 경로를 막지 않는 초기 값으로, 10일 전체 플레이의 밸런스 검증은 아직 남아 있다.

## 규칙과 저장

- `resources.ts`의 조회는 순수 계산이다. 저장한 잔량·회복 진행분·게임 시각에서 현재 값을 구하며 읽기·폴링·실제 네트워크 대기는 재고나 게임 시간을 변경하지 않는다.
- 자리를 떠나도 게임 시간이 지나면 낚시 기회가 회복된다. 가득 찬 상태에서 초과 회복 시간을 저축하지 않는다.
- 행동 조건을 먼저 검사한 뒤 작업 기회를 소비하고 실제 효과를 처리한다. 도구가 없거나 이미 소진된 선택은 재료·시간을 쓰지 않는다. 작업 중 생존 조건으로 중단되면 이미 시작한 구간은 소모되고 중단 이후의 보상은 지급하지 않는다.
- 상태는 `GameState.resourceState[locationId][siteId]`에 저장한다. 기존 저장에 이 필드가 없으면 처음부터 추적한다. 과거에 추적하지 않았던 채집 횟수를 추측해 차감하지 않으며, 새 상태가 생긴 뒤에는 저장·재방문 시 초기화하지 않는다.
- 누락된 콘텐츠 필드만 기본 정의로 보완한다. 편집한 수량·용량·시간·명시적인 `resourceUse: null`은 보존한다. 보관된 콘텐츠 버전 원본을 덮어쓰지 않는다.
- 콘텐츠 검증은 잘못된 채집지 참조, 중복 ID, 용량을 넘거나 0 이하인 비용을 거부한다.

## 제작을 위한 다음 행동

재료가 부족한 레시피에 ‘준비 방법’을 표시한다. 다녀온 지역에서 현재 확인 가능한 채집 행동, 발견한 보관함의 남은 재고, 알려진 제작 메뉴의 가공 방법을 우선순위에 따라 최대 두 가지씩 보여 준다. 아직 열어 보지 않은 보관함과 조건에 막혀 공개되지 않은 행동·레시피의 내용은 안내에 사용하지 않는다.

예: 나무 판자가 부족하면 거처에서 목재를 가공할 수 있음을, 끈 묶음이 부족하면 다녀온 숲의 덩굴 채집을 안내한다. 재고가 없는 곳은 소진·수집 완료·회복 대기 상태로 구분한다. 이 계산에 LLM 호출은 없다.

기존 전용 설명이 없는 새 레시피도 실제 재료 조건과 아이템 생성 효과를 사용해 상세 패널에 표시한다. 따라서 레시피 ID를 서비스의 설명 목록에 추가하지 않아도 필요한 재료와 획득 경로를 볼 수 있다.

## 확인한 증거

- 채집지 7개 테스트: 도구 간 재고 공유, 실패한 수색, 조건 실패, 부재 중 회복, 읽기 불변성, 회복 상한, 임의 ID·비용, 사망 중단, 기존 저장, Studio 수정 보존과 잘못된 참조.
- 재료 안내 3개 테스트: 미방문 지역·숨은 보관함·조건에 막힌 행동과 레시피 비공개, 가공 경로, 소진·회복 상태, 새 레시피의 실제 GameService 표시.
- 기존 목재·요리·저장 12개 테스트와 새 게임의 탐색 → 제작 → 조리 → 섭취 경로 1개 테스트를 함께 확인했다.
- TypeScript 빌드와 클라이언트 구문 검사를 통과했다. 384×824 브라우저에서 마지막 벌목 → 소진 표시 → 거처 이동 → 화로의 부족 재료 안내를 확인했다. 가로 넘침과 콘솔 오류는 없었다.
- 검증은 메모리 저장소와 모의/기본 서사를 사용했다. 실제 사용자 저장이나 Gemini 호출을 사용하지 않았다.
