# 상태 기반 텍스트 월드: 작은 창고

기존 생존 게임의 기능을 보존하면서, LLM 없이 동작하는 두 방의 최소 흐름을 추가했습니다. 홈의 **작은 창고 · 상태 기반 월드**에서 실행합니다. 기존 역무실·지역 탐색 전체를 새 데이터 모델로 이행한 것은 아닙니다.

## 실행

```powershell
npm.cmd run start
```

[작은 창고 열기](http://127.0.0.1:3000/client/state-world.html). 서버가 이미 실행 중이면 새 빌드로 다시 시작해야 합니다. 기존 서버가 선택한 파일 저장소 또는 PostgreSQL 저장소에 별도 게임 세션을 저장합니다. 이 흐름에는 Gemini 설정이나 키가 필요하지 않습니다.

예시 경로: 선반 접근 → 통조림 획득 → 캐비닛 접근 → 열기 시도(잠금 확인) → 바깥 복도 → 열쇠 획득 → 창고 → 캐비닛 접근 → 잠금 해제 → 열기 → 구급약 획득 → 닫기. 다시 선반이나 캐비닛을 확인해도 물건은 돌아오지 않습니다.

행동마다 자동 저장합니다. 브라우저에는 별도 키 `textrpg-state-world-v1`로 게임 ID만 보관하며, 새로고침하면 서버의 확정 상태와 확인 기록을 읽습니다. `새로 시작`은 새 세션을 만들며 기존 생존 게임 저장을 덮어쓰지 않습니다.

## 기존 코드의 재사용과 변경 범위

| 역할 | 파일 | 구현 |
| --- | --- | --- |
| 데이터 경계 | `src/game/state-world/model.ts` | 정의·인스턴스·배치·방·지점·연결·명령·기억·저장 스키마 |
| 세계 | `world.ts` | ID Map, 자식·인접 간선·방별 지점 인덱스, 배치 무결성, 비용 경로 |
| 콘텐츠 | `content.ts` | 두 방, 선반, 캐비닛, 통조림 2개, 열쇠, 구급약 |
| 행동 | `actions.ts` | 재검증, 같은 객체 이동, 시간 비용, 예약 사건 반영 |
| 관측 | `observe.ts` | 밝기·거리·개폐·가림과 현재 관측 및 과거 기억의 분리 |
| 문장 | `render.ts` | 사실 선정, 변화 비교, 재확인, 한국어 템플릿 |
| 선택 | `choices.ts` | 관측 기반 구조화 명령, 4개씩 순환 페이지와 추가 행동 버튼 |
| 저장 | `save.ts` | Map을 배열로 직렬화, 인덱스·선택지 재구성 |
| 연결 | `service.ts`, `src/state-world-routes.ts` | 기존 `GameRepository`, 세션 잠금, 기존 `advanceGameSeconds` |
| 화면 | `client/state-world.html`, `.css`, `.js`, `index.html` | 모바일 텍스트·선택지·소지품·과거 기록·자동 이어하기 |

표에서 경로가 생략된 엔진 파일은 `src/game/state-world/` 아래에 있습니다. 기존 `text-world/world.ts`의 조사 함수를 `src/game/korean.ts`로 옮겨 두 엔진이 공유하며 기존 export도 유지합니다. `GameStateSchema`의 선택적 `stateWorld` 필드와 저장 정규화 분기를 추가했습니다. 기존 게임 API가 새 세션을 생존 게임으로 처리하는 것을 진입점에서 차단합니다.

## 세계와 관측의 계약

- 배치 원본은 `placements` 하나입니다. 인벤토리도 `parentId === player.inventoryId`인 객체를 조회합니다. 수집해도 ID와 수량을 유지하며 새 객체를 복제하지 않습니다.
- `children`, 인접 간선, 방별 지점은 복원 가능한 인덱스입니다. 코어 행동은 현재 방의 객체와 인접 출구에 필요한 경로만 조회합니다. 전역 객체·지점 컬렉션 순회를 차단한 테스트에서도 이동과 수집이 동작합니다.
- 부모는 하나이며 잘못된 참조, 순환, 중복 ID, 음수 수량, 잘못된 개폐 상태를 거절합니다. 부모 객체에 놓인 물건은 부모의 접근 지점을 상속합니다.
- `empty`는 전체가 보이고 양의 수량의 내용물이 없을 때 계산합니다. `closed`, `dark`, `far`, `occluded`, `partial`은 빈 상태와 구분합니다. 닫힌 수납함의 위 표면과 안쪽도 별도로 관측합니다.
- 관측과 렌더러는 세계를 변경하지 않습니다. 행동이 확정된 뒤 관측 → 사실 선정·서술 → 관측/출력 기록 갱신 순서로 처리합니다. 다음 선택지와 소지품은 같은 확정 상태를 읽습니다.
- 확인 시각과 리비전을 기억합니다. 어둡거나 닫힌 내부를 마지막으로 확인한 내용물로 덮어쓰지 않습니다. 보이지 않는 자동 닫힘도 기억을 갱신하지 않습니다. 기록 UI는 항상 **이전 확인 기록**으로 표시합니다.
- `look`, `defocus`, 화면 읽기, 선택지 페이지 이동에는 시간이 들지 않습니다. 관심 해제는 실제 위치를 유지합니다. 이동 간선 비용과 조작 비용만 기존 게임 시계에 반영합니다.
- 예약 사건은 저장된 게임 시각으로 조명 변경·자동 닫힘을 처리합니다. 벽시계 타이머와 외부 호출은 없습니다. 사건이 끝난 상태에서 본문과 선택지를 만듭니다.

## API와 저장

- `POST /api/state-world/games`: 생성 및 최초 관측.
- `GET /api/state-world/games/:gameId?page=0`: 읽기와 선택지 재계산. 상태·시간을 변경하지 않습니다.
- `POST /api/state-world/games/:gameId/actions`: 다음과 같은 명령을 전달합니다.

```json
{
  "requestId": "9a2cf8d2-98f1-4d46-9499-f75b503ab9d1",
  "revision": 0,
  "command": { "type": "approach", "targetId": "shelf_01" }
}
```

지원 명령: `move`, `approach`, `look`, `defocus`, `take`, `open`, `close`, `unlock`. 대상 명령에는 `targetId`가 필요합니다. 자연어 문자열은 받지 않습니다. 오래된 리비전, 관측할 수 없는 대상, 막힌 경로, 중복 획득은 상태와 시간을 변경하지 않습니다. 잠긴 줄 모르고 여는 시도는 정상 행동으로 2초를 쓰고 잠금을 기억합니다.

서버는 프로세스 내 큐와 기존 저장소 잠금을 사용합니다. PostgreSQL에서는 기존 advisory lock을 사용합니다. 같은 요청의 응답을 잃었을 때는 동일한 요청 ID·명령·리비전으로 재조회합니다. 직전 완료 요청은 재실행하지 않으며, 더 오래된 요청은 리비전으로 거절합니다. 저장 실패는 저장소의 원래 세션에 영향을 주지 않습니다. 파일 저장소는 기존과 같이 단일 서버 프로세스를 전제로 합니다.

저장 형식 `version: 1`, 콘텐츠 `contentVersion: storehouse-1`을 사용하며 정의·맵도 스냅샷에 포함합니다. 객체, 배치, 플레이어, 시간, 관측과 출력 기록, 남은 사건, 직전 요청 정보를 보존합니다. 손상되거나 지원하지 않는 버전의 저장을 새 세계로 교체하지 않습니다. 기존 생존 저장은 기존 정규화 경로를 유지하며 새 세계로 자동 변환하지 않습니다.

응답의 `timing.engineMs`는 행동 검증·실행·관측·서술 및 플레이어 화면/선택 계산 시간입니다. `serverMs`는 저장 읽기·복원·게임 시계 연결·직렬화·저장을 포함한 잠금 획득 후 서버 처리 시간입니다. 잠금 대기, HTTP 왕복과 브라우저 렌더링은 별도입니다. 현재 서비스는 요청마다 스냅샷을 복원하고 저장하므로 이 저장 비용은 세계 크기에 비례합니다. 대규모 세계의 성능이나 특정 지연 수치를 보장하지 않습니다.

## 검증

```powershell
npm.cmd run build
node --test tests/state-world.test.cjs
node --check client/state-world.js
```

새 엔진 테스트 **14개 전부 통과**, TypeScript 빌드 및 클라이언트 구문 검사 통과. Node 내장 테스트를 기존 저장소와 동일하게 사용하며 새 테스트 프레임워크를 추가하지 않았습니다. 테스트는 입장·자동 공개·영속 획득·비공개 내부·관측 불가와 빈 상태·위치 유지·잘못된 명령·막힌 경로·중복 요청·기억·파일 저장 복원·JSONB 형태의 키 재정렬·HTTP API·저장 실패를 다룹니다. 서버에서 제공한 선택지만으로 전체 아이템 획득을 실행하며 해당 테스트에서는 `fetch`를 금지합니다.

기존 `tests/text-world.test.cjs`도 실행했습니다. 22개 중 14개 통과, 8개는 과거 `inspect:floor` 또는 `travel:office` 추천 선택을 직접 기대해서 실패했습니다. 변경한 기존 모듈을 Git HEAD 원본으로 대체한 비교 실행에서도 같은 8개가 같은 선택 ID에서 실패했습니다. 이번 변경에서 생긴 회귀로 처리하지 않았으며, 기존 테스트/추천 선택 계약 정리는 별도 범위입니다.

브라우저는 한 인앱 세션에서 384×824 기준으로 자동 공개, 획득 후 빈 선반, 소지품, 닫힌 캐비닛, 시간 정지 재확인, 새로고침 이어하기를 확인했습니다. 가로 넘침과 브라우저 오류 로그는 없었습니다. 실 PostgreSQL 인스턴스 연동은 이번 로컬 검증 범위에 포함하지 않았습니다.

## 아직 적용하지 않은 범위

기존 지역·전투·NPC·제작을 새 엔진으로 이행하는 작업, 수량 일부 분할, 물건 놓기·다른 수납함으로 옮기기, 숨겨진 공간을 직접 뒤지는 조사 행동, 복잡한 시야·물리 계산, 콘텐츠 편집기 연동은 추가하지 않았습니다. 새 전투·NPC·그래픽·3D 시스템과 LLM 호출도 추가하지 않았습니다. 가림은 명시적 데이터 규칙으로 판정하며 첫 맵에는 별도 조사 퍼즐이 없습니다.
