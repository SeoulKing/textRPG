# 퀘스트의 다음 단계 안내

진행 중인 퀘스트에 재료를 찾는 단계와 실제 전달·조립을 하는 단계를 구분해 표시한다. 첫 통조림 부탁은 편의점 진열대 탐색에서 급식소 전달로, 구조 신호는 부품 탐색에서 임시 거처 제작으로 안내가 바뀐다. 물건을 모았다는 이유만으로 퀘스트를 완료 처리하지 않는다.

## 데이터와 실행 계약

- 선택적인 `guidance`에 `gathering`, `ready`, `completion`을 작성한다. `completion`은 행동 또는 선택 ID와 실행 장소를 참조한다. 검증기는 존재하지 않거나 장소가 맞지 않는 참조를 거부한다.
- 연결된 완료 행동의 실제 소비량·소지 조건·도구를 체크리스트로 사용한다. 중복 소비는 합산한다. 도구 내구도와 나머지 실행 조건이 충족되지 않으면 준비 완료라고 안내하지 않는다.
- 알려진 장소에서 이미 확인한 재고만 획득처로 표시한다. 남은 수량과 수집 완료 상태를 반영하며, 미발견 보관함의 내용물을 공개하지 않는다.
- 기존 저장에는 목적이 동일한 기본 퀘스트의 누락된 안내만 보완한다. 수정된 목표, 명시적 `null`, 작성자가 지정한 안내는 유지한다. 진행과 보관된 콘텐츠 원본을 변경하지 않는다.
- 안내 조회는 게임 상태·시간·아이템을 바꾸지 않는다. LLM 호출을 추가하지 않으며 탐색 선택지에도 안내용 행동을 추가하지 않는다.
- 클라이언트는 안내와 획득처를 HTML 이스케이프하고 기존 퀘스트 패널에 표시한다.

## 검증

`tests/quest-guidance.test.cjs`의 6개 테스트에서 새 게임의 실제 선택으로 부탁 수락 → 편의점 탐색 → 통조림 수집 → 급식소 전달을 확인했다. 준비 단계 전환, 알려진 재고, 레시피 수정과 중복 비용, 파손 도구, 기존 콘텐츠 보존, 잘못된 참조도 확인했다. 외부 요청은 차단했고 발생 횟수는 0회다. 빌드와 컴파일된 콘텐츠 검증, 클라이언트 구문 검사가 통과했다.

384×824 격리 브라우저에서 확인한 병원 재고 안내, 진열대 탐색 → 통조림 3개 수집 → 퀘스트 패널의 급식소 전달 안내 전환을 확인했다. 가로 넘침과 콘솔 오류는 없었다. 이 UI 검증은 메모리 저장소와 기본 서사를 사용했으며 사용자 저장과 실제 Gemini를 사용하지 않았다.
