# 운영 구축 독립 정적 인수 기록

2026-11-05 · 검토 담당: Codex 독립 품질 에이전트

## 인수 대상과 판정 범위

이번 M0는 **제작 조직의 운영 구성과 전체 출시·공개 시범판 제작 계약 초안 전달**입니다. M1 이후 게임 제작, 새 미술, 실행 검증, 공개 배포를 승인하거나 시범판의 실제 동작을 인수하는 단계가 아닙니다.

[운영 헌장](README.md), [원장](board.json), [출시 계약 초안](RELEASE_PLAN.md), [CLI 실행기](../../scripts/studio/studio.mjs), 엔진·작업 결과 프로토콜·앱 인계 모듈과 [운영 모듈 테스트](../../tests/studio-organization.test.mjs)를 독립 컨텍스트에서 읽고 대조했습니다. 구현 담당자의 완료 설명만으로 인수하지 않고 승인·상태 전이·실제 결과 경로·중단 처리의 코드 경로를 확인했습니다.

정적 산출물과 확인 기록은 M0 인수 근거로 사용할 수 있습니다. 아래의 실행 미확인 항목을 실제 동작 검증 통과로 바꾸어 기록하지 않습니다.

## 발견 사항과 수정 확인

| 발견 사항 | 수정 후 읽기 확인 |
| --- | --- |
| 총괄 잠금 전에 읽은 오래된 원장을 실행 중 다시 저장할 수 있었습니다. | CLI가 잠금 획득 후 원장을 읽고 승인 계약을 재검증합니다. |
| 실행 디렉터리 생성 등 초기화 실패가 잠금 해제 범위 밖에 있었습니다. | 잠금 이후 초기화를 try/finally 안에 두고 종료 시 신호 처리기와 잠금을 정리합니다. |
| 검토의 JSON 오류·실행 실패까지 정상 중단처럼 재개할 수 있었습니다. | 시간 한도·사용자 중단만 review 상태로 남기고, 다른 오류는 실패 지문과 함께 보류합니다. |
| 개별 결과·작업 오류가 독립 작업까지 중단시켰습니다. | 작업별 오류는 해당 작업을 보류하고 이어갑니다. CLI 기동·비정상 종료·기록 저장 같은 공통 실행 기반 오류는 해당 회차를 중단합니다. 총괄 요청 조정 실패는 판단 사항으로 올립니다. |
| 원장의 done 작업에 검토 근거가 없을 수 있었습니다. | 원장 검증과 완료 전이 양쪽에서 검토 결과 경로와 비어 있지 않은 증거를 요구합니다. 결과 프로토콜은 작업 ID·목표 ID·단계와 실제 근거 파일을 추가로 확인합니다. |
| 허용된 경로 별칭으로 기밀 경로를 기준 백업할 수 있었습니다. | 논리 경로와 실제 경로를 확인하여 작업 공간 밖 링크와 내부 기밀 경로를 거부합니다. 작업 전 원본 바이트 백업은 자동 복원하지 않습니다. |
| 미승인 작업의 발주 프롬프트와 앱 결과 인수 절차가 불명확했습니다. | prompt는 승인 계약·작업 권한을 확인합니다. handoff/report는 같은 총괄 잠금과 결과 프로토콜을 사용합니다. CLI는 진행 중인 active 앱 작업이 있으면 시작하지 않습니다. |
| 시간 한도의 종료 요청만으로는 대기 중인 Promise가 끝나지 않을 수 있었습니다. | stop()이 중복 종료 요청을 막고 대기 Promise를 interruptionError로 즉시 거절하여 finally의 프로세스 정리로 진입합니다. 실제 운영체제 종료 동작은 미검증입니다. |
| 앱 결과가 이전 시도의 결과 파일을 재사용할 수 있었습니다. | producer·reviewer·검토 재개용 producer 파일을 현재 작업의 runId 디렉터리 아래로 논리·물리 양쪽에서 제한합니다. 제작·검토 결과가 같은 실제 파일이면 인수를 거부합니다. |

승인 지문은 목표 범위·완료 조건·선행 목표·허용 능력과 검증·미술·게시 권한을 포함합니다. 작업자는 원장·승인을 직접 바꾸지 않고 요청 결과를 제출하며, 총괄이 승인 범위와 의존성을 확인하여 반영합니다. 요청 결과가 새로운 권한 자체를 부여하지 않습니다.

## 수행한 정적 확인

- 각 작성자가 수정한 JavaScript 파일에 node --check를 수행하여 구문 오류가 없음을 확인했습니다. 검토 담당은 테스트 파일의 구문만 확인했습니다.
- 총괄이 studio.mjs validate로 원장의 구조·경로·작업 및 목표 의존성을 확인했습니다.
- 총괄이 JSON 3개, 상대 import 6개, 문서 링크 44개를 정적으로 대조했습니다. 이 문서는 당시 작성 대기 링크였으며 이제 생성했습니다.
- 총괄의 변경 공백 검사는 기존 CRLF를 보존한 채 core.whitespace=cr-at-eol을 명령에 적용하여 확인했습니다.
- 테스트 파일에는 승인·계약 지문·의존성·완료 증거·원장 보존·실행 잠금·기준 백업·경로 탈출·결과 계약에 대한 최상위 20개 시나리오를 준비했습니다. 테스트를 실행한 결과는 아닙니다.

실행 상한은 조직 전체 최대 4명이며, 초기 CLI는 제작자 또는 검토자 한 프로세스를 순차 실행합니다. 앱의 총괄 직접 운영에서는 소유 범위가 겹치지 않는 제작자를 최대 2명까지 배정할 수 있습니다. handoff 명령을 통한 초기 앱 인계는 한 번에 하나의 active 제작 작업만 허용합니다.

## 실행하지 않은 항목과 남은 인수

라이브 Codex 제작·검토 작업, 모델 호출, 테스트, 게임, 브라우저, 빌드·내보내기·공개 배포는 실행하지 않았습니다. 따라서 CLI 인증·모델 접근, 실제 하위 프로세스 종료, 시간 한도에서의 복구, 앱 도구 연동, 실패 후 재개, 실제 게임 연결·플레이 품질은 이번 기록의 통과 항목이 아닙니다.

시간 한도·사용자 중단은 대기 Promise를 종료하고 프로세스 정리로 진입하도록 구현되어 있습니다. 운영체제가 종료를 거부하는 경우와 자식 명령까지 회수되는 실제 동작은 실행하지 않았으므로 미검증으로 남깁니다.

수정 범위·개별 검증 명령·앱 JSON의 실제 작성자 확인은 운영 계약입니다. 파일별 OS 격리나 JSON의 진위를 이 실행기가 보증하지 않습니다. CLI 검토는 별도 읽기 전용 프로세스로 실행하도록 구현되었고, 앱 결과의 독립 검토 수행 여부는 인수하는 앱 총괄이 확인해야 합니다.

다음 단계는 제작 계약의 사용자 판단을 원장에 반영한 뒤 M1을 승인하는 것입니다. 기존 사용자 저장·원본·수동 배치를 검증을 위해 초기화하거나 변경하지 않습니다.
