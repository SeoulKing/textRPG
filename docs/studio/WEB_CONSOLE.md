# 모바일 제작실 운영

[아르카나 제작실](https://arcana-production-desk-bang.seoulprince.chatgpt.site)에 본인 계정으로 로그인하여 휴대폰에서 운영합니다. 브라우저의 ‘홈 화면에 추가’를 사용하면 아이콘으로 바로 열 수 있습니다. 첫 버전 알림은 웹의 지시함·배지로 제공하며 푸시는 후속 범위입니다.

## 처음 한 번 연결

1. 웹의 **PC 연결**에서 연결 코드를 만듭니다. 코드는 10분 동안 한 번만 사용할 수 있습니다.
2. 이 PC의 서비스 접근 설정은 Codex가 Windows 사용자 계정으로 암호화하여 준비합니다. 화면이나 소스에 서비스 토큰을 복사하지 않습니다.
3. 코드로 아래 pair 명령을 수행한 뒤 숨김 연결기를 시작합니다. 현재 Codex 대화에 코드만 전달하셔도 이 단계를 맡기실 수 있습니다.

~~~powershell
node scripts/studio/bridge.mjs pair --site https://arcana-production-desk-bang.seoulprince.chatgpt.site --code <연결코드>
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/studio/start-bridge.ps1
~~~

이후에는 웹앱에서 지시합니다. Codex 앱 화면을 열어 둘 필요는 없지만 작업 PC와 연결기는 실행 중이어야 합니다. PC가 꺼지면 마지막 확인 상태가 표시되고 지시는 대기합니다. 새 PC를 연결하면 이전 기기와 미확인 실행 상태를 자동 재실행하지 않습니다.

## 결과함

제작실 홈의 **결과함**에서 새 지시의 완성 화면, 로컬 본편에 적용한 내용, 확인 범위와 남은 제약을 봅니다. 전후 이미지가 있으면 휴대폰에서도 선택해 열 수 있습니다. 같은 지시에는 결과 카드 한 건이 보이고, 부서별 과정은 상세 기록에서 확인합니다. 목표 안에서 시안의 선택과 수정은 총괄과 독립 검토자가 처리합니다. 사용자님의 결정이 필요한 범위 변경이나 해결할 수 없는 도구 문제는 이유와 함께 표시합니다. 카드를 읽거나 확인을 누를 때까지 다음 지시를 보류하지 않습니다.

## 모바일 사용

- **홈:** 주간 잔여 사용량·초기화 시각, 내 지시로 만든 목표·완료 조건·부서별 작업, 실제 진행 동작과 연결 상태를 확인합니다. 주간 한도가 반환되지 않으면 미제공 상태를 표시합니다.
- **부서:** 총괄·기획·서사·그래픽 디자인·캐릭터·개발·품질과 대화합니다. 명확한 변경 지시는 원문·완료 조건을 가진 새 목표와 선행 관계가 있는 부서 작업으로 등록합니다. 관련 있는 승인 목표의 범위 안일 때만 기존 목표에 추가하며, 단순 질문은 작업을 만들지 않습니다. 특정 부서의 진행 중 작업 보완은 화면에서 보낸 turn ID가 일치할 때만 바로 전달합니다.
- **지시함:** 접수·실행·완료·확인 필요를 구분하고 목표 승인, 판단 답변, 실제 Codex 승인 요청을 처리합니다.
- **사용량:** 계정 전체의 반환된 한도만 보여줍니다. 초기화 예정 시각·마지막 갱신·초기화권 보유량을 표시하며 토큰을 구독 잔여량으로 환산하지 않습니다.

‘다음 작업부터 일시정지’는 현재 작업 인수 뒤에 멈춥니다. ‘현재 작업 중단’은 진행 중 작업의 중단을 요청하며 부분 변경을 보존합니다. 직접 내린 새 지시는 일반적인 정적 검토·코드·콘텐츠·UI 제작의 위임 근거로 기록합니다. 위임 범위 밖의 미술·실행 검사·게시·접속할 수 없는 앱 전용 도구가 필요한 작업은 해당 승인·인계 조건만 따로 표시하며, 독립적인 일반 제작은 계속할 수 있습니다. 이미 주어진 구체적인 승인도 함께 확인합니다. 예를 들어 같은 사용자님이 제작실을 대상으로 말씀하신 뒤 “웹푸시하라고”라고 명령하면, 모델 답변 대신 실제 명령·대상 근거로 해당 제작실의 게시만 승인 기록에 포함합니다. 요리 목표나 다른 사이트의 권한을 바꾸지 않습니다. 질문·부정·조건부 승인·대상 혼동은 게시 승인으로 간주하지 않습니다.

## 기술 연구

**부서 → 기획** 대화에서 **기술 연구**를 선택하고 조사할 문제를 보내 주세요. 예를 들어 “Godot 2D 조명 기법 중 모바일 웹에서 쓸 수 있는 방식을 찾아 아르카나 상점 씬에 적용할 방법을 비교해 주세요”라고 요청하실 수 있습니다. PC 연결기가 공개 자료와 아르카나의 관련 파일을 읽고, 출처·적용 후보·제약·권장안과 최소 실험 범위를 기획 대화에 남깁니다. 검색을 확인할 수 없는 요청은 지시함에서 확인 필요로 표시합니다.

연구는 읽기 전용으로 진행합니다. 적용할 안을 결정하시면 **기술 연구**를 해제하고 기획 대화에 적용 범위를 지시해 일반 제작으로 넘기실 수 있습니다.

## 새 지시가 작업이 되는 순서

1. 총괄이 실제 파일을 읽기 전용으로 확인하고 목표·완료 조건·부서별 작업을 정리합니다. 선택된 기존 목표는 참고 맥락이며 새 요청을 거절하는 경계가 아닙니다.
2. 지시와 계획은 PC의 영속 대기열에 먼저 저장합니다. 원장 잠금을 잡은 뒤 최신 원장에 등록하며 같은 명령은 중복 목표를 만들지 않습니다.
3. 자체 제작 중이면 현재 제작과 독립 검토를 마치고 새 목표를 우선 진행합니다. 이전 목표는 이어받을 순서에 남습니다. 다른 실행기가 잠금을 보유하면 등록 대기 이유를 웹에 표시하고 해제 후 자동 등록합니다.
4. 각 제작 결과는 별도 검토를 거쳐 다음 부서로 전달합니다. 특별 승인이 필요한 작업과 중단된 제작은 자동 재실행하지 않습니다. 기존 목표의 최종 인수는 사용자님이 판단합니다. 새 제작 목표는 총괄이 위임된 범위의 결과를 전달합니다.

그래픽 지시의 **지시 처리 흐름**에서 게임 기획의 제작 명세와 그래픽 디자인의 작업을 확인할 수 있습니다. 작업에 따라 Blender 모델 또는 PixelPen 도트 자산을 제작하고, 필요한 경우 그래픽 디자인이 Godot 씬에 적용합니다. 기존 자산을 쓰는 씬 작업은 기획에서 바로 Godot 작업으로 넘깁니다. 최초 발주의 Blender 제작에는 Terra Ultra가 배정됩니다. [그래픽 제작 흐름](README.md#그래픽-제작-흐름)

## 지시별 처리·인계 확인

홈의 목표, 대화의 지시 영수증, 지시함에서 **지시 처리 흐름**를 열면 원문부터 현재 담당·대기 이유, 부서 배정, 제작 결과, 독립 검토·보완, 다음 부서 인계와 근거 파일을 시간순으로 확인합니다. 여러 지시가 같은 목표에 추가된 경우 해당 commandId의 작업·요청 계보를 따라 표시하며 관련 없는 과거 작업을 이 지시가 만든 결과처럼 합치지 않습니다.

새 실행에서는 선행 작업의 제출 요약·근거 파일·협업 요청 이유를 다음 담당자의 프롬프트에 함께 넣습니다. 인계 준비, 응답이 확인된 전달, 선행 작업 대기와 아직 수락되지 않은 요청을 구분합니다. 전달 기록은 파일 내용을 실제로 읽거나 사용자 품질 인수를 마쳤다는 뜻이 아닙니다. 불필요한 부서·가상의 대화·회의를 만들지 않습니다.

협업 기록은 로컬 원장의 collaborationEvents에 보존되며 웹에는 필요한 요약을 동기화합니다. 이전 작업의 상태·결과에서 확인한 정보는 **기존 기록**, 선행 관계만 정해진 인계는 **예정**, 기능 적용 뒤 남긴 이벤트는 **실제 기록**으로 구분합니다. 과거에 없던 인계 시각이나 대화 내용을 소급 생성하지 않습니다.

## 부서 완료 보고와 총괄의 후속 배정

담당 부서의 결과가 독립 품질 검토를 통과하면 원장에 총괄 완료 보고를 함께 저장합니다. 총괄은 완료한 결과·근거와 목표 전체의 완료 조건, 미완료 작업·협업 요청을 확인한 뒤 다음 담당 작업을 지정하거나 빠진 통합·후속 작업을 승인 범위 안에서 배정합니다. 다음 부서는 총괄이 지정한 순서와 선행 결과를 이어받습니다. 작업별 완료와 목표 전체의 최종 인수는 구분합니다.

모든 부서 작업이 끝났다는 사실만으로 목표 확인을 완료 처리하지 않습니다. 총괄이 목표의 각 완료 조건을 실제 제출 근거와 대조합니다. 새 제작 목표는 결과함에 전달하며 기존 목표는 사용자 인수 대기로 넘깁니다. 미실시한 플레이·미술 승인·검증은 확인했다고 기록하지 않습니다. 별도 앱에서 완료를 보고했을 때도 PC 연결기가 보고를 발견해 총괄 확인을 이어받습니다.

완료 보고·총괄 확인·다음 배정은 **지시 처리 흐름**에 기록합니다. 실패한 총괄 확인을 같은 조건으로 자동 반복하지 않으며 재개 근거를 남겨 다시 이어받습니다. 사용자 일시정지·중단과 기존 실행 시간·작업 선택 한도를 유지하며, 한도를 자동 연장하지 않습니다. 과거 작업에 총괄이 보고를 받았다는 기록을 소급 생성하지 않습니다.

## PC 연결기 완전 종료

웹의 연결 상태 설정에서 **PC 연결기 완전 종료**를 선택하면 현재 작업을 중단하고 Codex 자식 프로세스와 PC 연결기까지 종료합니다. 상태 동기화와 사용량 조회도 멈춥니다. 사이트와 과거 기록은 계속 열 수 있습니다.

완전히 종료한 PC 프로그램은 웹에서 다시 켤 수 없습니다. PC에서 start-bridge.ps1을 실행하시면 기존 기기 등록을 재사용하므로 연결 코드를 다시 입력하지 않습니다. Windows 자동 시작은 기본으로 등록하지 않습니다.

## PC 연결기 관리

~~~powershell
node scripts/studio/bridge.mjs status
node scripts/studio/bridge.mjs stop
~~~

Windows 로그인 시 자동 연결을 원하실 때만 다음을 선택합니다.

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/studio/start-bridge.ps1 -AutoStart
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/studio/start-bridge.ps1 -DisableAutoStart
~~~

비밀 설정은 .runtime/studio/bridge-secrets.json에 DPAPI 암호문으로 저장되며 해당 Windows 사용자만 복호화합니다. bridge-config.json은 주소·기기 식별정보만, bridge-state.json은 지시 처리·영속 outbox를 보관합니다. 비밀·원본 인증 파일·개인 저장을 클라우드에 보내지 않습니다. bridge.stdout.log/bridge.stderr.log는 필요한 연결 문제에서만 확인합니다.

## 구조와 확인 범위

웹 소스는 sites/arcana-studio의 독립 Sites 저장소이며 게임 저장소를 게시하지 않습니다. D1은 연결·지시·메시지·최근 snapshot을 저장하고 로컬 원장은 기존 조직 운영의 기준으로 유지합니다. PC는 HTTPS로만 외부 연결하며 인터넷 공개 포트를 열지 않습니다.

구축 확인은 JavaScript·PowerShell 구문, 웹 타입, D1 마이그레이션 구조와 사이트 산출물 빌드입니다. 브라우저·게임·모델 시범 실행·자동 테스트는 별도 요청 전에는 수행하지 않습니다. 실제 PC 등록과 상주 기동은 사용자가 생성한 연결 코드로 수행하는 운영 단계입니다.

## 부서별 기본 모델 설정

부서 화면의 **기본 모델 설정** 또는 **더보기 → 부서별 모델 설정**에서 모델과 추론 강도를 선택하고 저장합니다. 선택지는 연결된 PC의 Codex 계정이 제공한 모델 목록과 지원 강도입니다. PC가 연결되지 않았을 때는 설정 요청을 보관하며, 진행 중인 제작·검토가 있으면 해당 실행을 마친 뒤 저장합니다. 반영 대기와 저장된 기본값은 구분해 표시합니다.

원장의 `settings.modelPolicy.departmentDefaults`에 부서별로 저장하므로 같은 프로필을 사용하던 다른 부서의 설정은 바뀌지 않습니다. 새 실행의 기본값에 적용하며, 작업별 명시 프로필과 critical 검토의 우선순위는 유지합니다. 기존 목표 승인·제작·검증 권한은 변경하지 않습니다.
