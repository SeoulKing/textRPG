# 요리·음식 후보 — COOK-010

아르카나의 기존 모닥불·생선구이를 바탕으로, 사용자님께서 선택하실 요리·음식 게임플레이와 첫 제작 범위를 제안드립니다. **현재는 정적 후보 기획만 승인된 단계**입니다. 추천은 선택을 대신하지 않으며 새 음식·효과·수치·미술은 확정하지 않았습니다. 이번 완료 범위는 선택 가능한 후보 전달까지이고 실제 구현은 선택 후입니다. 후속 작업은 아직 발주하지 않습니다(`requests=[]`).

## 확인한 기존 기반과 미검증

‘있음’은 소스·연결 확인이며 정상 플레이를 검증했다는 뜻은 아닙니다.

## 후보 A — 강변 캠프 식사 · 추천

- **플레이 경험:** 낚시한 생선을 굽고 품질을 확인한 뒤 먹는 짧고 편안한 생활 흐름입니다. 이미 있는 기능을 처음부터 끝까지 일관되게 이해하고 사용하시도록 정리합니다.
- **레시피·조리·섭취:** 기존 민물고기 굽기, 모닥불 품질별 시간, 진행·취소와 소지품 섭취를 유지합니다. 재료 수량·조건·결과와 섭취 전 실제 회복 예상량을 명확하게 전달합니다.
- **효과·허기·숙련도:** 기존 허기 회복과 품질 확률·완성 성장값으로 출발하는 안입니다. 새 강화 효과·허기 벌칙은 첫 범위에 추가하지 않는 제안입니다.
- **비용·재사용:** 세 후보 중 작습니다. 기존 생선구이 세 품질·모닥불·아이템 그림·창·진행바를 재사용하며 새 음식 미술 없이 시작하실 수 있습니다.
- **첫 범위·결정:** 음식 한 종류와 기존 세 품질로 낚시→제작/설치→조리→획득→섭취를 정리합니다. ‘차분한 생활 경험’을 먼저 완성할지 선택해 주시면 됩니다.

## 후보 B — 출정 전 식단

- **플레이 경험:** 다음 행동을 생각하며 어떤 음식을 만들고 먹을지 고르시는 준비 경험입니다. 음식의 용도가 달라 레시피 선택과 재료 수집의 이유가 생깁니다.
- **레시피·조리·섭취:** 생선구이에 소수의 대체 음식 후보를 더하고 재료 조합을 선택합니다. 보조 재료는 실제 획득 경로를 확인한 뒤 선정합니다. 기존 재료 이름만으로 식용·공급 가능하다고 확정하지 않습니다.
- **효과·허기·숙련도:** 허기 중심 음식과 다른 목적의 음식을 구분하는 방향입니다. 추가 회복/일시 보조 중 효과 방향, 중첩·교체·만복 제한은 사용자님 판단으로 남깁니다. 기존 품질·숙련도는 재사용하되 효과량·지속 시간·새 성장 보상은 미정입니다.
- **비용·재사용:** 중간 이상입니다. 레시피 목록, 서버 효과·저장, 기존 포션과의 역할 검토가 추가됩니다. 기존 재료·모닥불은 재사용 후보이며 새 음식 외형은 썸네일과 별도 미술 범위를 정하셔야 합니다.
- **첫 범위·결정:** 기존 음식과 용도가 분명히 다른 대체 음식부터 작게 비교하는 안입니다. 음식 종류·효과 방향·재료 공급·새 미술 허용 여부를 먼저 결정해 주셔야 합니다.

## 후보 C — 불 앞의 손맛

- **플레이 경험:** 알맞은 순간에 뒤집거나 마무리하며 직접 잘 구웠다는 감각을 얻으시는 안입니다. 레시피 수보다 짧은 조작의 재미에 집중합니다.
- **레시피·조리·섭취:** 기존 생선구이에 짧은 타이밍 행동을 추가하고 완성 음식은 소지품에서 드십니다. 입력 기회·실패 처리·중단 방식은 선택 후 설계합니다.
- **효과·허기·숙련도:** 기존 허기 회복과 세 품질을 재사용합니다. 손 조작과 숙련도 확률이 품질에 각각 어떻게 기여할지는 미정입니다. 기존 저장의 음식·숙련도는 소급 변경하지 않습니다.
- **비용·재사용:** 중간 이상입니다. 기존 불꽃·진행바·썸네일을 재사용할 수 있지만 서버 시간 판정, 지연·연결 종료, 모바일/키보드 입력 공정성과 취소 구현이 추가됩니다.
- **첫 범위·결정:** 한 레시피에 한 종류의 짧은 참여 행동부터 제안드립니다. 조작 필수 여부와 실패 시 음식·재료 처리 방향을 정하셔야 합니다. 실패 벌칙이나 품질 보너스 수치는 확정하지 않습니다.

## 추천 첫 범위와 시범판 영향

**A를 먼저 선택하시는 안을 추천드립니다.** 현재 기반에 가장 가깝고 새 미술 없이 완성 흐름을 확인하실 수 있습니다. 음식의 전략적 용도가 우선이면 B, 조작의 손맛이 우선이면 C를 선택하실 수 있습니다. 세 후보를 모두 필수 범위로 묶지 않습니다.

A를 선택하시면 레시피 선택→재료·조건·시간 확인→진행/취소→품질별 음식 획득→소지품 섭취→효과 반영을 한 계약으로 정리하는 안입니다. 서버가 재료 소모·생성·섭취를 판정하며, 중단·부족·반복 요청으로 잘못된 소모/지급을 만들지 않는 기준입니다. 기존 `riverFish`, 목재·모닥불, `grilledFish/Fine/Excellent` ID와 `arcanaLife`, `skillTraining.cooking/crafting`, 최초 지급 표식을 보존합니다. 구 저장의 아이템 보정·카탈로그를 함께 맞추고 진행 중 작업을 재접속 시 자동 완성·중복 지급하지 않는 정책을 유지하는 안입니다. 이는 후속 구현·검토 조건이며 현재 동작 보증이 아닙니다.

[시범판 초안](../RELEASE_PLAN.md)의 낚시 이후, 재접속 이전에 조리·섭취를 연결하는 안입니다. 제작·조리 외 메뉴·설치 시간이 추가되며 총 체험 시간은 미측정입니다. 새 캐릭터가 계속 연결되어 있었다면 10~15분의 허기 감소는 약 20~30이므로 현재 음식 한 개의 회복량보다 작습니다. 이는 코드 값 계산이며 플레이 측정이 아닙니다. 첫 음식을 먹이려고 강제로 기다리게 하거나 허기를 임의로 깎지 않습니다. B·C는 재료 수집·조작 학습에 따라 10~15분 목표를 다시 판단하셔야 합니다. M1~M4의 지역·의뢰·성장·공개 범위는 자동 확대하지 않습니다.

## 사용자 선택 — 첫 음식 3종

- 버섯구이: 버섯을 굽는 요리입니다.
- 구운 감자: 감자를 굽는 요리입니다.
- 고기꼬치: 재료는 사용자 지정 **고기 + 나뭇가지**입니다.

신규 음식은 이 3종으로 좁힙니다. 기존 생선구이는 보존합니다. 재료 수량·회복량은 아직 확정하지 않았으며, 미술 스킬의 컨셉 승인 순서에 따라 음식 3종을 한 장의 시안으로 먼저 제시합니다. 위 A/B/C는 이전 탐색 후보이며 현재 선택을 대신하지 않습니다.

## 승인 후 구현 연결

버섯구이(버섯1), 구운감자(감자1), 고기꼬치(고기1+나뭇가지1)를 추가했습니다. 기존 생선구이는 유지합니다. 새 음식도 보통/양호/우수 3품질과 기존 허기회복40/50/60, 모닥불별6/4/3초를 사용합니다. 신규재료4종은 기존상점에서 구매2골드/판매1골드의 초기값으로 공급합니다. 음식·재료7종의64px PixelPen원본과 PNG를 제작하고 품질별음식은 같은 썸네일을 공유합니다. TS구문과 독립 정적 검토만 수행하며 플레이·브라우저·웹내보내기는 미실행입니다.
