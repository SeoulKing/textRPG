# 병원의 공통 탐색과 기존 행동 연결

병원을 접수실과 임시 처치실로 구성했다. 접수대 뒤 약품 보관함의 접근·자세 변경·개방·내용물 확인은 물리 엔진에서 실행하고 수집은 다음 선택으로 남긴다. 처치실에서는 임시 처치대를 살핀 뒤 응급 처치나 환자 돕기를 선택한다. 지역 이동은 기존 지도 메뉴를 이용한다.

## 재고의 단일 기준

- 엔티티의 `components.stockNode.nodeId`가 해당 지역의 기존 stockNode를 가리킨다.
- 남은 수량과 돈의 기준은 GameState.stockState다. 탐색 엔티티는 그 값을 투영하며 별도 재고를 지급하지 않는다.
- 닫힌 보관함의 내용물은 서술 문맥과 수집 선택지에서 숨긴다. 열기에 실패하면 발견 처리하지 않는다.
- 묶음 수집은 각 기존 수집 선택의 실제 보상·숙련·시간 효과를 한 번씩 실행한다. 병원 네 품목은 기본 숙련에서 총 60분이다. 접근과 자세 변경의 짧은 시간은 별도로 실행된다.
- 수집한 물건은 소지 엔티티로 연결되어 기존 담기·꺼내기·제작 소비·지역 이동 규칙을 따른다. 재고 엔티티를 직접 TAKE하는 선택으로 기존 비용을 우회하지 못한다.
- 보관함에 플레이어가 넣어 둔 물건은 재고 동기화에서 보존한다. remain과 disappear는 기존 재고 노드의 의미를 유지한다.
- 수집 도중 사망하면 그 전에 실행한 수집만 남는다. 나머지 품목은 그대로 보관함에 남으며 중단을 기록한다.

## 고유 행동의 연결

`components.interactionPoint.actions`에 기존 actionId와 role(work 또는 care)을 작성한다. 관찰·근접·현재 관심 대상 조건을 만족할 때만 후보가 된다. 기존 조건과 일일 제한도 적용하며, Choice Director는 작업과 회복을 서로 다른 행동 계열로 다룬다.

기존 rules의 실행 경로를 한 번 호출한다. onNarrative 콜백은 실행된 로그와 실제로 선택된 장면만 전달한다. 무작위 분기의 가능성을 미리 서술하지 않는다. SERVICE 결과에는 실제 선택된 문단, 보상, 시간, 돈·상태 변화, 중단 여부를 저장한다. 받은 아이템의 물리 엔티티는 보상 지급 후 한 번만 만든다.

병원의 기존 응급 처치 비용과 회복량, 환자 돕기의 네 결과와 확률을 유지했다. 원래 병원 장면에 작성되어 있던 환자·처치 활동을 사용하며 새로운 NPC 사건을 생성하지 않는다.

## 저장과 작성 도구

기존 버전에는 원래 병원 재고가 있는 경우에만 기본 방을 보완한다. 이미 작성한 병원 방과 탐색을 사용하지 않는 설정은 유지한다. 예전 저장의 남은 재고·소지품·발견 여부와 보관함에 집중하던 상태를 이어 받는다. 새 구성 요소는 선택 필드이므로 기존 저장의 초기화가 필요하지 않다.

Studio 문서의 저장·파싱·게시 경로는 연결 필드를 보존한다. 존재하지 않는 재고 노드, 다른 지역의 행동, 휴대하거나 밀 수 있는 재고 보관함 연결은 게시 검증에서 거부한다.

## 읽기와 검증

입장 또는 선택당 기존 서술 요청 한 번을 사용한다. 다음 선택 문구와 짧은 속말도 같은 요청에 포함한다. 재조회와 저장 복원에는 다시 생성하지 않는다. 기본 서사는 실제 실행 결과와 선택된 고유 장면으로 이어 쓴다.

- 병원 테스트 14개: 비공개 내용물, 한 번의 의도로 발견, 별도 수집, 실제 비용·숙련, 중복 요청, 부분 수집 후 사망, 기존 저장, 유료 처치, 네 무작위 분기, 서비스 중단, 임의 콘텐츠 ID, 현금·소진, Studio 보존.
- 기존 지역·선택 연출·Choice Director·제작 테스트 34개와 Studio 방·재고 테스트 8개 통과. 기존 Studio 테스트의 탐색 보조 함수도 현재의 STOW 선택을 통해 휴대를 마치도록 수정했다.
- TypeScript 빌드와 컴파일된 콘텐츠 검증 통과.
- 384×824 격리 브라우저에서 입장 → 보관함 확인 → 묶음 수집 → 처치실 이동 → 처치대 관찰 → 응급 처치 → 환자 돕기의 흐름을 확인했다. 이전 본문·선택한 줄·짧은 속말을 유지하고 대기 중 입력을 잠그며 결과를 이어 붙인다.

브라우저는 인메모리 저장과 기본 서사를 사용한다. 사용자 저장과 실제 Gemini 할당량을 사용하지 않는다. 실제 Gemini 문체·자연어 충실도는 이번 검증 범위에 포함하지 않는다.


마지막 읽기 확인에서 천 조각 보상이 본문에는 허락으로만 표현되는 것을 발견했다. 기본 SERVICE 서술의 끝에 실제 받은 물건을 챙기는 문장을 연결하고 네 보상 분기와 중단 테스트로 확인했다. 이 문장 보완은 브라우저 확인 이후 적용했으며, UI 동작은 동일하다. 브라우저에서는 여섯 행동 뒤 일곱 본문 블록, 가로 폭 384px, 콘솔 오류 없음까지 확인했다.
