# 아르카나 아르카나 세계

현재 개발 모드에서는 로그인 없이 입장과 이름 등록을 사용합니다. 카카오·구글 계정 기능은 유지하며 정식 운영 전환 시 활성화할 수 있습니다.

## 제공 범위

아르카나는 사람들이 계속 들어와 활동하는 하나의 지속되는 온라인 세계입니다. `main`은 그 세계의 고정 식별자이며 방·파티·4인 인스턴스가 아닙니다. 사람의 입장·퇴장이나 접속 제한 변경으로 세계를 새로 만들거나 초기화하지 않습니다. 현재 4명은 개발 중에만 적용하는 임시 동시 접속 제한이며 방문자와 재접속 유예 인원도 포함합니다. 향후 파티는 이 세계 안에서 맺는 별도 그룹입니다. 같은 실내·층의 플레이어가 서로 보이고 광장 슬라임의 HP·추격·투사체·처치 결과를 공유합니다. 서버는 20Hz로 시뮬레이션하고 10Hz로 상태를 전송합니다. 플레이어는 같은 공간의 반경 384 월드 픽셀(24타일) 이내에서 표시되며, 표시된 뒤에는 448픽셀 밖에서 제거해 경계 깜빡임을 줄입니다. 공간 그리드를 한 번 구성하고 연결마다 바뀐 플레이어와 제거 ID만 전송합니다. 최초 접속·재접속 때는 근거리 전체 기준 목록을 새로 전달합니다. 메뉴·대화·탭 전환은 세계를 멈추지 않습니다.

일반 몬스터의 보상은 마지막 유효 타격자에게 한 번 지급합니다. 현재 슬라임의 기존 보상은 돈 30, 경험치 0이며, 각자의 스킬 숙련도는 유효 사용·적중으로 성장합니다. 슬라임은 30초 뒤 재생성됩니다. 필드 보스용 피해 기여도 분배 함수는 준비되어 있으나 새 보스·파티·공동 수업·PvP는 이번 범위에 포함하지 않습니다.

계정 화면은 `/account.html`, 게임은 `/godot/`입니다. 비회원은 방문자 번호로 표시됩니다. 로그인하면 이름을 등록하고 다른 기기에서도 동일한 캐릭터를 이용합니다. 방문자는 같은 브라우저에서 7일, 로그인 세션은 30일 유지하며 로그아웃 시 세션을 취소합니다.

## 운영 설정

- 운영 서버는 `NODE_ENV=production`, PostgreSQL, 32자 이상의 `AUTH_SECRET`, HTTPS `PUBLIC_BASE_URL`이 필요합니다. 누락하면 시작을 거절합니다.
- DB는 기존 우선순위인 `NEON_DATABASE_URL` → `DATABASE_URL`을 사용합니다. 로컬 개발에서는 원자적 JSON 체크포인트를 사용하지만 공개 서버의 파일 저장 대체 경로는 허용하지 않습니다.
- `ALLOWED_ORIGINS`는 쉼표로 구분한 정확한 Origin 목록입니다. 생략하면 `PUBLIC_BASE_URL`만 허용합니다. 프런트엔드·API·소켓은 같은 Origin으로 제공합니다.
- `ARCANA_DEV_CONNECTION_LIMIT=4`는 개발 모드의 임시 동시 접속 제한입니다. `ARCANA_DEVELOPMENT_ACCESS=false`로 개발 모드를 끄면 이 제한은 적용하지 않습니다. 기존 `ARCANA_WORLD_CAPACITY` 설정과 64명 상한은 사용하지 않습니다. 제한 해제는 대규모 접속 처리 성능을 보장하지 않으며 운영 전 부하 확인과 서버 자원 설계가 필요합니다.
- `ARCANA_ADMIN_ACCOUNT_IDS`에는 운영자 내부 계정 UUID를 쉼표로 지정합니다. 소셜 프로필 이름이나 이메일로 운영자 권한을 부여하지 않습니다.
- 기존 Render Blueprint에 구글 로그인 키와 개발용 임시 동시 접속 제한을 추가했습니다. 실제 공급자 앱 등록·DB·환경변수와 배포 반영은 별도 운영 설정입니다.

카카오는 `KAKAO_REST_API_KEY`와 앱 설정에 따른 `KAKAO_CLIENT_SECRET`, 구글은 `GOOGLE_CLIENT_ID`와 `GOOGLE_CLIENT_SECRET`을 설정합니다. 각 공급자 콘솔에 다음 콜백을 등록합니다.

- `<PUBLIC_BASE_URL>/api/auth/kakao/callback`
- `<PUBLIC_BASE_URL>/api/auth/google/callback`

카카오 이메일 자동 연결에는 계정 이메일 동의와 `is_email_valid`, `is_email_verified`가 모두 필요합니다. 구글은 서명·발급자·대상 클라이언트·만료·nonce를 검증한 ID 토큰의 `email_verified`를 사용합니다. 이메일은 양쪽에서 확인된 정확한 문자열이 같을 때 자동 연결하며 점·별칭을 임의로 치환하지 않습니다. 이메일이 다르거나 없으면 로그인 후 계정 화면의 다른 공급자 연결을 사용합니다. 공급자 앱이 테스트 사용자만 허용하는 설정이면 공급자 콘솔에서도 외부 사용자 허용을 준비해야 합니다.

기존 Render 무료 웹 서비스에는 휴면과 재시작이 있고, 무료 Render PostgreSQL에는 보관 기한이 있습니다. 장기 저장에 사용할 실제 DB의 수명·백업을 운영자가 확인해야 합니다. 서버가 잠든 경우 클라이언트는 연결 지연을 안내하고 재시도합니다.

## 입력 반응과 거래 복구

화염파·불꽃 장막·메테오·거대화염구·화염난사는 입력 직후 기존 시전·효과 자산으로 예상 연출을 시작합니다. 요청 번호로 서버의 투사체·낙하체·효과와 연결해 중복 표시를 줄이며, 거절·취소·연결 종료 시 예상 연출을 정리합니다. HP·MP·쿨타임·아이템·보상 확정은 서버가 담당합니다.

구매·판매·포션 사용에는 고유 행동 번호를 사용합니다. 서버는 캐릭터별 처리 기록을 소지금·아이템·세계 체크포인트와 같은 거래로 저장하고 저장 완료 후 응답합니다. 같은 번호의 재전송은 다시 실행하지 않으며 다른 내용으로 번호를 재사용하면 거절합니다. 기록은 24시간 유지하며 최대 1024건의 미만료 기록이 차면 새 거래를 제한합니다. 퇴장·재접속·서버 재시작 후에도 기록을 복원합니다.

클라이언트는 미확인 거래를 브라우저 저장소에 보관합니다. 복귀 시 결과를 먼저 조회하고, 미처리 요청만 같은 번호로 최대 1분 동안 재시도합니다. 오래된 요청은 자동 실행하지 않으며 공격 입력은 이 복구 큐에 넣지 않습니다.

## 연결 기록과 서버 송신 대기열

게임 메뉴의 **연결 기록 저장**은 최근 2분의 초당 요약, 최대 48개의 지연·접속 사건, 최근 끊김 직전 기록을 JSON으로 내려받습니다. 프레임 p95/p99·최대 시간, 웹소켓 왕복 응답·수신 간격·파싱/적용 시간, HTTP 응답 요약, 위치 보정 횟수와 함께 서버의 작업 대기·tick 간격/실행·상태 생성·저장 대기/commit·송신 대기·전송량을 기록합니다. 서버 상세 지표는 초당 최대 한 번 전달합니다. 계정·토큰·대화·아이템 목록·이동 입력은 이 기록에 넣지 않습니다. 콘솔에서는 `arcanaNetworkReport()`로 같은 보고서를 조회할 수 있습니다.

`outsideServerMs`는 왕복 응답에서 서버 처리와 송신 대기를 뺀 값으로, 네트워크와 클라이언트 수신 스케줄 지연을 함께 포함합니다. 서버 작업 시간도 비동기 대기를 포함한 경과 시간이며 CPU 사용 시간은 아닙니다. 최신 서버 지표의 수신 후 경과 시간도 함께 남겨 오래된 지표를 구분합니다.

행동 응답은 순서를 유지하는 별도 대기열로 보존하고 상태 전송보다 우선합니다. 세계 상태는 아직 보내지 않은 생성 작업 하나만 유지해 최신 작업으로 교체하며, 실제로 보낼 때 플레이어 변경분과 스킬 정의를 계산합니다. 전투 이벤트는 미전송분을 합쳐 보존합니다. 소켓에 이미 넘긴 데이터는 취소하지 않습니다. 대기열의 개수·바이트·최대 대기 시간과 미전송 이벤트 수에 상한을 두고, 상한을 넘으면 재접속으로 최신 확정 상태를 복원합니다. 송신 적체 경고는 간격을 두어 서버 로그에 남깁니다.

## 저장과 접근 경계

- `arcana_online_records`는 계정·공급자 식별자·세션·캐릭터·소유권·이름·세계 체크포인트·보상 기록을 종류와 ID로 구분합니다. DB 거래로 이름 중복·가입·계정 연결을 직렬화합니다.
- 활성 세계는 전용 PostgreSQL advisory lock을 유지합니다. 재배포로 이전 서버와 새 서버가 겹쳐도 두 세계가 동시에 실행되지 않습니다. 현재 버전의 운영 인스턴스 수는 1개로 유지합니다.
- 처치 기록, 세계 체크포인트와 캐릭터 보상은 같은 DB 트랜잭션에 기록합니다. 보상 키는 세계와 몬스터 생명주기를 포함합니다.
- 게임 ID는 접근 권한이 아닙니다. HTTP 조회·행동·저장·복구와 소켓 연결은 서버 세션과 소유권을 확인합니다. 온라인 캐릭터에는 기존 개인 전투 소켓·상태 월드 API·수동 저장 되돌리기를 허용하지 않습니다.
- 개발 제한을 적용하는 동안 입장부터 연결 종료 후 30초까지 임시 접속 인원에 포함합니다. 재접속 유예 중 캐릭터는 피해를 받을 수 있으며, 유예가 끝나면 저장하고 제거합니다. 명시적으로 홈으로 나가면 자리를 즉시 반환합니다.
- 이동·전투는 DB 응답을 기다리지 않습니다. 약 1초마다 불변 체크포인트를 별도 저장 큐에 넘기며 처치·패배·주요 행동은 즉시 큐에 등록합니다. 한 건을 저장하는 동안 대기 상태는 최신 체크포인트로 합치고 처치 기록과 퇴장 캐릭터의 저장은 유지합니다. 처치 기록·캐릭터 보상·세계 상태는 같은 DB 거래로 확정합니다.
- 수동 저장 성공 응답과 정상 종료는 저장 큐가 비워질 때까지 기다립니다. DB 지연이 5초를 넘거나 저장에 실패하면 추가 세계 진행을 중단합니다. 전투 화면의 즉시 결과는 DB 확정 전일 수 있으며 강제 종료 시 마지막 확정 체크포인트 이후의 진행이 유실될 수 있습니다.
- 긴 NPC 생성 요청은 세계 큐 밖에서 처리합니다. 완료 시 캐릭터의 최신 HP·MP·재사용 대기시간과 개인 진행을 병합해 다른 플레이어의 시간을 멈추지 않습니다.

다중 인스턴스 배포나 채널 증설에는 별도의 세계 라우팅과 프로세스 간 전달 계층이 필요합니다. 인원이 늘어도 하나의 논리적 세계를 유지하는 방향으로 영역별 상태 전송과 서버 작업 분산을 확장합니다. 채널이나 독립된 세계를 인원 증가의 기본 단위로 삼지 않습니다. 현재 세계 ID·캐릭터 ID·접속 ID는 분리되어 있으나, 다중 서버 동기화를 구현한 상태는 아닙니다.

## 기존 저장 이관과 운영

로그인 소유권이 확인되는 기존 카카오 수동 저장은 첫 인증 때 이관합니다. 이미 생성된 온라인 캐릭터는 덮어쓰지 않습니다. 두 계정을 연결하면서 캐릭터가 둘 다 발견되면 계정 화면에서 사용할 캐릭터를 선택합니다. 선택하지 않은 캐릭터는 보관하며 소지금·아이템·성장 수치를 합산하지 않습니다.

소유권이 없는 개발 저장은 운영자가 서버를 중지한 뒤 이관합니다. 먼저 대상 계정을 로그인으로 생성하고 내부 계정 UUID를 확인합니다.

```powershell
node scripts/arcana-migrate.cjs GAME_ID ACCOUNT_ID
```

대상 계정에 캐릭터가 이미 있다면 기본적으로 중단합니다. 기존 캐릭터를 보관하고 교체하려는 경우에만 `--replace-character`를 명시합니다. 다른 계정에 속한 저장은 이 명령으로 가져올 수 없습니다.

운영자로 로그인한 브라우저에서 `POST /api/arcana/admin`에 `{characterId, seconds}`를 보내면 퇴장시킵니다. `seconds:0`은 퇴장만 하고, 양수는 지정 시간 동안 입장을 제한합니다. 계정 UUID는 본인 `/api/auth/me`의 `user.id`에서 확인할 수 있습니다.

## 빌드와 직접 확인

아트 원본과 열린 편집기를 건드리지 않는 독립 빌드 경로를 제공합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build-arcana-online.ps1 -Publish
npm.cmd run build
```

첫 명령은 최신 맵에서 서버용 충돌·출입 데이터도 생성하고 Godot 웹 파일을 반영합니다. 두 번째 명령은 서버와 배포용 웹 사본을 만듭니다. 이미 만든 독립 빌드의 가져오기 캐시는 `-ExistingBuild <.runtime/godot/online-build-...>`로 재사용할 수 있습니다.

자동 테스트는 `tests/arcana-online.test.cjs`에 작성했으며 기본 실행하지 않습니다. 실행 요청 시 서버를 컴파일한 뒤 `node --test tests/arcana-online.test.cjs`로 대상 테스트만 실행합니다.

직접 확인할 핵심 항목은 다음과 같습니다.

1. 서로 다른 브라우저 프로필 네 개에서 방문자로 입장하고, 다섯 번째 입장이 개발용 임시 제한 안내를 받는지 확인합니다.
2. 함께 이동하고 상점·학교·층을 바꾸어 같은 공간의 플레이어만 표시되는지 확인합니다.
3. 같은 슬라임의 HP·공격·처치가 일치하며 마지막 타격자에게 돈 30이 한 번만 지급되는지 확인합니다.
4. 한 명이 메뉴·대화를 열거나 탭을 전환해도 다른 플레이어와 몬스터가 계속 움직이는지 확인합니다.
5. 접속을 끊었다가 30초 안에 복귀하고, 다른 기기에서는 명시적 이어받기를 선택하는지 확인합니다.
6. 로그인·이름 등록·다른 공급자 연결·기존 캐릭터 선택 후에도 개인 진행이 보존되는지 확인합니다.
7. 남의 게임 ID와 기존 개인 전투 URL로 접근해도 읽기·행동·보상이 거절되는지 확인합니다.

개발 모드를 끄면 접속 제한 필드가 `null`이 되고 인원 표시에 고정 정원이 없어지는지도 확인합니다. 접속자가 모두 나갔다 돌아와도 같은 세계와 진행이 유지되어야 합니다.

타입 검사와 웹 빌드 성공은 실제 다인 플레이·외부 OAuth·운영 DB 복구 확인을 대신하지 않습니다.

## 현재 개발 모드

사용자 요청에 따라 현재는 로그인 없이 입장과 이름 등록을 모두 허용합니다. `ARCANA_DEVELOPMENT_ACCESS=true`이며 Render Blueprint에도 같은 값을 지정했습니다. 로그인 버튼은 개발 화면에서 숨깁니다. 카카오·구글 구현과 계정 연결은 유지하며, 정식 등록 정책을 적용할 때 이 값을 `false`로 바꿉니다. 개발 모드에서도 브라우저별 세션·캐릭터 소유권·정원·이동·보상 검증은 그대로 적용하며 운영자 권한을 자동으로 주지 않습니다. 개발 방문자의 진행은 브라우저에 연결되므로 다른 기기와 자동 공유되지 않습니다.

## 저장·전송 개선 확인

통신 버전 3은 플레이어 변경분을 사용하므로 서버와 Godot 웹 산출물을 함께 반영한 뒤 새로고침합니다. 위치 확인 응답은 작은 접수 응답만 보내고, 변하지 않은 스킬 트리는 재생성·반복 전송하지 않습니다.

직접 확인 시 DB 응답이 느려도 이동·투사체·다른 플레이어의 동작이 진행되는지, 멀리 떨어지거나 다른 층으로 이동한 캐릭터가 사라졌다가 가까이 오면 다시 나타나는지 확인합니다. 재접속 후 유령 캐릭터나 중복 보상이 없어야 합니다. `tests/arcana-network.test.cjs`에는 느린 DB의 체크포인트 병합·처치 기록 보존·거리 이탈·변경 없는 프레임·재접속 기준 상태 사례를 준비했으며 기본 실행하지 않습니다. 실제 처리 가능 인원과 지연 개선 폭은 부하 측정 전 확정하지 않습니다.

## 건물 출입

건물 내부와 광장은 같은 `main` 세계의 장소이며 출입 시 세계 재입장·소켓 교체를 하지 않습니다. 행동 전 마지막 위치 입력을 확인한 뒤 출입구를 판정합니다. 서버는 실내외·층 이동마다 장소 변경 순번을 올리고, 변경 전 장소에서 늦게 도착한 좌표는 적용하지 않고 현재 장소와 도착 위치를 돌려줍니다. 클라이언트는 그 위치로 맞추며 대기 입력이 찬 경우를 접속 끊김으로 표시하지 않습니다. 문의 바깥 도착점도 문 방향을 따라 계산합니다.

## 모닥불·요리·허기 · 2026-11-02

온라인 캐릭터에 목재 30개를 한 번 지급합니다. 민물고기는 낚시로만 얻으며, 소지품의 제작 탭에서 목재 5개를 3초 동안 가공해 모닥불 1개를 만듭니다. 완성한 모닥불을 선택해 가까운 야외의 빈 땅에 배치하고, 가까이에서 상호작용하면 민물고기 1개를 생선구이로 굽습니다. 모닥불은 공용이며 별도 연료 소모·회수·연장은 없습니다.

제작(crafting)·요리(cooking)는 기본 습득 생활 스킬입니다. 완성당 XP 100, XP 100당 숙련도 1, 상한 100을 사용합니다. 완료 직전 숙련도로 보통·양호·우수 품질을 추첨합니다. 숙련도 0의 확률 85/14/1%에서 100의 10/40/50%로 선형 변화합니다. 모닥불은 품질 순서대로 30/45/60분 유지·굽기 6/4/3초이며, 생선구이는 허기 40/50/60을 회복합니다. 모닥불 품질은 굽기 속도에만 관여하고 생선구이 품질은 요리한 사람의 숙련도로 결정합니다.

허기는 100에서 시작하며 접속 중 30초마다 1씩 줄어듭니다. 접속하지 않은 동안은 줄지 않고 허기 0의 불이익은 없습니다. 생선구이는 HP·MP를 회복하지 않으며, 허기 100에서는 소비하지 않습니다. 기존 텍스트 게임의 생선구이 규칙은 유지합니다.

캐릭터의 arcanaLife에 허기·감소 누적 시간·목재 지급 표식을 저장하고, 기존 skillTraining에 두 스킬 경험치를 저장합니다. 세계 체크포인트의 campfires에는 품질별 아이템 ID·설치자·위치·절대 만료 시각을 저장합니다. 미완료 작업은 재시작 시 취소됩니다. 재료 소모·결과물·경험치 지급은 완료 순간 함께 처리하며 이동·전투·접속 해제·불 만료로 취소되면 소모하지 않습니다.

WebSocket 명령은 life_craft/life_place/life_cook/life_eat/life_cancel입니다. 기존 입력 순번 및 행동 ID 영수증을 재사용합니다. 실내·물·장애물·출입구·플레이어·다른 모닥불과 겹치는 설치는 서버에서 거절합니다. 기존 저장에는 기본값과 정적 아이템 카드를 보완하며 접속해도 목재 지급을 반복하지 않습니다. 표시 자산은 사용자 지시에 따라 기존 PixelFX fire/campfire를 재사용합니다.

직접 확인: 소지품 목재 최초 지급 → 제작 진행·취소·완성 → 설치 미리보기·배치 → 낚시로 민물고기 획득 → 모닥불에서 굽기 → 생선구이 먹기. 숙련도·품질별 성능, 다른 플레이어의 모닥불 사용, 재접속 후 허기·재고·만료 시각 보존을 함께 확인합니다. 자동 테스트와 브라우저 플레이는 별도 요청 시 진행합니다.
