# 아르카나 실시간 전투 통신

## 조사와 적용

2026-10-29 기준 공식 공개 자료를 참고했습니다.

| 자료 | 공개 방식 | 이번 적용 |
| --- | --- | --- |
| [Riot: VALORANT netcode](https://www.riotgames.com/en/news/peeking-valorants-netcode) | 로컬 입력 예측, 서버 판정과 보정 | 기존 발사·회피 예측을 유지하고, 동기화 응답을 기다리지 않고 다음 입력을 전송합니다. |
| [Roblox: Server authority](https://create.roblox.com/docs/projects/server-authority) | 서버를 상태 원본으로 유지하고 클라이언트에서 예측 후 차이를 보정 | 피해·MP·보상은 기존 서버 규칙으로 확정합니다. 미확인 주문의 MP를 로컬 예약하고 쿨타임이 있는 주문의 중복 입력을 제한합니다. 전체 물리 롤백·재시뮬레이션을 구현한 것은 아닙니다. |
| [Render: WebSockets](https://render.com/docs/websocket) | 같은 웹 서비스에서 WebSocket 지원, 연결 종료에 대비한 재연결 | 기존 Node 서비스의 같은 포트를 사용하며 HTTPS에서는 wss로 연결합니다. |
| [Godot 4.5: WebSocketPeer](https://docs.godotengine.org/en/4.5/classes/class_websocketpeer.html) | 매 프레임 poll하고 텍스트 프레임 송수신 | 전용 combat_socket.gd가 연결·요청 대응·타임아웃을 관리합니다. |

## 통신과 입력 처리

- `GET /api/games/:gameId/combat-ws`로 연결합니다. 서버의 `{ready:true, protocol:1}` 뒤 `{id, action}`을 보내며 응답은 `{id, result}`입니다. 공간 전투 입력만 허용하고 HTTP와 같은 GameService·게임별 잠금을 사용합니다.
- 클라이언트는 최대 4개 요청을 동시에 보낼 수 있습니다. 위치 동기화는 하나만 진행하고 대기 중인 위치 요청을 추가하지 않습니다. 공격·회피는 앞선 동기화의 응답을 기다리지 않습니다. 광장의 비전투 시계도 같은 소켓으로 1초 간격 동기화하여 첫 발사가 HTTP 시계 응답에 막히지 않게 합니다.
- 쿨타임이 있는 미확정 동일 주문은 중복 발사하지 않습니다. 쿨타임 0인 파이어볼은 응답을 기다리지 않고 연속 전송할 수 있습니다. MP 예약은 표시·입력 제한에만 사용합니다. 서버 수치가 최종 판정입니다.
- 입력 대기열은 최대 8개이며 전송 전 500ms를 넘긴 입력은 만료합니다. 순간이동의 기존 즉시 로컬 조작은 유지합니다.
- 서버는 수신 즉시 공용 게임별 잠금에 등록합니다. 재연결·HTTP 종료 요청이 이전 연결에서 이미 받은 입력을 추월하지 않게 합니다. 동일·이전 공간 입력 sequence는 기존 서비스가 중복 처리하지 않습니다.
- 서버 응답의 sequence가 적용한 상태보다 작으면 버립니다. 승패 종료 처리 중 후속 응답은 상태를 덮어쓰지 않습니다.
- 연결 실패 시 지수 백오프로 재연결하고 대기 입력을 지웁니다. 처리 여부가 불명확한 공격은 재전송하지 않으며, 일시정지 공간 동기화로 서버 상태를 확인한 뒤 입력을 재개합니다.
- 서버는 메시지 16KiB, 연결당 미완료 입력 8개, 응답 버퍼 1MiB를 제한하며 30초 ping/pong으로 끊긴 연결을 정리합니다. 브라우저 연결은 같은 Origin만 허용합니다. 게임 ID를 통한 접근 경계는 기존 HTTP API와 같습니다.
- 로그인·일반 행동·전투 종료 확인·저장 불러오기는 기존 HTTP 경로를 사용합니다. 기존 1초 주기 저장과 주요 행동 저장을 유지합니다.

## 직접 확인

서버를 새 코드로 빌드·재시작하고 새 웹 산출물로 게임을 여신 뒤 확인합니다.

1. 개발자 도구 Network에서 `combat-ws`의 101 연결과 Messages 입력·응답을 확인합니다. 공간 전투의 반복 actions POST는 없어야 합니다.
2. 슬라임과 싸우며 공격 직후 회피를 사용합니다. 서버 동기화 응답 때문에 회피 연출이 멈추지 않고, MP·쿨타임·보상이 서버 상태로 정리되어야 합니다.
3. 연결을 잠시 끊었다가 복구합니다. 과거 공격이 몰아서 재발사되지 않고 서버 상태 동기화 후 새 공격이 가능해야 합니다.
4. 적 처치 후 기존 사망 연출과 보상·자동 종료가 유지되어야 합니다.

WebSocket은 물리적인 왕복 지연이나 DB 저장 시간을 없애지 않습니다. PvP용 과거 판정 되감기, 고정 틱 전체 롤백, UDP 전송은 이번 범위에 포함하지 않습니다. 실제 왕복 지연·체감 개선 수치는 실행 측정 전에는 확정하지 않습니다.
