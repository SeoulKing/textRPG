# 개발 담당

아르카나의 실행 구조·게임 상태·서버·UI와 통합 기준을 이 문서에서 관리합니다. 작업 규칙과 검증 선택은 [AGENTS.md](../../AGENTS.md), 요청별 진입점은 [WORKFLOW.md](../WORKFLOW.md)를 따릅니다. Godot 구현·설계·문제 해결은 [프로젝트 전용 Godot 스킬](../../skills/godot-arcana-development/SKILL.md)을 먼저 읽고 필요한 항목만 적용합니다.

## 현재 구조와 완료 범위

- 본편은 [godot-arcana/project.godot](../../godot-arcana/project.godot) → [main.tscn](../../godot-arcana/main.tscn) → [scripts/main.gd](../../godot-arcana/scripts/main.gd)입니다. 현재 주인공은 **하이브리드 버전 1**이며 제작실도 본편 안에 둡니다. [캐릭터 역할 문서](CHARACTER_ART.md)의 확정 원본과 작업실을 사용합니다.
- 현재 월드·배치는 `scenes/native_2d/`, 상점은 `scenes/shop_2d.tscn`을 따라 실제 호출을 확인합니다. 과거 `pixel3d_world.gd`가 남아 있다는 사실만으로 기본 렌더러라고 추측하지 않습니다.
- 서버 시작은 `src/server.ts`, 공용 세계·계정·전투는 `src/online/`, 규칙·저장·기존 콘텐츠는 `src/game/`입니다. 클라이언트 그림과 서버의 이동·보상·퀘스트 판정을 구별합니다.
- 폐허 서울 텍스트 RPG·스튜디오는 [별도 프로젝트](../../../seoul-survival/README.md)입니다. 현재 아르카나가 사용하는 공용 엔진·스키마·콘텐츠 시드는 보존하며 다른 프로젝트 폴더에 의존하지 않습니다.

소스 수정·제작 산출물·게임 연결·웹 내보내기·서버 제공·공개 배포·실제 플레이 확인은 서로 다른 단계입니다. 현재 디자인 확정은 모든 동작과 기능의 시각 검수를 끝냈다는 뜻이 아닙니다. 요청 범위의 연결을 완수하고 미확인은 정확히 남깁니다.

## 설계와 제작 방향

먼저 출발·이동·방향 전환·정지와 발 접지·체중 이동이 자연스럽게 이어지도록 다듬고, 확정 주인공을 기준으로 월드를 꾸밉니다. 분수 광장이 대표 장면입니다. 프레임 수·구조 검사·버전 숫자만으로 자연스러움과 미술 완성을 판단하지 않습니다.

공통 카메라·픽셀 단위·재질·연결점·등록 규격으로 일관성을 제작 가능한 조건으로 만듭니다. 큰 자산은 같은 단위를 더 넓게 쓰고 자산마다 픽셀 크기를 바꾸지 않습니다. 인물·적은 강한 윤곽, 자연물은 재질 계열의 약한 경계, 바닥은 재질 면으로 읽히게 합니다. 외곽선·세부 규격은 [캐릭터](CHARACTER_ART.md)와 [월드](WORLD_BUILDING.md)의 역할 문서에서 관리하며 이곳에 다시 복제하지 않습니다.

기존 씬을 수정할 때 사용자 배치·Transform·ID·저장 상태를 보존합니다. 기능을 작은 책임으로 나누고 외부 의존성은 상위 노드가 명시적으로 전달합니다. JSON의 실제 필드·Variant 형식을 확인하고 공유 Resource를 인스턴스별 수정 전에 구분합니다. 생성 파일만 수정해 다음 출력에서 변경이 사라지게 하지 않습니다.

## 실행·빌드·문제 해결

[README](../../README.md)의 로컬 실행을 사용합니다. `.env`·`.env.local`은 유지하고 값을 출력하지 않습니다.

```powershell
npm run dev           # 기본 3000, /godot/
npm run build:server  # 서버 컴파일
npm run build         # 서버 컴파일 + 기존 Godot 웹 출력 패키징
npm start
```

`npm run build`는 Godot 소스를 내보내지 않습니다. Godot 변경의 웹 반영은 `scripts/build-godot-arcana.ps1`과 실제 `export_presets.cfg`를 따릅니다. 기존 엔진·호스팅·인증·저장을 임의로 초기화하지 않습니다. 도구·의존성 설치는 검증만을 이유로 추가하지 않습니다.

기본 확인은 수정 내용·참조와 필요한 구문 검사입니다. 별도 요청 없이 게임·테스트·브라우저를 실행하지 않습니다. 실패는 도구/대상/핵심 오류로 식별하고 전제가 바뀌었을 때만 한 번 재시도합니다. 정적 검사로 답을 얻었다면 같은 위험을 다루는 검사를 반복하지 않습니다.

구현별 상세 문서는 해당 기능을 수정할 때만 읽습니다: [온라인](../arcana-online.md), [전투 네트워크](../arcana-combat-network.md), [파이어볼 성장](../arcana-fireball-progression.md), [성능](../arcana-performance.md), [아이템](../ARCANA_ITEMS.md). 역할별 원칙과 기술 명세를 같은 파일에 계속 덧붙이지 않습니다.

## 화면과 아이콘 규격

기준 화면은 384×824, `canvas_items`·`expand`이며 창 비율을 고정하지 않습니다. 도트 월드는 최근접 정수 배율, HUD·한글은 읽기 좋은 별도 해상도를 유지합니다. 컨테이너의 배치와 사용자 Control 설정을 보존합니다.



### 아이템 썸네일 공통 규격

새 아이템을 추가할 때는 아이템 정의와 함께 해당 아이템의 썸네일도 제작하고 실제 소지품 화면에 연결합니다. 사용자 확정 규격은 **64×64픽셀 캔버스, 투명 배경 PNG, 사방 최소 8픽셀 투명 여백, 이진 알파(0/255)**입니다. 아이템의 이름·수량·장착 표시·프레임은 UI가 담당하며 이미지에 굽지 않습니다. 제한된 소재별 팔레트와 선명한 도트 윤곽을 사용하고, 현재 소지품의 40×40 최근접 표시에서도 종류가 구분되어야 합니다. 승인 레퍼런스가 있는 아이템은 실제 참조 이미지의 색을 추출하고, 실루엣·명암·소재 디테일을 보며 PixelPen 원본 픽셀로 옮겨 보정합니다. 단순 도형 조립이나 임의 팔레트로 참조의 질감을 대체하지 않습니다. 사용자님이 품질을 확인한 재사용 기준은 [레퍼런스 기반 음식 제작기](../../godot-arcana/tools/author_reference_food_icons.gd)와 [실행 스크립트](../../scripts/author-reference-food-icons.ps1)입니다. 실제 참조색 팔레트·소재별 픽셀 클러스터 보정·검정 1픽셀 윤곽·PixelPen 저장/재열기/PNG 출력·실제 크기와 확대본 확인을 한 흐름으로 사용합니다. 단순 축소만으로 완성하지 않으며, UI 클릭과 네이티브 API 제작 여부는 정확히 구분해 보고합니다. 사용자 지정 아이템 외곽선은 순수 검정(#000000) 1소스 픽셀 한 줄입니다. 인접한 어두운 띠로 외곽을 두껍게 만들지 않으며, 내부의 소재별 결·주름·구운 흔적은 색상 명암과 세부 도트로 표현합니다.

PixelPen 편집 원본(`art/source/items/.../*.pxpen`)을 보존하고 저장·재열기·PNG 출력으로 제작합니다. 게임용 PNG는 `art/export/items/`에 두고 `scripts/inventory_view.gd`의 `ITEM_TEXTURES`에 실제 아이템 ID를 등록합니다. 같은 외형의 품질 변형은 승인된 기본 썸네일을 공유할 수 있습니다. 새 외형이 필요한 경우 기존 컨셉 승인 절차를 따르며, 이미 승인한 외형은 다시 승인받지 않습니다. 수동 편집 원본을 재생성으로 덮어쓰지 않습니다.

첫 기준은 승인된 민물고기·생선구이·목재입니다. 컨셉은 `art-studies/item-thumbnails-v1/concept-v1.png`, 편집 원본과 실제 크기 비교는 `godot-arcana/art/source/items/inventory-v1/`, 재출력은 `scripts/author-item-thumbnails.ps1`을 사용합니다. 민물고기와 생선구이를 같은 낚시 아틀라스 조각으로 표시하지 않습니다.

### 스킬 아이콘 공통 규격

모든 스킬 아이콘은 64×64픽셀 캔버스의 투명 배경 PNG로 제작합니다(사용자 확정 2026-10-29). PixelPen 편집 원본도 64×64로 통일하고, 사방 최소 8픽셀 투명 여백과 이진 알파를 유지합니다. 퀵슬롯 표시 크기와 원본 제작 해상도를 혼동하지 않습니다. 불꽃탄·화염파·불꽃 장막에도 같은 규격을 적용합니다. 세 이미지의 공통 팔레트·도트 밀도·가장자리 8도트 여백을 맞추고, 각각 불덩이·부채꼴 불길·속이 빈 화염 보호막으로 실루엣을 구분합니다. 글자·숫자·별도 프레임을 넣지 않습니다. 퀵슬롯 썸네일은 사용자 요청(2026-10-29)에 따라 기존보다 50% 확대하여 화염 주문 48×48, 그 외 45×45로 56×56 버튼 중앙에 표시합니다. 슬롯 설정에는 32×32 최근접 표시를 사용하며 포션·다른 메뉴 아이콘은 기존 도형을 유지하며, 대시·텔레포트는 각 승인 PNG를 사용합니다.

편집 원본은 `godot-arcana/art/source/spells/*.json`의 팔레트 인덱스·64행 도트 레이어입니다. `node scripts/build-arcana-spell-art.cjs`는 기존 원본을 보존해 게임용 `art/export/spells/*.png`와 밝은/어두운 배경의 64·32도트 비교 `art/reference/spells/fire-spells.png`를 다시 출력합니다. 재출력 시 원본을 삭제하지 않습니다. 썸네일 원본 크기와 월드 이펙트의 실제 판정 범위는 별개입니다.

오른쪽 조작부는 [원신 모바일 플레이 화면](https://www.hoyolab.com/article/37885242)의 아이콘 우선순위와 가벼운 원형 경계를 참고합니다. 그림이나 버튼 자산을 복제하지 않고 Godot의 도형 그리기로 제작합니다.

- 주 행동은 76×76, 스킬은 56×56 터치 영역으로 두며 엄지 주변의 호로 배치합니다. 빈 슬롯은 같은 터치 영역 안에서 시각적인 원만 작게 표시합니다.
- 2026-10-28 HUD 밝기 개선 요청: 상아색 표면 #fffaf0, 남색 글자 #26364d, 보조 글자 #586779를 사용합니다. 상단 상태창과 하단 아이콘 메뉴는 여백·둥근 모서리·얇은 흰 테두리·작은 그림자로 배경과 분리합니다. 주 행동은 연한 하늘색과 파랑, 보조 스킬은 상아색과 스킬 고유색으로 구분합니다. 두꺼운 사각 패널을 조작 버튼마다 반복하지 않습니다.
- 아이콘을 먼저 읽게 하고 주 행동에만 짧은 이름을 붙입니다. 스킬 이름은 툴팁과 슬롯 편집에서 제공하며 포션 수량은 작은 보조 숫자로 표시합니다.
- 가상 조이스틱은 무채색 검정·회색의 반투명 원으로 표시합니다. 바탕은 검정 24%, 손잡이는 짙은 회색 48% 불투명도, 테두리는 옅은 회색 38~46%와 1px 선을 사용합니다. 누르는 동안만 나타나며 배경이 비칩니다. 파랑·금색·불투명 흰색 표면을 사용하지 않습니다.
- 쿨타임은 숫자 대신 줄어드는 외곽 링으로 표시합니다. 비활성 상태에서도 아이콘의 형태를 읽을 수 있도록 유지합니다. 키 힌트는 터치 화면에서는 숨깁니다.
- HUD 글꼴은 게임에 포함한 Noto Sans KR을 사용합니다. 본문은 Medium 500, 숫자·메뉴·제목·키 힌트는 SemiBold 600으로 구분하며 상단 장소명은 18px, 체력·마력·소지금은 16px입니다. 하단 메뉴는 아이콘만 표시합니다. 숫자는 고정 폭 기능(tnum)을 사용하고 보조 설명도 최소 12px로 둡니다. FontVariation에는 OpenType 태그의 정수 키를 사용합니다. SIL OFL 라이선스는 fonts/NotoSansKR-OFL.txt에 보관하고 웹 산출물에도 포함합니다.
- HP는 코럴 #df596c, MP는 파랑 #398bda의 28px 바로 표시하고 바 안에 흰색 숫자와 짙은 외곽선을 표시합니다. 상단 경험치·숙련도 바는 표시하지 않으며, 쿨타임은 흰 받침 위의 파란 링으로 구분합니다. 소지품 등 메뉴 본문에도 같은 밝은 표면과 짙은 글자를 적용합니다.
- 상단 상태창은 장소 한 줄과 HP·MP 각각 한 줄로 구성하고 ARCANA 문구와 소지금은 숨깁니다. 가로 화면에서는 왼쪽 위 12 논리 단위 여백에 폭 320 논리 단위로 표시하며, 세로 화면에서는 상단 중앙에 둡니다. 기존 Noto Sans KR과 Linear 필터를 사용하고 글자까지 확대되는 Control 배율은 적용하지 않습니다.
- 하단 탐색 메뉴는 아이콘만 있는 밝은 둥근 도크로 묶고 화면 폭에 맞춰 최대 480 논리 단위로 제한합니다. 게임 판정·단축키·슬롯 설정·다중 터치 처리 경로는 UI를 바꾸어도 유지합니다.
- 실제 UI의 오프라인 렌더는 `pwsh -File scripts/render-godot-pixel3d-art.ps1 -Hud`로 재출력합니다. `hud-mobile.png`, `hud-wide.png`와 hud-panel.png는 미리보기이며 서버에 연결된 플레이 검증을 대신하지 않습니다.


## 게임 동작과 상태 계약

### 개발자 전용 이동 가속
Godot 편집기/디버그 실행과 localhost·127.0.0.1 웹 미리보기에서 4번 퀵슬롯을 이동 가속에 사용합니다. 키보드 4 또는 슬롯 클릭으로 기본 속도와 3배 속도를 전환합니다. MP·쿨타임·서버 스킬 목록과 분리된 로컬 개발 도구이며 가속 상태는 저장하지 않습니다. 일반 호스트의 웹 배포에는 이 스킬을 노출하지 않습니다. 키보드·조이스틱·클릭 경로 이동에 같은 배율을 적용하고, 가속 중에도 이동을 짧은 구간으로 나눠 충돌을 지킵니다.

### 시작 화면
게임 진입·새로고침 때는 저장 위치와 상태를 복원하고 지도를 바로 보여줍니다. 저장된 전투 결과·대화·던전 상태만을 이유로 결과창이나 안내 팝업을 자동으로 다시 열지 않습니다. 초기 조작 안내 토스트와 화면 중앙 상시 상태 문구도 표시하지 않습니다. 서버 연결 실패처럼 복구에 사용자 행동이 필요한 화면은 유지하며, 사용자가 직접 상호작용해서 여는 대화·결과 화면은 사용할 수 있게 둡니다.

### 스킬 습득과 관리
바텀탭은 지도·소지품·의뢰·스킬·메뉴 순서입니다. 아르카나 일반 필드의 성장 원본은 노션 개인 페이지 ‘아르카나’ 아래의 ‘스킬·숙련도 체계 v0.2’입니다. 캐릭터 레벨·직업에 따른 성장과 주문 습득 제한을 제거하고, 기존 구현된 기본 주문은 무료로 직접 배웁니다. 새 모험은 파이어볼을 알고 액티브 첫 칸에 장착한 상태로 시작합니다. 액티브 6칸(주력 4+자유 2)·패시브 2칸은 시범 기준이며 주력/자유는 현재 같은 액티브를 허용합니다. 퀵슬롯 4개는 단축키이며 서버 장착 구성과 별개입니다. 기본 회피·포션은 전투 스킬 장착 칸을 쓰지 않고, 미장착 주문은 서버에서도 거절합니다. 전투(일시정지 포함)·비행 중 투사체·대화·던전 중 습득과 장착 변경은 막습니다. 기존 학습 목록·빈 장착 구성·쿨타임은 보존하고, 구 저장에서 학습 목록이 없으면 구 해금 기준으로 한 번 복원합니다.

시범 성장값: 숙련 경험치 100당 숙련도 1, 상한 100(경험치 10000). 유효 피해·실제 보호량 1당 경험치 1이며 초과 피해는 제외하고, 실제 회피 성공은 경험치 10입니다. 허공 발사·실패·단순 장착에는 지급하지 않습니다. 피해·보호량은 floor((10 + floor(숙련도/10) × 2) × 기존 계수)입니다. 파이어볼은 피해 5~15, MP 4·재사용 3초입니다. 일반 필드 HP 100·MP 30은 캐릭터 레벨과 분리합니다. 구 캐릭터 누적 경험치는 최초 이관 때 당시 학습한 주문에 균등 배분하고 1회 버전 표식을 남깁니다. 구 level/xp 필드는 호환용으로 보존하되 새 보상으로 증가시키지 않습니다. 패시브·전문화는 저장 확장 기반만 두고 실제 효과는 미정 상태로 유지합니다. 희귀·융합·생활 기획 예시를 임의로 사용 가능하게 만들지 않습니다.

파이어볼 사용 보완: 짧게 누르기/일반 발사는 사거리 안의 화면에 보이는 슬라임이 있으면 자동 조준하고, 없으면 주인공이 바라보는 방향으로 발사합니다. 드래그·길게 누르기의 직접 조준과 취소, MP·쿨타임 제한은 유지합니다. 시작 때 저장된 승리·패배 전투가 남아 있으면 finish로 종료 확인을 처리한 뒤 복원해 다음 발사를 막지 않게 합니다. 전투 진행 중 상태는 자동 종료하지 않습니다. 실제 사용자 저장을 변경하는 자동 전투 테스트는 실행하지 않았으며 Godot 컴파일·웹 빌드를 확인했습니다.

### 슬라임 처치 보상 표시
슬라임 처치 시 승리 결과창을 자동으로 열지 않습니다. 처치 보상은 마리당 슬라임의 점액질 1개이며 골드와 동전 연출은 지급하지 않습니다. 획득은 짧은 떠오르는 문구로 표시합니다. 실제 지급과 의뢰 집계는 서버에서 처치 시 한 번 수행하며 클라이언트 연출이 별도 지급 요청을 만들지 않습니다. 여관 주인 마르텐의 의뢰를 수락한 뒤 슬라임 10마리를 처치하고 돌아와 보고하면 10골드를 한 번 지급합니다. 점액질은 보고 시 소모하지 않습니다. 마나 포션 구매가는 개당 10골드, 판매가는 4골드입니다. 승리 상태의 종료 확인은 조용히 처리하고 패배 화면 정책과 분리합니다.

### 건물 자동 입장
기능이 연결된 건물은 문 앞의 좁은 접촉 영역에서 안쪽 이동 의도가 약 .12초 이어지면 기존 travel 경로로 자동 입장합니다. 문을 누른 클릭 이동은 문 앞까지 안내한 뒤 입장하며, 가로질러 지나가거나 서 있기만 해서는 들어가지 않습니다. 닫힌 패널·전투 진행·조준·비활성 페이지에서는 자동 입장을 시작하지 않고 동일한 문에 대한 중복 요청을 막습니다. 기존 E/상호작용 진입은 유지합니다. entrance_id가 있으나 entrance_enabled=false인 준비 중 문은 자동 진입 대상에서 제외합니다.

### 생활 스킬 · 강 낚시
기본 나무 낚싯대 1개를 기존·신규 캐릭터에 한 번 지급합니다. 소지품 → 장비의 생활 도구 슬롯에서 직접 장착한 뒤, 어느 강둑에서든 앞쪽의 강물을 바라보고 E/상호작용으로 낚시를 시작합니다. 서버는 보유·장착·전방 강물과 다리 제외 영역을 다시 판정합니다. 낚시는 기본 습득한 생활 스킬이며 전투 장착 칸과 MP를 쓰지 않습니다. 서버가 입질 대기·1.4초 챔질 기회·포획 판정을 진행합니다. Space/E 또는 터치 버튼을 누르면 포획 구간이 상승하고 떼면 하강하며, 움직이는 물고기를 구간 안에 유지해 포획 게이지를 채웁니다. 성공은 강물고기 1개와 숙련 경험치 25, 구간을 벗어난 누적 시간이 0.3초 미만인 완벽한 포획은 경험치 40입니다. 경험치 100당 숙련도 1, 상한 10000 경험치·숙련도 100이며 숙련도에 따라 포획 구간이 26%에서 최대 38%까지 넓어집니다. 실패·취소에는 경험치와 아이템을 지급하지 않습니다. 숙련도는 기존 skillTraining의 fishing 항목에, 물고기는 기존 inventory에 저장합니다. 진행 중 낚시는 저장·복구하지 않으며 연결 종료·전투·행동 불능 시 취소합니다. 스킬 → 생활 스킬 → 낚시에서 성장과 조작 설명을 확인합니다. 강물·다리의 원본은 scenes/native_2d/city_river_quarter.tscn이며 실제 타일에서 내보낸 online-layout.json의 fishing 영역을 서버가 사용합니다. 고정 낚시 지점 JSON은 더 이상 사용하지 않습니다. 장착은 flags.arcana_life_tool, 최초 지급은 flags.arcana_fishing_rod_received에 저장합니다. 전투·낚시·다른 생활 작업 중에는 장비 교체를 막습니다. 확정 하이브리드 캐릭터와 별도 도구 자산으로 낚시 상태를 표시하고, 오른쪽 조작창으로 인물과 찌의 가림을 줄입니다.
