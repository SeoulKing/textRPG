# 제작·요리 작업 실행 규칙

활동에 `activity: { kind: "craft" | "cook" | "build" }`를 붙이면 재료 투입 → 작업 시간 → 완성 순서로 처리한다. 효과 배열이 수량과 시간의 유일한 원본이며, 완료 후 지급할 아이템을 먼저 선언했어도 실행 시점은 작업이 끝난 뒤다.

## 처리와 실패

- 시작 전에 모든 재료 비용을 합산한다. 같은 재료를 두 줄에서 소비하면 두 비용을 합해 검사하며, 돈과 사용할 도구도 함께 확인한다. 하나라도 부족하면 아무 비용도 지불하지 않는다.
- 시작한 시도는 재료·돈·도구 사용 비용을 한 번 지불한다. 도구의 마지막 사용도 한 번의 완성된 작업을 수행할 수 있다. 작업 도중 중단되면 투입 재료와 시작 비용은 돌아오지 않는다.
- 이동·탐색과 같은 가상 시계가 흐르므로 다른 지역의 문·조명·채집지에도 같은 시간이 적용된다. 소비한 물건의 물리 엔티티도 작업 전에 정리한다.
- 작업 중 사망하거나 구조 시한을 놓치면 완성품·설비 플래그·완료 서술을 지급하지 않는다. 예를 들어 무전기 조립이 10일차 아침을 넘으면 신호 준비 완료로 판정하지 않는다.
- 명시적인 작업 정의가 없는 휴식·이동·기존 이야기 선택은 자신의 효과 순서를 유지한다. 확률 결과 속에 숨긴 입력 비용, 작업 중 지역 이동, 날짜 건너뛰기는 작업 정의 검증에서 거부한다.

## 상태와 요청

`activityRevision`은 시작한 작업마다 증가한다. 선택지에 붙여 보낸 같은 번호는 한 번만 실행할 수 있다. 서버는 현재 장면에 실제로 표시된 작업인지도 확인한다. 재전송·중복 클릭·작업을 마친 뒤 도착한 옛 요청은 재료와 시간을 다시 쓰지 않는다. 클라이언트는 번호만 바뀌어도 버튼의 요청을 갱신한다.

`lastActivity`에는 작업 ID·종류, 완료/중단, 시작 시각·계획 시간·실제 경과, 투입·완성 수량을 저장한다. 기존 저장은 번호 0과 기록 없음으로 보완하며, 새 기록을 저장하거나 읽는 것만으로 작업을 다시 실행하지 않는다.

기존 레시피에는 누락된 실행 메타데이터만 보완한다. Studio에서 편집한 수량·비용·작업 시간과 명시적인 `activity: null`은 보존한다. 새 ID의 레시피도 같은 규칙을 사용하며, 재료 상세 패널은 엔진이 합산한 실제 비용을 표시한다.

## 확인

관련 테스트는 `tests/activities.test.cjs`에 있다. 기본 레시피 12개, 중간 시계 이벤트에서 완성품 부재, 사망 중단, 구조 시한, 임의 레시피 ID와 합산 비용, 저장 이행과 Studio 보존, 동시 요청 및 새 작업 재실행을 검사한다. 클라이언트의 작업 번호 갱신은 `tests/scene-preparation.test.cjs`에서 확인한다. 별도 LLM 호출을 추가하지 않는다.

384×824 메모리 브라우저 세션에서 땔감을 두 번 제작했다. 실제 응답은 목재 4→2, 땔감 0→8, 경과 20분, 작업 번호 0→2였으며 재료 표시와 획득 칩도 일치했다. 대기 중에는 버튼이 잠겼고 완료 후 새 작업이 가능했다. 가로 넘침과 콘솔 오류는 없었다. 테스트용 기본 서사를 사용해 실제 Gemini 요청은 하지 않았다.

예전 레시피가 지역 이동 등 작업 계약에 맞지 않는 별도 효과로 편집돼 있었다면 실행 메타데이터를 강제로 붙이지 않는다. 그 효과를 보존하고, 명시적으로 작업 계약을 지정한 새 정의에는 검증 규칙을 적용한다.
## 제작·요리 결과를 본문에 연결

제작 완료 로그가 있어도 레시피 메뉴의 본문은 비어 있던 경로를 수정했다. 작업이 끝나면 실제로 실행된 완료 효과의 문장만 모아 `lastActivity.paragraphs`와 생성 시각에 저장하고 현재 본문으로 표시한다. `kind`에 따라 제작·요리·설비 작업·휴식 제목을 사용한다. 각 작업의 revision이 바뀌므로 같은 레시피를 다시 실행해도 실제 완료 장면이 새로 이어지며, 재조회에는 같은 장면을 유지한다.

- 제작·요리·설비 작업에는 종류에 맞는 짧은 속말을 기존 500ms 대기 연출 중 표시한다. 추가 LLM 호출 없이 작성된 콘텐츠와 실제 실행 결과를 사용한다.
- 완료 문장의 `당신은` 주어를 생략해 현재의 밀착 서술을 유지한다. 제작 결과 문장을 새로 창작하거나 실행하지 않은 무작위 분기를 표시하지 않는다.
- 중단되면 시작한 작업과 투입 비용, 미완성 상태만 표시한다. 완료 효과의 문장과 완성품은 나타나지 않는다.
- 음식 사용은 직전 요리 본문을 다시 붙이지 않는다. 다른 메뉴나 지역으로 떠나면 활동 본문의 표시를 종료하되 실제 작업 기록은 보존한다.
- 사용자 정의 레시피와 활동 메타데이터가 있는 지역 행동도 같은 처리 경로를 사용한다.

관련 검증은 `tests/activity-reading.test.cjs`, 기존 활동 실행 테스트와 클라이언트 대기 테스트에 있다. 테스트에서 실제 생성 요청은 차단한다.

384×824 인앱 브라우저의 한 격리 세션에서 땔감 제작·반복 제작·요리 진입·묽은 죽 완성을 확인했다. 실제 제작·요리 문장이 본문에 남고 수량 칩과 일치했다. 좁은 제작 버튼에서 속말이 화면 밖으로 나가던 문제를 줄바꿈으로 수정했으며, 제작·요리 모두 오른쪽 끝이 약 362px 안에 들어온다. 가로 넘침과 브라우저 오류는 없었다. 재료가 부족하면 실행 버튼을 비활성화하되 레시피의 재료·준비 방법은 계속 살펴볼 수 있다. 검증용 외부 생성 요청은 0회였다.

이 단계의 관련 테스트 39개가 통과했다. 별도로 현재 병원 탐색을 사용하는 10일 생존 경로 3개도 통과했다. TypeScript 빌드와 클라이언트 구문 검사를 마쳤다.
