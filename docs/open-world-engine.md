# 자유로운 텍스트 세계의 엔진과 플레이 흐름

## 지향점

이 게임의 핵심은 미리 정해진 이야기 분기를 따라가는 것보다, 장소와 사물의 상태를 읽고 도구와 자원을 사용해 자기 방법으로 살아가는 경험이다. 생존의 비용, 채집과 제작의 연결, 같은 문제를 푸는 여러 수단, 인물과 세계에 남는 결과를 하나의 상태 체계로 연결한다.

표현은 기존 1인칭 소설체와 3~5개 추천 선택을 유지한다. 플레이어가 다른 시도를 원할 때는 관찰 가능한 사물이나 소지품을 직접 고른다. 대상 목록을 확인하는 일에는 게임 시간이나 Gemini 호출을 쓰지 않는다.

## 공통 실행 경로

1. **세계:** 장소 그래프, 사물의 포함·지지·가림 관계, 소유, 조명, 잠금, 자원, 인물 상태를 저장한다.
2. **관찰:** 현재 빛과 시야, 거리, 열림, 이전 관찰을 적용한다. 알 수 없는 내용물은 클라이언트에 보내지 않는다.
3. **가능한 상호작용:** 사물·도구·대상·조건을 조합해 실제 실행 가능한 의도를 만든다. 실행 전에 같은 규칙으로 다시 검증한다.
4. **선택:** Director가 추천 3~5개를 고른다. `주변과 물건`에서는 추천에서 빠진 대상과 행동도 직접 고를 수 있다. 추천 순위는 권한 검사나 세계의 물리 규칙이 아니다.
5. **실행:** 접근·자세 변경·조작을 순서대로 처리한다. 시간·기력·도구 마모·재료 비용은 실제 동작에서 한 번만 계산한다. 발견과 수집, 중단 전·후를 구분한다.
6. **세계 반응:** 가상 시간이 다른 장소에도 전해진다. 옮긴 물건, 열린 문, 꺼진 빛과 사용한 자원은 자리를 떠나도 유지된다.
7. **서술:** 실제 사건과 관찰만 Gemini에 전달한다. 속말 다음에 검증된 문단부터 이어 쓰며, 실패해도 세계 결과는 되돌리거나 다시 실행하지 않는다.

## 이번 구현: 추천 밖의 행동도 실행 가능한 세계

- 역무실·편의점·일반 탐색 지역에서 전체 후보와 추천 결과를 별도로 제공한다.
- 저장 스냅샷의 `exploration`에는 현재 관찰 가능한 대상의 이름·배치·관찰 여부와 확정된 행동 ID만 보낸다. 숨은 컴포넌트·재고·보상은 보내지 않는다.
- `주변과 물건`을 열어 대상을 고르는 일은 UI 상태만 바꾼다. 실제 행동을 고르면 기존 `optionId + revision`과 스트리밍 실행 경로를 사용한다.
- 이미 지닌 물건을 손에 꺼내거나, 다른 보관함까지 다가가 넣거나, 열린 문을 닫거나, 사물을 옮기는 행동을 추천 순위와 무관하게 선택할 수 있다.
- 추천 선택은 현재 관심에 맞는 배치 하나만 보여 준다. 전체 상호작용 목록은 호환되는 목적지를 모두 보여 준다.

## 이어서 구현할 핵심 시스템

- [x] **도구와 재질에 따른 여러 해결법:** 열쇠·도구로 잠금장치 파손·힘을 쓰는 구조 파괴이 서로 다른 시간, 소음, 마모, 재사용 가능성을 갖는다. 방 ID별 예외문 대신 도구 기능과 대상 성질로 계산한다.
- [x] **채집 → 제작 → 세계 활용:** 기존 재료와 제작 도구를 물리적 세계의 행동에 연결한다. 새 도구로 탐색 방법이 늘어나고, 거점의 보관·작업 환경이 이후 생활에 영향을 준다.
- [x] **인물의 관찰과 기억:** 기존 인물이 실제 목격한 행동, 교환, 도움, 소유물 변화만 관계와 반응에 반영한다. LLM이 거래 결과나 호감도를 임의로 만들지 않는다.
- [x] **손상과 수리:** 재질·손상·수리가 관찰·보관·가림·통로와 가능한 행동에 반영된다. 기존 소지품을 수리 재료로 쓰며 같은 자원을 따로 복제하지 않는다.

## 완료를 입증할 플레이 흐름

- 추천에 없는 사물을 직접 선택하고 관찰·조작할 수 있다.
- 같은 장애물을 적어도 두 가지 실제 수단으로 해결하며 비용과 이후 상태가 달라진다.
- 실제 채집과 제작으로 얻은 도구가 다른 장소의 상호작용을 늘린다.
- 옮기거나 사용하거나 손상시킨 사물이 이동·재방문·저장 복원 뒤에도 같은 상태다.
- 인물이 목격한 행동과 교환 결과가 이후 반응에 연결된다.
- 중복 클릭·오래된 선택·부분 실패가 물건이나 보상을 복제하지 않는다.
- 모바일에서 추천 선택, 직접 대상 선택, 속말과 스트리밍 본문이 한 독서 흐름으로 이어진다.

현재 체크되지 않은 시스템은 구현 완료로 간주하지 않는다. 기능이 추가될 때마다 위 플레이 흐름을 실제 제공된 선택으로 검증한다.

## 이번 변경 검증

- 추천 외 목록에서 제공한 역무실·편의점 행동 70개를 저장 복원 후 실제 실행했다.
- 열쇠와 진압봉으로 같은 문을 열되, 진압봉에는 시간·기력·마모·소음과 잠금장치 파손이 남는다.
- 손도끼로 문을 여러 번 손상시키는 상태가 저장 복원 후 유지되며, 파괴된 문은 다시 닫을 수 없다.
- 상자를 파괴하면 내용물과 해체 재료가 드러나지만 수집은 별도 행동이다. 중복 파괴로 재료가 복제되지 않는다.
- 재질·도구 조건, 마지막 내구도 소진, 후보 계산의 상태 불변성을 자동 테스트로 확인했다.
## 채집한 재료와 세계의 손상 연결

- `structure.repair`는 필요한 재료, 작업 시간, 기력, 작업 묘사, 선택적 도구 기능과 소음을 정의한다. 규칙은 특정 사물 ID에 의존하지 않는다.
- 파손되면 직접 포함하거나 받치던 물건을 같은 장소의 옆자리로 옮긴다. 새 물건을 담거나 받칠 수 없고, 원래 물성은 복원을 위해 저장한다.
- 수리는 재료를 실제 차감해 구조 내구도와 원래 보관·받침·가림 기능을 복원한다. 바닥에 나온 내용물은 그 자리에 남고, 망가진 열쇠 잠금은 복원하지 않는다.
- 파손 횟수를 저장해 새로 재건한 구조의 해체 재료와 이전 해체 재료를 구별한다. 손상된 구조에 작업을 중복 제출하거나 파괴를 다시 실행해 재료를 복제할 수 없다.
- 기존 저장의 부서진 기본 상자는 내용물을 보존해 바닥으로 옮기고 원래 물성을 보완한다. 사용자 정의 사물은 저장된 원래 물성을 사용하며, 알 수 없는 물성을 임의로 만들어 수리하지 않는다.

검증: `text-world-repair.test.cjs`의 7개 테스트로 기능 복원, 재료 보존, 기존 저장 이행, 도구 소진, 소음, 사용자 정의 대상과 비용 검사를 확인했다. `crafted-world-route.test.cjs`는 새 게임에서 편의점 자재 수집 → 손도끼 제작 → 숲 벌목 → 역무실에서 손상·수리 → 지역 이동·재방문의 20개 행동을 실행한다. 이 경로는 재료나 시간을 주입하지 않으며, 서버가 제공한 행동과 기존 이동 API만 사용한다. 중복·오래된 수리 요청도 검사한다.

도구 제작·다른 장소에서의 활용·거점 보관과 작업 환경의 연결을 검증했다. 전체 목표 완료는 통합 플레이와 남은 상태 보존 경계까지 검토한 뒤 판단한다.
## 인물의 관찰과 물물교환

- 인물은 자신의 위치·조명·가림·소음 전파에 따라 목격하거나 들은 사건만 기억한다. 소리만 들었으면 행위자의 신원이나 숨은 물건을 안다고 처리하지 않는다.
- 자기 소유물을 가져가거나 손상시키는 일을 목격하면 관계와 반응에 남는다. 기억은 중복 사건을 건너뛰고 저장·재방문 뒤에도 유지한다.
- 선물과 물물교환은 엔진이 실제 플레이어 소지품과 NPC 재고를 변경한다. 슈미에게 물건을 나누면 관계 조건에 따라 배터리 교환이 열리며, 판매한 재고는 재방문으로 다시 생기지 않는다.
- LLM은 확정된 전달 결과 다음에 반응과 다음 답변을 한 번에 생성한다. 실제 수량 변화는 별도 결과 문단과 획득·소비 표시로 전달한다.
- 탐색 공간에 배치된 인물은 가까이 다가가 대화한 뒤 같은 공간으로 돌아온다. 지역 대화 선택도 저장된 인물 위치와 동일한 조건을 사용한다.

검증: `npc-world-memory.test.cjs`에서 시야·청취·소유·기억 이행을 확인하고, `npc-social-route.test.cjs`에서 새 게임의 18개 실제 행동으로 소음 발생 → 대화 → 선물 → 교환 → 재방문을 실행한다. 중복 요청과 오래된 선택에 의한 물건 복제, 탐색 안팎의 대화 위치도 검사한다. 역할 응답은 모의 생성으로 검증하며 실제 Gemini 호출은 추가하지 않는다.

## 거점의 보관과 작업 환경

- 거처의 기존 제작·요리·휴식 흐름을 유지하면서 살림 자리를 직접 탐색할 수 있다. 선택적 진입과 출구는 방 데이터의 `optionalEntry`로 정의하므로 다른 지역에도 같은 흐름을 적용할 수 있다.
- 뚜껑을 열어 둔 일반 보관함의, 직접 수집한 자재만 현지 제작 재료에 합친다. 닫힘·막힌 통로·어둠·타인 소유·미발견 재고는 자동으로 사용하지 않는다. 실제 도구는 소지해야 한다.
- 비용 전체를 먼저 검증하고 소지 재료부터 사용한다. 모자란 수량만 보관된 실물에서 차감하며, 남은 스택과 포함 관계는 보존한다. 재료 조회와 제작 목록 열기에는 생성 요청이 없다.
- 거처 작업대는 처음에는 파손되어 있다. 판자 2개·고철 2개·끈 1개와 작업 시간·기력을 써서 복원하면 일반 제작 시간이 20% 줄어든다. 작업 종류와 배율은 컴포넌트로 정하며, 파괴되거나 접근할 수 없으면 효과가 사라진다.
- 제작 화면은 사용 가능한 보관 수량과 작업대 효과를 표시한다. 결과 본문은 실제로 꺼내 쓴 재료와 작업대를 기록한다. 이미 가진 도구 때문에 제작할 수 없을 때는 '이미 보유'로 표시한다.
- 보관하는 도구마다 내구도를 함께 저장한다. 새 도구를 제작해도 이전 도구의 마모는 유지되고, 하나가 파손되어도 다른 도구를 함께 삭제하지 않는다. 도구 변경·보관과 실제 마모를 시스템 노트에서 구분한다.

검증: `shelter-work-route.test.cjs`의 23개 실제 행동으로 수집 → 작업대 복원 → 보관 → 칼 제작(20분 → 16분) → 이동 → 재방문·잔여 물건 회수를 확인했다. 자원과 시간을 주입하지 않았으며, 중복 요청·저장 복원·보관 재료 차감도 확인한다. `work-environment.test.cjs`는 닫힌 보관함·다른 장소·소유·어둠·재료 부족·개별 도구 마모 경계를 검사한다. 384×824 브라우저에서 보관 수량 표시, 같은 본문의 속말과 제작 결과 연결, 가로 넘침 없음과 콘솔 오류 없음을 확인했다. 브라우저는 모의 상태를 사용하며, 실제 자원 획득 경로는 별도 서비스 테스트에서 검증한다. Gemini 호출은 추가하지 않았다.

## 통합 플레이와 남은 범위 검토

`open-world-journey.test.cjs`는 새 게임에서 제공된 47개 행동을 이어 실행한다. 편의점 수집 → 역무실 상자 이동 → 슈미에게 물건 나눔·유한 재고 교환 → 거처 작업대 복원·자재 보관 → 보관 재료로 칼 제작 → 숲에서 사용 → 칼 보관 → NPC 재방문 → 잔여 자재·칼 회수까지 자원과 시간을 주입하지 않는다. 매 저장에서 JSONB처럼 객체 키를 재정렬하고 실제 저장 정규화를 거쳐, 세계 배치·교환 재고·보관 수량·개별 내구도·관찰 기억이 함께 유지되는 것을 검사한다.

| 실제 생성문의 사실 충실도 | 아래 실제 작업대 응답 검토에서 누락과 근거 없는 촉감을 발견해 검사 보완 | 계속 검토 필요 |
| 현재 게임의 모든 탐색 장소가 같은 사물 탐색 흐름을 사용 | 급식소·검문소·역무실 신호함을 공통 탐색에 연결했다. 대합실과 지하층 탐사 진입의 기존 경계는 유지한다 | 미완료 |

핵심 엔진이 갖춰졌다는 이유만으로 전체 목표를 완료 처리하지 않는다. 급식소·검문소의 기존 내용과 비용·보상·퀘스트를 공통 공간 탐색에 연결하고 10일 생존 경로까지 확인했다. 역무실 신호함도 같은 탐색에 연결했다. 대합실·지하층 탐사의 기존 경계와 실제 생성문의 읽기 경험은 계속 검토한다.

## 직접 선택의 독서 흐름과 실제 서술 검토

- `주변과 물건`에서 실행할 행동을 고르면 그 행동을 본문의 선택지 자리에 옮긴 뒤 공통 대기 연출을 사용한다. 선택지의 속말은 본문에 표시하고, 채움은 1초 동안 한 번 진행한 뒤 유지한다. 빠른 응답을 채움 종료까지 붙잡는 별도 지연은 추가하지 않는다.
- 384×824 인앱 브라우저의 한 세션에서 추천에 없던 '보관함으로 다가간다'를 선택했다. 대기 중 선택한 행 하나만 표시되고 입력이 잠겼으며, 응답 전후 속말 문단의 화면 위치가 유지된 채 결과가 그 아래 이어졌다. 결과 후 추천 3개가 복구됐고, 가로 넘침·콘솔 오류가 없었다. 이 UI 검증은 외부 요청을 차단한 모의 서버를 사용했다.
- 실제 Gemini 검증은 새 게임의 8개 행동으로 자재를 수집하고 작업대를 복원하는 장면 하나에만 사용했다. `gemini-3.5-flash-lite` 한 호출에서 첫 문단 1.274초, 생성 2.379초, 행동 전체 2.437초를 기록했다. 평균이나 보장 시간이 아닌 단일 표본이다.
- 이 실제 문장은 '거친 결'과 '매끄러운 표면'을 현재 관찰 근거 없이 추가했고, 복원한 작업대의 제작 시간 감소 효과를 전달하지 않았다. 당시에는 사실 ID 검사만 통과했으므로, 이 결과를 충실한 서술 성공 사례로 간주하지 않는다.
- 감각이 없는 장면에도 감각을 넣도록 읽히던 지침을 수정했다. 관찰에 없는 표면 질감과, 사용 효과가 빠지거나 감소율이 잘못된 필수 작업대 설명을 검사한다. 이미 검증된 문단은 유지하면서 잘못된 부분만 기본 서술로 마무리하며 생성 재시도는 하지 않는다. 이 검사는 알려진 오류를 다루며 모든 자연어 의미를 증명하는 장치는 아니다.
- `narration-grounding.test.cjs`와 기록된 장면 fixture로 실제 실패 문장을 재현하고, 근거 있는 감각 표현·잘못된 효과 수치·부분 스트림 복구·다른 작업 종류의 기본 서술을 확인했다. 관련 서술·스트리밍·역무실 테스트 39개와 빌드가 통과했다. 수정 후 실제 Gemini 재호출은 하지 않았다.

## 급식소·검문소의 공통 탐색 전환

- `civic-definitions.ts`가 급식소의 배식대·노파·폐자재 더미·식재료 상자, 검문소의 통신 차량·무전 기록·초소 주변을 고정 공간에 배치한다. 실제 미수집 재고는 기존 원장으로부터 투영하며 입장 시 내용물을 공개하지 않는다. 상자나 차량을 살핀 뒤 수집을 따로 선택한다.
- 배식대의 구매·배급표 교환·품삯, 노파의 통조림 전달, 무전 기록 확인·정찰은 공통 `interactionPoint`에서 기존 행동을 한 번 실행한다. 날짜에 따른 가격, 일일 업무 조건, 퀘스트 보상, 선택된 정찰 분기의 보상·부상과 중단 결과를 그대로 따른다.
- 거래는 별도 의미 계열로 묶어 추천에서 구매와 교환을 함께 나열하지 않는다. 전체 목록에는 조건을 만족하는 두 방법 모두 남는다. 배식대 접근을 입장 추천에 포함하며, 공개된 배식 서비스는 접근 직후 사용할 수 있다. 기록을 해독하는 것처럼 조사가 필요한 지점은 기존 관찰 조건을 유지한다.
- 노파는 배식대 옆 실제 인물로 배치된다. 가까이 다가가 대화한 뒤 같은 위치·자세로 돌아온다. 원래 지역 행동 ID로 탐색 조건을 우회하는 요청은 거절한다.
- 식재료 상자는 같은 방에서 밀어 옮길 수 있으며, 내용물과 재고 원장은 함께 유지된다. 배식대는 소유한 물건을 올려놓고 다시 챙길 수 있는 받침이다. 재고 보관함을 통째로 휴대하는 것은 계속 금지한다. `PUSH`는 같은 방 바닥에서 옆자리·통로 앞 관계만 허용하므로 재고를 다른 지역 소지품으로 넘기지 않는다.
- 기존 저장의 발견·부분 수집·관심 대상은 새 세계로 이행하고, 소진한 더미는 재방문으로 다시 생기지 않는다. 이미 작성한 방은 기본 방보다 우선하며 편집한 배치·재고 수량·행동 역할도 게시와 저장된 콘텐츠 버전에서 유지한다.

검증:

- `civic-text-world.test.cjs` 20개: 비공개 내용물, 실제 비용·보상 비교, 거래 조건, 퀘스트, 정찰 4분기, 작업 중 사망, 저장 이행, 게시된 편집값, 실제 NPC 대화 복귀, 기존 행동 우회 방지, 상자 이동·물건 놓기·재수집. `choice-director.test.cjs`의 기존 8개도 통과했다.
- `survival-ten-days.test.cjs`: 새로 제공된 선택과 지도·아이템 API만 사용한다. 자원과 시간을 주입하지 않는다. 낚시 실패 경로는 185개 행동(구매 6회·품삯 작업 4회), 성공 경로는 327개 행동(생선 72개·구매 없음)으로 10일에 도달했다. 식사를 하지 않고 휴식만 반복하면 3일차에 탈진으로 끝나는 대조 경로도 유지됐다.
- 병원의 기존 14개 회귀 검사를 확인했다. 숨은 금액 `275` 검사는 선택지 해시에 우연히 들어간 숫자를 오인하지 않도록 실제 사실과 표시 문구를 대상으로 고쳤다.
- 한 브라우저 검증 세션에서 배식대의 식사 구매·금액과 획득 표시, 지도 이동, 검문소 입장 → 차량 발견 → 별도 수집을 확인했다. 새 탭의 기본 크기를 다시 맞춘 뒤 검문소 흐름을 384×824로 실측했고, 가로 넘침·콘솔 오류가 없었다. 이후 공개 서비스의 접근 조건과 상자 물성 보완은 서비스·물리 테스트로 확인했다. 브라우저와 자동 테스트는 외부 생성 요청을 차단했으며 이번 전환에서 실제 Gemini 호출은 사용하지 않았다.
- 최종 빌드, 런타임 콘텐츠 검증, 변경 공백 검사 통과. 로컬 서버를 새 빌드로 재시작했다.

## 역무실 신호함 연결

기존 콘텐츠의 신호함은 역무실 벽면에 배치하고, 역무실의 단일 `textWorld`에서 다른 사물과 함께 접근·개방·수집한다. 개방 전에는 내용물을 공개하지 않으며 발견과 묶음 수집은 별도 선택이다. 안테나·고철·물의 수량과 각 수집의 시간·상태 비용은 기존 재고 규칙을 그대로 실행한다. 자세 변경 등 실제 준비 동작의 시간은 추가로 계산한다.

기존 신호함 메뉴는 노출과 직접 실행을 함께 차단한다. 예전 메뉴에서 저장한 게임은 이미 확인한 내용과 남은 재고를 보존해 신호함 앞으로 이행한다. 기존 역무실 저장에는 없는 재고 사물만 보완하고, 문·배치·수집 결과를 초기화하지 않는다. 이행과 일반 재조회에는 생성 API를 호출하지 않는다. Studio의 별도 배치와 삭제한 재고 정의도 존중한다. 콘텐츠 기본값 모듈은 실행 규칙에 의존하지 않아 서버의 모듈 로드 순서에 영향을 받지 않는다.

`subway-stock-world.test.cjs`는 발견과 별도 수집, 기존 비용과 준비 시간, 중복 실행 거부, 부분 수집 저장 이행, 기존 역무실 보존, Studio 우선권, JSONB 복원 후 선택지, 기존 메뉴 우회 차단과 대합실 복귀를 검사한다. 10일 생존 경로도 서버가 제시하는 역무실 입장 → 신호함 확인 → 묶음 수집 → 대합실 복귀로 변경했다. 이 연결은 API·엔진 테스트로 검증하며, 추가 실제 Gemini 호출과 브라우저 검증은 수행하지 않았다.
