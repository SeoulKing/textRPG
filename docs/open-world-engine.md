# 자유로운 텍스트 세계의 엔진과 플레이 흐름

## 지향점

이 게임의 핵심은 미리 정해진 이야기 분기를 따라가는 것보다, 장소와 사물의 상태를 읽고 도구와 자원을 사용해 자기 방법으로 살아가는 경험이다. 생존의 비용, 채집과 제작의 연결, 같은 문제를 푸는 여러 수단, 인물과 세계에 남는 결과를 하나의 상태 체계로 연결한다.

표현은 기존 1인칭 소설체와 3~5개 추천 선택을 유지한다. 플레이어가 다른 시도를 원할 때는 관찰 가능한 사물이나 소지품을 직접 고른다. 대상 목록을 확인하는 일에는 게임 시간이나 Gemini 호출을 쓰지 않는다.

## 공통 실행 경로

1. **세계:** 장소 그래프, 사물의 포함·지지·가림 관계, 소유, 조명, 잠금, 자원, 인물 상태를 저장한다.
2. **관찰:** 현재 빛과 시야, 거리, 열림, 이전 관찰을 적용한다. 알 수 없는 내용물은 클라이언트에 보내지 않는다.
3. **가능한 상호작용:** 사물·도구·대상·조건을 조합해 실제 실행 가능한 의도를 만든다. 실행 전에 같은 규칙으로 다시 검증한다.
4. **선택:** Director가 추천 3~5개를 고른다. `주변과 물건`에서는 추천에서 빠진 대상과 행동도 직접 고를 수 있다. 추천 순위는 권한 검사나 세계의 물리 규칙이 아니다.
5. **실행:** 접근·자세 변경·조작을 순서대로 처리한다. 시간·기력·도구 마모·재료 비용은 실제 동작에서 한 번만 계산한다. 발견과 수집, 중단 전·후를 구분한다.
6. **세계 반응:** 가상 시간이 다른 장소에도 전해진다. 옮긴 물건, 열린 문, 꺼진 빛과 사용한 자원은 자리를 떠나도 유지된다.
7. **서술:** 실제 사건과 관찰만 Gemini에 전달한다. 속말 다음에 검증된 문단부터 이어 쓰며, 실패해도 세계 결과는 되돌리거나 다시 실행하지 않는다.

## 이번 구현: 추천 밖의 행동도 실행 가능한 세계

- 역무실·편의점·일반 탐색 지역에서 전체 후보와 추천 결과를 별도로 제공한다.
- 저장 스냅샷의 `exploration`에는 현재 관찰 가능한 대상의 이름·배치·관찰 여부와 확정된 행동 ID만 보낸다. 숨은 컴포넌트·재고·보상은 보내지 않는다.
- `주변과 물건`을 열어 대상을 고르는 일은 UI 상태만 바꾼다. 실제 행동을 고르면 기존 `optionId + revision`과 스트리밍 실행 경로를 사용한다.
- 이미 지닌 물건을 손에 꺼내거나, 다른 보관함까지 다가가 넣거나, 열린 문을 닫거나, 사물을 옮기는 행동을 추천 순위와 무관하게 선택할 수 있다.
- 추천 선택은 현재 관심에 맞는 배치 하나만 보여 준다. 전체 상호작용 목록은 호환되는 목적지를 모두 보여 준다.

## 이어서 구현할 핵심 시스템

- [x] **도구와 재질에 따른 여러 해결법:** 열쇠·도구로 잠금장치 파손·힘을 쓰는 구조 파괴이 서로 다른 시간, 소음, 마모, 재사용 가능성을 갖는다. 방 ID별 예외문 대신 도구 기능과 대상 성질로 계산한다.
- [x] **채집 → 제작 → 세계 활용:** 기존 재료와 제작 도구를 물리적 세계의 행동에 연결한다. 새 도구로 탐색 방법이 늘어나고, 거점의 보관·작업 환경이 이후 생활에 영향을 준다.
- [x] **인물의 관찰과 기억:** 기존 인물이 실제 목격한 행동, 교환, 도움, 소유물 변화만 관계와 반응에 반영한다. LLM이 거래 결과나 호감도를 임의로 만들지 않는다.
- [x] **손상과 수리:** 재질·손상·수리가 관찰·보관·가림·통로와 가능한 행동에 반영된다. 기존 소지품을 수리 재료로 쓰며 같은 자원을 따로 복제하지 않는다.

## 완료를 입증할 플레이 흐름

- 추천에 없는 사물을 직접 선택하고 관찰·조작할 수 있다.
- 같은 장애물을 적어도 두 가지 실제 수단으로 해결하며 비용과 이후 상태가 달라진다.
- 실제 채집과 제작으로 얻은 도구가 다른 장소의 상호작용을 늘린다.
- 옮기거나 사용하거나 손상시킨 사물이 이동·재방문·저장 복원 뒤에도 같은 상태다.
- 인물이 목격한 행동과 교환 결과가 이후 반응에 연결된다.
- 중복 클릭·오래된 선택·부분 실패가 물건이나 보상을 복제하지 않는다.
- 모바일에서 추천 선택, 직접 대상 선택, 속말과 스트리밍 본문이 한 독서 흐름으로 이어진다.

현재 체크되지 않은 시스템은 구현 완료로 간주하지 않는다. 기능이 추가될 때마다 위 플레이 흐름을 실제 제공된 선택으로 검증한다.

## 이번 변경 검증

- 추천 외 목록에서 제공한 역무실·편의점 행동 70개를 저장 복원 후 실제 실행했다.
- 열쇠와 진압봉으로 같은 문을 열되, 진압봉에는 시간·기력·마모·소음과 잠금장치 파손이 남는다.
- 손도끼로 문을 여러 번 손상시키는 상태가 저장 복원 후 유지되며, 파괴된 문은 다시 닫을 수 없다.
- 상자를 파괴하면 내용물과 해체 재료가 드러나지만 수집은 별도 행동이다. 중복 파괴로 재료가 복제되지 않는다.
- 재질·도구 조건, 마지막 내구도 소진, 후보 계산의 상태 불변성을 자동 테스트로 확인했다.
## 채집한 재료와 세계의 손상 연결

- `structure.repair`는 필요한 재료, 작업 시간, 기력, 작업 묘사, 선택적 도구 기능과 소음을 정의한다. 규칙은 특정 사물 ID에 의존하지 않는다.
- 파손되면 직접 포함하거나 받치던 물건을 같은 장소의 옆자리로 옮긴다. 새 물건을 담거나 받칠 수 없고, 원래 물성은 복원을 위해 저장한다.
- 수리는 재료를 실제 차감해 구조 내구도와 원래 보관·받침·가림 기능을 복원한다. 바닥에 나온 내용물은 그 자리에 남고, 망가진 열쇠 잠금은 복원하지 않는다.
- 파손 횟수를 저장해 새로 재건한 구조의 해체 재료와 이전 해체 재료를 구별한다. 손상된 구조에 작업을 중복 제출하거나 파괴를 다시 실행해 재료를 복제할 수 없다.
- 기존 저장의 부서진 기본 상자는 내용물을 보존해 바닥으로 옮기고 원래 물성을 보완한다. 사용자 정의 사물은 저장된 원래 물성을 사용하며, 알 수 없는 물성을 임의로 만들어 수리하지 않는다.

검증: `text-world-repair.test.cjs`의 7개 테스트로 기능 복원, 재료 보존, 기존 저장 이행, 도구 소진, 소음, 사용자 정의 대상과 비용 검사를 확인했다. `crafted-world-route.test.cjs`는 새 게임에서 편의점 자재 수집 → 손도끼 제작 → 숲 벌목 → 역무실에서 손상·수리 → 지역 이동·재방문의 20개 행동을 실행한다. 이 경로는 재료나 시간을 주입하지 않으며, 서버가 제공한 행동과 기존 이동 API만 사용한다. 중복·오래된 수리 요청도 검사한다.

도구 제작·다른 장소에서의 활용·거점 보관과 작업 환경의 연결을 검증했다. 전체 목표 완료는 통합 플레이와 남은 상태 보존 경계까지 검토한 뒤 판단한다.
## 인물의 관찰과 물물교환

- 인물은 자신의 위치·조명·가림·소음 전파에 따라 목격하거나 들은 사건만 기억한다. 소리만 들었으면 행위자의 신원이나 숨은 물건을 안다고 처리하지 않는다.
- 자기 소유물을 가져가거나 손상시키는 일을 목격하면 관계와 반응에 남는다. 기억은 중복 사건을 건너뛰고 저장·재방문 뒤에도 유지한다.
- 선물과 물물교환은 엔진이 실제 플레이어 소지품과 NPC 재고를 변경한다. 슈미에게 물건을 나누면 관계 조건에 따라 배터리 교환이 열리며, 판매한 재고는 재방문으로 다시 생기지 않는다.
- LLM은 확정된 전달 결과 다음에 반응과 다음 답변을 한 번에 생성한다. 실제 수량 변화는 별도 결과 문단과 획득·소비 표시로 전달한다.
- 탐색 공간에 배치된 인물은 가까이 다가가 대화한 뒤 같은 공간으로 돌아온다. 지역 대화 선택도 저장된 인물 위치와 동일한 조건을 사용한다.

검증: `npc-world-memory.test.cjs`에서 시야·청취·소유·기억 이행을 확인하고, `npc-social-route.test.cjs`에서 새 게임의 19개 실제 행동으로 소음 발생 → 대화 → 선물 → 교환 → 재방문을 실행한다. 중복 요청과 오래된 선택에 의한 물건 복제, 탐색 안팎의 대화 위치도 검사한다. 역할 응답은 모의 생성으로 검증하며 실제 Gemini 호출은 추가하지 않는다.

## 거점의 보관과 작업 환경

- 거처의 기존 제작·요리·휴식 흐름을 유지하면서 살림 자리를 직접 탐색할 수 있다. 선택적 진입과 출구는 방 데이터의 `optionalEntry`로 정의하므로 다른 지역에도 같은 흐름을 적용할 수 있다.
- 뚜껑을 열어 둔 일반 보관함의, 직접 수집한 자재만 현지 제작 재료에 합친다. 닫힘·막힌 통로·어둠·타인 소유·미발견 재고는 자동으로 사용하지 않는다. 실제 도구는 소지해야 한다.
- 비용 전체를 먼저 검증하고 소지 재료부터 사용한다. 모자란 수량만 보관된 실물에서 차감하며, 남은 스택과 포함 관계는 보존한다. 재료 조회와 제작 목록 열기에는 생성 요청이 없다.
- 거처 작업대는 처음에는 파손되어 있다. 판자 2개·고철 2개·끈 1개와 작업 시간·기력을 써서 복원하면 일반 제작 시간이 20% 줄어든다. 작업 종류와 배율은 컴포넌트로 정하며, 파괴되거나 접근할 수 없으면 효과가 사라진다.
- 제작 화면은 사용 가능한 보관 수량과 작업대 효과를 표시한다. 결과 본문은 실제로 꺼내 쓴 재료와 작업대를 기록한다. 이미 가진 도구 때문에 제작할 수 없을 때는 '이미 보유'로 표시한다.
- 보관하는 도구마다 내구도를 함께 저장한다. 새 도구를 제작해도 이전 도구의 마모는 유지되고, 하나가 파손되어도 다른 도구를 함께 삭제하지 않는다. 도구 변경·보관과 실제 마모를 시스템 노트에서 구분한다.

검증: `shelter-work-route.test.cjs`의 23개 실제 행동으로 수집 → 작업대 복원 → 보관 → 칼 제작(20분 → 16분) → 이동 → 재방문·잔여 물건 회수를 확인했다. 자원과 시간을 주입하지 않았으며, 중복 요청·저장 복원·보관 재료 차감도 확인한다. `work-environment.test.cjs`는 닫힌 보관함·다른 장소·소유·어둠·재료 부족·개별 도구 마모 경계를 검사한다. 384×824 브라우저에서 보관 수량 표시, 같은 본문의 속말과 제작 결과 연결, 가로 넘침 없음과 콘솔 오류 없음을 확인했다. 브라우저는 모의 상태를 사용하며, 실제 자원 획득 경로는 별도 서비스 테스트에서 검증한다. Gemini 호출은 추가하지 않았다.

## 통합 플레이와 남은 범위 검토

`open-world-journey.test.cjs`는 새 게임에서 제공된 49개 행동을 이어 실행한다. 편의점 수집 → 역무실 상자 이동 → 슈미에게 물건 나눔·유한 재고 교환 → 거처 작업대 복원·자재 보관 → 보관 재료로 칼 제작 → 숲에서 사용 → 칼 보관 → NPC 재방문 → 잔여 자재·칼 회수까지 자원과 시간을 주입하지 않는다. 매 저장에서 JSONB처럼 객체 키를 재정렬하고 실제 저장 정규화를 거쳐, 세계 배치·교환 재고·보관 수량·개별 내구도·관찰 기억이 함께 유지되는 것을 검사한다.

| 현재 게임의 모든 탐색 장소가 같은 사물 탐색 흐름을 사용 | 대합실과 지하층의 전투·수색·수집을 공통 세계에 연결했다. 후속 검증 범위는 아래 각 구현 항목에 기록한다 | 연결 구현, 전체 경로 최종 검토 필요 |

핵심 엔진이 갖춰졌다는 이유만으로 전체 목표를 완료 처리하지 않는다. 급식소·검문소의 기존 내용과 비용·보상·퀘스트를 공통 공간 탐색에 연결하고 10일 생존 경로까지 확인했다. 역무실 신호함도 같은 탐색에 연결했다. 대합실과 탐사 진입 경계도 연결했다. 지하층 내부도 공통 세계에 연결했으며, 전체 통합 경로와 실제 생성문의 읽기 경험은 계속 검토한다.

## 직접 선택의 독서 흐름과 실제 서술 검토

- `주변과 물건`에서 실행할 행동을 고르면 그 행동을 본문의 선택지 자리에 옮긴 뒤 공통 대기 연출을 사용한다. 선택지의 속말은 본문에 표시하고, 채움은 1초 동안 한 번 진행한 뒤 유지한다. 빠른 응답을 채움 종료까지 붙잡는 별도 지연은 추가하지 않는다.
- 384×824 인앱 브라우저의 한 세션에서 추천에 없던 '보관함으로 다가간다'를 선택했다. 대기 중 선택한 행 하나만 표시되고 입력이 잠겼으며, 응답 전후 속말 문단의 화면 위치가 유지된 채 결과가 그 아래 이어졌다. 결과 후 추천 3개가 복구됐고, 가로 넘침·콘솔 오류가 없었다. 이 UI 검증은 외부 요청을 차단한 모의 서버를 사용했다.
- 실제 Gemini 검증은 새 게임의 8개 행동으로 자재를 수집하고 작업대를 복원하는 장면 하나에만 사용했다. `gemini-3.5-flash-lite` 한 호출에서 첫 문단 1.274초, 생성 2.379초, 행동 전체 2.437초를 기록했다. 평균이나 보장 시간이 아닌 단일 표본이다.
- 이 실제 문장은 '거친 결'과 '매끄러운 표면'을 현재 관찰 근거 없이 추가했고, 복원한 작업대의 제작 시간 감소 효과를 전달하지 않았다. 당시에는 사실 ID 검사만 통과했으므로, 이 결과를 충실한 서술 성공 사례로 간주하지 않는다.
- 감각이 없는 장면에도 감각을 넣도록 읽히던 지침을 수정했다. 관찰에 없는 표면 질감과, 사용 효과가 빠지거나 감소율이 잘못된 필수 작업대 설명을 검사한다. 이미 검증된 문단은 유지하면서 잘못된 부분만 기본 서술로 마무리하며 생성 재시도는 하지 않는다. 이 검사는 알려진 오류를 다루며 모든 자연어 의미를 증명하는 장치는 아니다.
- `narration-grounding.test.cjs`와 기록된 장면 fixture로 실제 실패 문장을 재현하고, 근거 있는 감각 표현·잘못된 효과 수치·부분 스트림 복구·다른 작업 종류의 기본 서술을 확인했다. 관련 서술·스트리밍·역무실 테스트 39개와 빌드가 통과했다. 수정 후 실제 Gemini 재호출은 하지 않았다.

## 급식소·검문소의 공통 탐색 전환

- `civic-definitions.ts`가 급식소의 배식대·노파·폐자재 더미·식재료 상자, 검문소의 통신 차량·무전 기록·초소 주변을 고정 공간에 배치한다. 실제 미수집 재고는 기존 원장으로부터 투영하며 입장 시 내용물을 공개하지 않는다. 상자나 차량을 살핀 뒤 수집을 따로 선택한다.
- 배식대의 구매·배급표 교환·품삯, 노파의 통조림 전달, 무전 기록 확인·정찰은 공통 `interactionPoint`에서 기존 행동을 한 번 실행한다. 날짜에 따른 가격, 일일 업무 조건, 퀘스트 보상, 선택된 정찰 분기의 보상·부상과 중단 결과를 그대로 따른다.
- 거래는 별도 의미 계열로 묶어 추천에서 구매와 교환을 함께 나열하지 않는다. 전체 목록에는 조건을 만족하는 두 방법 모두 남는다. 배식대 접근을 입장 추천에 포함하며, 공개된 배식 서비스는 접근 직후 사용할 수 있다. 기록을 해독하는 것처럼 조사가 필요한 지점은 기존 관찰 조건을 유지한다.
- 노파는 배식대 옆 실제 인물로 배치된다. 가까이 다가가 대화한 뒤 같은 위치·자세로 돌아온다. 원래 지역 행동 ID로 탐색 조건을 우회하는 요청은 거절한다.
- 식재료 상자는 같은 방에서 밀어 옮길 수 있으며, 내용물과 재고 원장은 함께 유지된다. 배식대는 소유한 물건을 올려놓고 다시 챙길 수 있는 받침이다. 재고 보관함을 통째로 휴대하는 것은 계속 금지한다. `PUSH`는 같은 방 바닥에서 옆자리·통로 앞 관계만 허용하므로 재고를 다른 지역 소지품으로 넘기지 않는다.
- 기존 저장의 발견·부분 수집·관심 대상은 새 세계로 이행하고, 소진한 더미는 재방문으로 다시 생기지 않는다. 이미 작성한 방은 기본 방보다 우선하며 편집한 배치·재고 수량·행동 역할도 게시와 저장된 콘텐츠 버전에서 유지한다.

검증:

- `civic-text-world.test.cjs` 20개: 비공개 내용물, 실제 비용·보상 비교, 거래 조건, 퀘스트, 정찰 4분기, 작업 중 사망, 저장 이행, 게시된 편집값, 실제 NPC 대화 복귀, 기존 행동 우회 방지, 상자 이동·물건 놓기·재수집. `choice-director.test.cjs`의 기존 8개도 통과했다.
- `survival-ten-days.test.cjs`: 새로 제공된 선택과 지도·아이템 API만 사용한다. 자원과 시간을 주입하지 않는다. 낚시 실패 경로는 185개 행동(구매 6회·품삯 작업 4회), 성공 경로는 327개 행동(생선 72개·구매 없음)으로 10일에 도달했다. 식사를 하지 않고 휴식만 반복하면 3일차에 탈진으로 끝나는 대조 경로도 유지됐다.
- 병원의 기존 14개 회귀 검사를 확인했다. 숨은 금액 `275` 검사는 선택지 해시에 우연히 들어간 숫자를 오인하지 않도록 실제 사실과 표시 문구를 대상으로 고쳤다.
- 한 브라우저 검증 세션에서 배식대의 식사 구매·금액과 획득 표시, 지도 이동, 검문소 입장 → 차량 발견 → 별도 수집을 확인했다. 새 탭의 기본 크기를 다시 맞춘 뒤 검문소 흐름을 384×824로 실측했고, 가로 넘침·콘솔 오류가 없었다. 이후 공개 서비스의 접근 조건과 상자 물성 보완은 서비스·물리 테스트로 확인했다. 브라우저와 자동 테스트는 외부 생성 요청을 차단했으며 이번 전환에서 실제 Gemini 호출은 사용하지 않았다.
- 최종 빌드, 런타임 콘텐츠 검증, 변경 공백 검사 통과. 로컬 서버를 새 빌드로 재시작했다.

## 역무실 신호함 연결

기존 콘텐츠의 신호함은 역무실 벽면에 배치하고, 역무실의 단일 `textWorld`에서 다른 사물과 함께 접근·개방·수집한다. 개방 전에는 내용물을 공개하지 않으며 발견과 묶음 수집은 별도 선택이다. 안테나·고철·물의 수량과 각 수집의 시간·상태 비용은 기존 재고 규칙을 그대로 실행한다. 자세 변경 등 실제 준비 동작의 시간은 추가로 계산한다.

기존 신호함 메뉴는 노출과 직접 실행을 함께 차단한다. 예전 메뉴에서 저장한 게임은 이미 확인한 내용과 남은 재고를 보존해 신호함 앞으로 이행한다. 기존 역무실 저장에는 없는 재고 사물만 보완하고, 문·배치·수집 결과를 초기화하지 않는다. 이행과 일반 재조회에는 생성 API를 호출하지 않는다. Studio의 별도 배치와 삭제한 재고 정의도 존중한다. 콘텐츠 기본값 모듈은 실행 규칙에 의존하지 않아 서버의 모듈 로드 순서에 영향을 받지 않는다.

`subway-stock-world.test.cjs`는 발견과 별도 수집, 기존 비용과 준비 시간, 중복 실행 거부, 부분 수집 저장 이행, 기존 역무실 보존, Studio 우선권, JSONB 복원 후 선택지, 기존 메뉴 우회 차단과 대합실 복귀를 검사한다. 10일 생존 경로도 서버가 제시하는 역무실 입장 → 신호함 확인 → 묶음 수집 → 대합실 복귀로 변경했다. 이 연결은 API·엔진 테스트로 검증하며, 추가 실제 Gemini 호출과 브라우저 검증은 수행하지 않았다.

## 끊기지 않는 대합실·역무실·지하층 진입

지하철 도착 시 대합실도 실제 탐색 방으로 사용한다. 역무실에서 돌아오면 탐색을 종료하는 대신 같은 세계 안에서 대합실로 이동한다. 슈미는 저장된 위치에 있으며 가까이 다가간 뒤 대화할 수 있고, 대화를 마치면 그 자리에서 탐색을 이어간다. 지하층 계단 앞에서는 진입 의도를 첫 번째 선택으로 제시한다.

방의 `arrivals`는 출발한 이웃 방별 도착 위치·시선·통과 문장을 정의한다. 대합실에서 역무실로 들어오면 입구에 서며, 정비 복도에서 돌아오면 철문 앞에 선다. 서로 연결되지 않은 방을 출발지로 지정하면 콘텐츠 검증에서 거부한다. 실제 이벤트와 기본 서술도 같은 도착 데이터를 사용하므로 닫힌 철문을 통과한 것처럼 묘사하지 않는다.

`regionalExit`가 있는 탐색 지역은 지도 이동 전에 열린 통로를 따라 실제 출구까지 이동한다. 방 사이 이동과 자세 변경의 시간도 엔진에서 계산한다. 닫힌 문·통로를 막은 물건·확인할 수 없는 어둠 때문에 출구에 닿지 못하면 지도와 실행 양쪽에서 같은 이유로 차단한다. 물건과 관찰 기록은 지역 이동 뒤에도 보존한다.

계단의 `journey` 선택은 현재 `optionId + revision`을 검증한 뒤 기존 심층 탐험 엔진에 실행을 넘긴다. 진입 10분을 유지한다. 새 공간 전투는 공통 탐색 렌더러를 한 번 호출하며 기존 조우 생성은 호출하지 않는다. 비전투 상황과 구형 저장은 기존 조우 경로를 사용한다. 요청 영수증을 저장해 중복 클릭·연결 복구로 탐사를 두 번 시작하지 않는다. 후퇴·귀환하면 확정된 귀환 결과와 획득 표시를 유지한 채 대합실로 돌아온다.

기존 저장의 대합실 경계만 보완하고, 이미 열린 문·옮긴 물건·NPC 위치·수집 결과는 유지한다. 저장 불러오기·지도·아이템 조회·저장·복원에서 필요한 최초 이행은 기본 서술로 처리하며 Gemini를 호출하지 않는다. 실제 지역 이동으로 새 대합실 장면에 도착하거나 새로운 탐색 행동을 했을 때만 기존 서술 경로를 사용한다.

검증 근거:

- `subway-concourse-world.test.cjs` 6개: 도착·문맥에 맞는 입구·이동·NPC 복귀·지도로 출구 우회 금지·저장 이행·사용자 정의 입구·계단 진입 중복 차단·실제 후퇴 선택과 귀환을 검증한다.
- 수집·NPC·통합 경로 등 관련 40개 회귀 테스트의 바뀐 진입 경로를 갱신했다. 최초 실행에서 옛 종료·입장 및 오류 문구를 기대하던 3개가 실패했고, 실제 새 경로로 수정한 해당 테스트를 별도로 통과시켰다. 전체 대상 목록의 행동 76개, 자원을 주입하지 않은 49개 행동 통합 경로, 낚시 성공·실패 각각의 10일 생존 경로를 확인했다.
- 공간 서술 5개, 스트리밍 12개, 호출 예산 3개, 실제 수집·조리 경로 1개와 Choice Director 8개를 관련 범위에서 검증했다. 스트리밍 테스트의 초기 진입도 대합실에서 실제 제공된 역무실 이동 선택을 사용한다.
- 한 모바일 브라우저 세션에서 대합실 → 역무실 → 대합실 → 슈미 관찰·대화·복귀 → 계단 확인을 실행했다. 이동 본문의 잘못된 철문 진입 묘사를 발견해 출발지별 도착 데이터로 고친 뒤 새 빌드에서 확인했다. 384×824 실측, 본문에 이어지는 속말과 결과, 가로 넘침 없음과 콘솔 오류 없음을 확인했다. 실제 Gemini 요청은 추가하지 않았다.

최종 선택 우선순위 보완 뒤 같은 브라우저 세션에서 384×824로 다시 계단에 접근해 지하층 진입이 첫 선택으로 표시되는 것을 확인했다. 검증 탭과 모의 서버는 종료했으며, 로컬 3000번 서버는 최종 빌드로 재시작하고 `/api/health` 정상 응답을 확인했다.

## 지하층의 실제 수색·보관·층 왕복

지하층에서 위험 상황을 해결하면 같은 `textWorld` 안의 수색 구역으로 이어진다. 왼쪽 벽면 보관함·가운데 나무 상자·오른쪽 선반, 맞은편 철문과 계단실은 엔진이 작성한 공간 데이터다. 사물 배치와 재질은 생성문에서 추출하거나 추측하지 않는다. 공간 전투에서는 조우 중에도 같은 수색 구역을 탐색할 수 있으며 상대가 대응한다. 도주·실패 뒤에는 하강을 막고 귀환한다.

- 최초 수색에는 기존 15분(11층부터 20분)과 실제 접근·자세·개방 시간이 든다. 선택지에도 수색 시간을 표시한다. 보관함을 열기 전에는 물건이 노출되지 않으며, 발견 후 수집은 별도 결정이다. 선반에 접근만 한 상태를 빈 선반으로 기록하지 않는다.
- 새 탐사의 전투 승리는 전리품을 자동 지급하지 않는다. 기존 층 보상량과 특정 층의 확정 장비를 물리적 내용물로 배치한다. 기존 저장의 이미 지급된 승리 보상과 이미 수색한 장소는 다시 지급하지 않는다.
- 물건은 개별 ID와 `expeditionLoot` 출처를 유지한다. 귀환 전 원장은 `carriedLoot`, 기존 소지품 원장은 `inventory`다. 넣기·내려놓기·재수집·용기 휴대에서 두 원장을 각각 갱신한다. 임시 전리품은 아이템 메뉴에서도 보이고 사용할 수 있으며, 같은 종류의 기존 소지품보다 먼저 소비한다. 사용·파손 이후에는 물리적 사물도 정리한다.
- 층별 방과 사물은 같은 세계에 남고, `exploredFloors`는 층 정의와 진행 결과를 저장한다. 이전 층을 방문해도 보상·조우를 재생성하거나 Gemini를 다시 호출하지 않는다. 나무 상자로 철문을 막으면 계단실 이동이 차단되며, 지도나 원래 명령으로 이를 우회할 수 없다.
- 위층 계단 앞에서는 이전 층 방문과 탐사 종료를 구분한다. 층 왕복은 15분, 한 번에 귀환은 기존의 층당 5분이다. 이미 방문한 상층 통로가 막혔다면 일괄 귀환은 숨기고 직접 돌아가 통로를 확인하게 한다. 정상 귀환은 실제 휴대한 물건만 정산하고, 귀환 중 사망은 임시 전리품만 잃는다.
- 최초 장면을 만들기 전에 기존 소지품 이동과 손 상태 정규화를 완료한다. 저장 재조회로 추천 선택지가 바뀌지 않는다. 클라이언트에는 방의 숨은 사물, 층 보관 자료, 미관찰 전리품을 보내지 않는다.

검증: `subway-floor-world.test.cjs` 11개, 기존 대합실·신호함·호출 예산·스트리밍·도구·조명·선택지 검사와 지하철 조우 검사까지 71개를 최종 빌드에서 통과했다. 기존 보상 검사는 구형 저장 모드를 명시하도록 갱신했고 새 탐사의 승리 후 자동 수집 금지도 별도로 검사한다. TypeScript 빌드, `app-api.js` 모듈 구문 검사와 런타임 콘텐츠 검증을 수행했다.

한 모바일 브라우저 세션에서 입장 → 보관함 발견 → 별도 수집 → 내려놓기 → 같은 사물 재수집, 전리품의 아이템 메뉴 표시와 사용을 확인했다. 최초 재조회 때 선택지가 바뀌는 문제를 이 과정에서 발견해 정규화 순서로 해결하고 회귀 검사를 추가했다. 최종 화면은 384×824이고 가로 넘침·콘솔 오류가 없다. 속말·결과·획득 칩은 기존 본문 흐름을 유지한다. 검증에서는 실제 Gemini 요청을 사용하지 않았다.

전체 목표는 아직 완료로 보지 않는다. 공간 전투와 데이터 기반 도구 활용은 아래와 같이 연결했으며, 실제 생성문 독서 경험 검토가 남아 있다. 층의 수색 공간은 현재 고정된 두 방 구조다. 지하층의 큰 조우는 기존 생성 규칙과 테스트에 따라 전투로 유지하며, 비전투 조우의 추가는 이번 변경 범위에 포함하지 않는다.

로컬 3000번 서버는 최종 빌드로 재시작했으며 `/api/health`에서 HTTP 200을 확인했다. 검증 탭과 모의 서버는 종료했다.

## 전투와 탐색이 공유하는 공간

새 지하층 전투는 조우 상대를 같은 방의 실물 사물로 배치한다. 명중·피해·설득·후퇴·성장은 기존 서버 판정을 사용하고, 문·엄폐·소지품·탐색은 공통 세계의 행동과 사건으로 처리한다. LLM은 가능 여부나 피해를 결정하지 않는다.

- 적대적인 상대가 보이거나 그 위협을 기억하면 `THREAT`에서 공격·엄폐·설득·이동·위험을 감수한 수색을 서로 다른 의도로 추천한다. 가능한 다른 사물 조작은 `주변과 물건`에서 고른다. 같은 문을 닫는 선택을 두 슬롯에 중복 추천하지 않는다.
- 엄폐는 온전하고 불투명하며 충분히 큰 사물 뒤에서 몸을 낮춘 상태다. 이동 가능한 사물 또는 명시적인 `providesCover` 배치만 사용하므로 벽에 붙은 보관함 뒤로 들어갈 수 없다. 엄폐는 반격의 기본 확률을 30%p 줄인다. 일어서거나 자리를 옮기면 현재 자세와 위치로 다시 판정한다.
- 같은 방에 있지 않으면 근접 반격은 불가능하다. 상대가 열린 통로로 따라오거나 닫힌 문을 여는 데에는 한 번의 대응을 쓰고, 그때 동시에 공격하지 않는다. 잠긴 문과 통로를 막은 물건은 우회하지 못한다. `문을 건너가 닫는다`는 실제 이동·개폐 행동 묶음이다.
- 전투 중 수색·발견·수집·내려놓기도 같은 원장을 갱신한다. 새 발견에서 멈추며 수집은 별도 선택이다. 실제 동작 비용 뒤 전투 대응 5분을 표시·적용한다. 음식·약은 원래 사용 시간을 이미 냈으므로 반격 때문에 시간을 다시 차감하지 않는다. 조명은 아이템 메뉴에서 조작하며 상대도 대응한다.
- 도구를 손에 든 뒤 공격하면 선택한 실물의 내구도를 소모한다. 새로 실체화하는 도구는 개별 사물로 만들어 낡은 도구와 여분의 정체성을 보존한다. 공격·방어 수치는 아이템의 `combat` 정의를 사용한다. 새 도구는 명시한 속성 또는 베기·타격 능력으로 전투에 참여하며, 조명·지렛대 전용 도구와 `combat.kind: none`은 제외한다. 마지막 내구도를 소모하는 공격도 사용 전 판정 수치를 유지하고 여분 도구는 보존한다.
- 중간 개폐 실패는 수행된 동작과 중단을 구분한다. 실패한 준비 뒤 공격을 실행하지 않는다. 승리·설득 뒤에는 같은 공간을 탐색하고, 승리로 나온 성장 선택만 잠시 처리한다. 후퇴한 층에서는 계단 하강 우회를 막고 귀환한다.
- 행동당 공통 서술은 최대 한 번이다. 단순 조회·중복 요청·일치하는 조명 상태의 재요청은 추가 호출을 만들지 않는다. 서술 실패에도 확정된 판정과 요청 영수증을 저장한다. 상대의 이동·개폐는 행동 주체를 명시하고, 상대가 여는 문에 플레이어의 촉감을 덧붙이지 않는다.

검증: `subway-combat-world.test.cjs` 13개와 기존 층 탐색·대합실·재고·호출 예산·스트리밍·도구·조명·선택지·구형 조우 검사를 포함한 84개가 최종 빌드에서 통과했다. 저장소의 객체 키를 재정렬해 복원한 뒤 표시된 선택지를 실제 API로 실행하고, 전투 중 별도 수집·중복 요청·내구도 파손·아이템 반응·자동 문 닫힘·후퇴 우회 차단·생성 실패를 검증했다.

실제 Gemini 검증은 1회였다. 첫 LLM 문단은 약 1.3초, 전체 처리는 약 2.1초였다. 최종 사실 검사에서 `invalid_narration`이 발생해 유효한 첫 문단을 유지하고 뒤 문단을 기본 서술로 보완했다. 행동 주체와 진행은 보존했지만 전투 생성문의 전체 품질 검토는 통과로 간주하지 않는다. 후속 실제 검증에는 원문 trace를 함께 남겨 누락 원인을 판별했다. 관찰 후에는 아무 변화도 없는 전투 요약을 필수 서술에서 제외하고, 문을 건넌 직후 이미 문 앞인 상태에서 다시 접근하던 불필요한 이동도 제거했다. 이 조정 뒤 원문을 저장한 실제 검증을 한 번 더 실행했다. 첫 문단은 약 1.38초, 전체 처리는 약 1.86초였다. 결과 행동 3개는 표현했지만 새 방의 조명·배치·출입구 사실 3개를 누락해, 유효한 LLM 문단 2개 뒤에 기본 서술 1개를 붙였다. 추가 재시도는 없었으며 생성문 전체가 검사에 통과한 것으로 보지 않는다.

모바일 검증은 384×824의 한 브라우저 세션에서 수행했다. 엄폐 후 결과·속말·이전 문단이 이어지고, 사물 패널에서 철문을 골라 이동·닫기를 실행하면 상대의 개방까지 같은 본문에 출력된다. 이 과정에서 모바일의 공통 `.choice-list` 고정 배치가 패널 안 행동까지 사물 탭 위에 겹치던 오류를 발견했다. 패널 행동만 일반 흐름으로 돌린 뒤 `position: static`, 탭 하단보다 아래에 있는 행동 영역, 탭 중앙의 올바른 클릭 대상과 실제 행동 요청 1회를 확인했다. 가로 넘침과 콘솔 오류는 없었다.


도구 정의 확장 검증: 콘텐츠 편집기의 아이템 스키마와 저장된 콘텐츠 버전을 사용해 새 도구의 작업·공격·방어, 파손과 여분 보존, 전투 제외, 내구도 없는 도구, 잘못된 정의 거부 및 JSONB 복원을 확인했다. 관련 테스트 40개와 TypeScript 빌드가 통과했고 런타임 콘텐츠 레지스트리도 검증했다.

## 공간 서술의 사실 누락과 문단 검증

필수 사실은 행동 결과뿐 아니라 새 공간의 조명·배치·출입구 연결도 포함한다. 프롬프트에 현재 필수 ID를 명시하고, 각 문단의 `factIds`를 먼저 정한 뒤 해당 사실을 담는 `text`를 생성하게 했다. 문단별 역할은 고정하지 않으며 선택지 표현은 본문 뒤에 같은 요청으로 받는다. 사실을 필수 목록에서 삭제하거나 검사를 완화해 통과시키지는 않는다.

`inspectNarration`은 구조 오류, 문단 수, 알 수 없는 ID, 누락된 필수 ID, 행동 모순과 시점 오류를 구분한다. 최종 검사 실패는 `draft_validation` trace에 원문·필수 ID·실패 이유를 남긴다. Gemini의 JSON 파싱 성공 기록과 서술 검사 결과는 별개다. 기존 `invalid_narration` 시간 측정 값과 유효 문단 유지·기본 서술 보완·행동당 최대 한 요청은 유지한다.

실제 응답에서 관찰한 다음 오류를 문단 게시 전 검사에 추가했다. 단순히 ID가 모두 있다는 이유만으로 이 표현들을 통과시키지 않는다.

- 구별할 정도의 빛을 근거 없이 환한 빛으로 바꾸는 표현
- 완료한 문 닫기를 닫으려다 실패한 의도로 바꾸는 표현
- 이동 사건 없이 상대가 뒤따라왔다고 서술하는 표현
- 근거 없이 닫힌 문틈 너머로 손을 뻗는 표현

작성된 감각이나 실제 이동 사건이 있으면 해당 표현을 허용한다. 이 검사는 관찰된 오류를 다루는 제한된 검사이며 자연어 전체의 의미적 충실도를 증명하지 않는다.

검증: 원문 세 개를 `tests/fixtures/combat-room-narration.json`에 보존했다. `narration-space.test.cjs` 8개는 누락과 모순 진단, 스트리밍·비스트리밍 보완, 사실 ID를 먼저 쓰는 문단, 잘못된 첫 문단 게시 차단을 검증한다. 기존 서술·연속성·스트리밍·공간 전투·호출 예산 검사와 함께 55개 및 TypeScript 빌드가 통과했다.

이번 실제 Gemini 요청은 총 두 번이며 각각 한 번만 호출했다. 첫 문단은 약 1.38초와 1.32초, 전체 처리는 약 2.39초와 2.31초였다. 첫 요청은 조명 ID를 누락했다. 두 번째는 모든 ID를 썼지만 실제 독서 검토에서 밝기·문 닫기·상대 이동의 오류를 발견했다. 마지막 검사 보강 후에는 이 원문을 재생해 게시 차단을 확인했으며 실제 생성 요청은 추가하지 않았다. 따라서 새로운 전체 생성문의 독서 품질 검토는 아직 남아 있다. 화면 배치나 브라우저 동작은 이번에 바꾸지 않았다.

## 실제 물건의 투척과 소리를 확인하는 상대

원설계서 30장의 “병을 던져 다른 방향에서 소리를 낸다”를 실제 물건과 관찰에 연결했다. 추천 선택에 없는 착지 지점은 기존 `주변과 물건`의 소지품 목록에서 고를 수 있다. 물건을 손에 들고 위협을 받는 장면에서는 현재 자리와 엄폐물에서 떨어진 연결 공간을 우선 추천한다. 같은 계열의 투척을 여러 개로 채우지 않는다.

- `throwable`은 단위 무게와 작성된 충돌 소리를 가진 아이템·사물 속성이다. 물병과 고철 조각에 정의했고, 새로운 아이템 ID나 방 정의도 같은 규칙을 사용한다. 현재 규칙에서는 손에 지닌 2kg 이하의 단일 물건을 던진다. 실제 물리 무게도 함께 확인하며 빈 경량 용기는 던질 수 있다. 내용물이 있는 용기와 투척 속성이 없는 물건은 후보에서 제외한다.
- `THROW`는 스택에서 정확히 한 개를 분리한다. 분리된 실물은 고유 ID와 전리품 출처를 유지하고 착지 지점에 남는다. 일반 소지품과 임시 전리품의 원장을 구분해 차감하며 다시 주우면 같은 한 개만 돌아온다. 마지막 물건이면 손을 비운다. 명중·피해·파손을 임의로 부여하지 않는다.
- 같은 방에서 확인 가능한 사물 옆, 현재 방 바닥, 보이는 열린 통로로 바로 연결된 방 바닥을 고른다. 닫힘·잠금·통로를 막은 사물·먼 방·지역 바깥은 우회하지 않는다. 준비 중 문이 닫히면 이미 사용한 시간만 남고 투척과 소모는 실행하지 않는다.
- 충돌 소리는 실제 착지 구역에서 발생하며 기존 전파·감쇠 규칙을 사용한다. 주변 인물은 보지 못한 투척의 행위자를 소리만으로 알아내지 않는다. 서술은 실제 투척·소리·목격 가능한 상대 이동만 전달한다.
- 전투 상대는 마지막으로 본 플레이어 구역, 마지막으로 들은 소리, 확인 중인 소리 위치를 저장한다. 플레이어가 보이면 계속 대응하며, 보이지 않을 때 새 소리를 들으면 그 위치를 확인한다. 직접 본 이탈 경로는 기억하지만 관찰하지 못한 플레이어의 현재 구역을 그대로 따라가지 않는다.
- 소리 확인도 실제 통로를 사용한다. 닫힌 문을 열거나 한 구역 이동하는 데 대응 한 번을 쓰며 동시에 공격하지 않는다. 잠긴 문과 장애물은 통과하지 못한다. 같은 소리를 반복 처리하지 않고, 확인이 끝나면 기존에 알던 위치를 기준으로 움직인다. 엄폐는 새 시각 정보에 영향을 주되, 이미 가까이 있는 위험에 대한 기존 엄폐·반격 판정은 유지한다.
- 투척 동작은 3초이며 전투 중에는 기존 대응 5분을 함께 적용한다. 단순 대기와 아이템 소지·조작도 기존 선택 계약을 사용한다. 대화·서술 호출은 늘리지 않는다.

검증: `text-world-throwing.test.cjs` 9개에서 스택 분리·재수집·다른 지역 왕복, 전리품 원장, 잘못된 후보 제외, 준비 중 실패, 실제 제공된 선택의 실행·중복 차단, 보이는 투척과 엄폐한 투척의 차이, 문 개방·소리 확인 상태의 JSONB 복원, 관찰하지 못한 상대 이동의 비공개 처리를 확인했다. 공간 전투·시뮬레이션·선택·NPC 기억·서술·스트리밍을 포함한 대상 71개 중 처음 70개가 통과했다. 대합실을 아직 탐색 외부로 기대하던 기존 이행 검사 한 개를 현재 구조에 맞게 갱신하고 NPC 검사 5개를 별도로 모두 통과시켰다. TypeScript 빌드와 런타임 콘텐츠 레지스트리 검증도 통과했다.

모바일은 384×824 한 세션에서 실제 서비스의 물병 꺼내기 → 상자 뒤 엄폐 → 계단실 투척을 실행했다. 세 행동에 서술 요청은 세 번, 실제 Gemini 요청은 0번이었다. 물병은 2개에서 1개로 줄고 상대는 계단실로 이동했다. 속말과 두 결과 문단, `-1 물병`·`+5분 3초` 표시가 같은 본문 블록에 이어졌다. 가로 넘침과 콘솔 오류가 없었고 검증 탭·모의 서버는 종료했다.

전체 목표는 계속 진행 중이다. 이번에는 명시된 환경 활용 한 경로를 추가했으며, 생존자 전체의 자율 생활이나 모든 상황의 은신·청취 행동을 완료한 것으로 보지 않는다. 실제 생성문 독서 품질 검토도 이전 항목의 미완료 상태를 유지한다.

마지막으로 빈 경량 용기의 투척은 허용하고 실제 내용물이나 과한 물리 무게는 차단하는 경계를 보완했다. 해당 사례를 포함한 투척·세계 시뮬레이션 26개를 새 빌드에서 모두 통과시켰다.
