# 지속되는 세계와 소설형 나레이터 개선

## 목표와 범위

세계의 진실은 엔진과 저장에 존재하고, 나레이터는 실제 인식한 결과를 소설 문장으로 전달한다. 사물의 컴포넌트와 공간 관계를 조합하여 탐색·수집·배치가 다음 인식과 선택에 영향을 주도록 한다.

사용자의 후속 지침에 따라 자유 입력 대신 상황에 맞는 3~5개 의도를 제시하며, NPC·좀비·전투는 추가하지 않는다. 공간은 방과 사물의 관계 그래프이고 연속 좌표 물리는 아니다.

## 사용자가 선택한 B 문체

**감각과 시선이 머무는 소설체.** 주어를 주로 생략한 1인칭 현재형으로 움직임과 관찰을 연결한다. 문단 역할과 묘사 순서는 고정하지 않는다. 중요한 탐색은 2~3문단, 단순 조작은 짧게 쓴다.

> 상자 앞에 몸을 낮추자, 멀리서는 한 덩어리로 보이던 뚜껑에 갈라진 틈이 눈에 들어온다. 가장자리를 짚은 손끝으로 거친 나뭇결이 전해진다. 뚜껑을 들어 올리는 손을 따라 시선도 안쪽으로 내려간다.
>
> 물병 하나. 그 곁에 나란히 놓인 작은 고철 조각 두 개. 드러난 나무 바닥 위의 물건들을 차례로 살피다가, 물병의 마개에 시선이 머문다. 봉인은 그대로다.

위 문장은 문체 선택용 예시다. 실제 생성의 물건·감각·수량·접촉은 현재 관찰 정보에서만 가져온다. `narrative-style.ts`를 실제 Gemini 나레이터 요청에 연결했다.

## 구현 확인

- [x] `spatial.ts`에서 포함·지지·상대 배치를 계산한다. 이름과 ID가 달라도 같은 컴포넌트로 밀기·담기·올려놓기·내려놓기·회수가 작동한다.
- [x] 무게·수용량·접근·순환 포함·통로 막힘을 검증한다. 중간 실패 전까지 수행한 결과와 시간은 남는다.
- [x] 닫힌 불투명 용기는 빛과 시야를 가린다. 투명한 용기는 안이 보이지만 닫힌 뚜껑을 통과해 집을 수 없다. 중첩 용기와 위에 놓인 광원도 구분한다.
- [x] 문 앞의 상자 뒤로 몸을 낮추면 해당 통로가 가려진다. 몸을 일으키거나 나오면 시야를 회복한다.
- [x] `world-time.ts`가 탐색·지역 이동·제작·요리의 가상 시간을 모든 생성된 장소에 전달한다. 자리를 떠나도 광원의 연료와 문 자동 닫힘이 진행되며, 목격하지 않은 사건은 감춘다. 짧은 행동의 시간 누적과 저장 복원은 같은 긴 행동과 일치한다. 원인 ID와 목격 여부를 기록한다. 실제 네트워크 대기와 상태 조회는 게임 시간을 흐르게 하지 않는다.
- [x] 보이지 않는 환경 사건은 서술 결과에서 제외한다. 들리는 소리도 출처가 보이지 않으면 이름과 ID를 숨긴다.
- [x] 기존 인벤토리 소비를 물리적 사본에 반영한다. 지역 간 이동은 수량을 지급하지 않고 휴대 엔티티를 옮긴다. 기존 수집 저장도 남은 수량 범위에서 보완한다.
- [x] 편의점의 기존 재고·돈·보상·경험치·시간을 유지한다. 수집 사본은 재고와 별도 식별자로 남아 배치·회수해도 보상을 반복 지급하지 않는다.
- [x] 역무실과 편의점의 실제 선택지에 컴포넌트 기반 상호작용을 연결했다. 재정리나 일반 지역 귀환으로 선택지 수를 채우지 않는다.
- [x] Director가 초점과 사건별 사실 묶음을 제공한다. 기본 서사도 개방 뒤 발견, 묶음 수집, 현재 위치·자세, 제공된 소리를 연결한다.
- [x] 기존 콘텐츠 검증과 저장이 새 컴포넌트를 보존한다. 편집기의 중첩 목록과 안/위 구분을 보완했다.

## 상황 기반 선택지

세계 상태 → 인식 → 가능한 의도 → Interaction Context → Choice Director → 선택된 행동의 문장 표현으로 나눈다. 역무실과 편의점이 같은 Director를 사용한다.

- `availableWorldOptions`와 `interactionOptions`는 컴포넌트·접근 조건·실제 휴대를 기준으로 가능한 행동을 계산한다. 서버는 선택된 ID와 revision을 검사한 뒤 실제 행동 묶음을 실행한다.
- `interaction-context.ts`는 EXPLORE, FOCUS, MANIPULATE, THREAT를 계산한다. 관심 대상은 물리적으로 가까운 대상과 별도 저장한다. 시선을 돌려도 위치와 자세는 유지한다.
- `choice-director.ts`는 진행·정보·상황 활용·시선 전환·이동 같은 슬롯을 채운다. 점수는 슬롯 내부에서만 비교하고 같은 행동 계열은 한 번만 노출한다. 명시적 이야기 분기는 서로 다른 결정을 보존한다.
- 수집한 물건을 실제로 조작하는 동안에만 배치 행동을 보여 준다. 담기·올리기·내려놓기는 한 계열에서 하나를 고르며, 다른 대상에 접근하면 해당 대상과 가능한 배치를 다시 계산한다.
- 새 발견과 방금 얻은 열쇠의 사용을 우선한다. 최근 표시·선택 행동과 이미 확인한 정보는 감점한다. 시선을 돌린 뒤에는 이전 대상의 뚜껑 조작을 숨긴다. 읽기·폴링은 이력을 쓰지 않으며, 상태가 같으면 저장 복원 뒤에도 같은 선택 순서를 유지한다.
- THREAT는 현재 보이는 광원의 소진·실제 어둠·닫히는 문에서만 발생한다. 주변광이나 다른 광원이 있으면 소진을 위험으로 오인하지 않는다. 아직 없는 적이나 사건은 생성하지 않는다.
- LLM은 현재 결과 전체와 다음 선택지의 문구·짧은 독백을 같은 요청에서 표현한다. 선택지에 미리 작성한 행동 서사는 붙이지 않는다. 대상 이름·동작 계열·안/위·개폐·점등 방향이 어긋난 문구는 기본 문구로 되돌린다. 알 수 없는 선택 ID는 채택하지 않는다. 자연어 의미 전체를 정규식으로 증명하는 검사는 아니다.
- 초점을 옮길 때는 미확인 대상을 우선하고, 확인을 마쳐 비어 있는 보관함을 감점한다. 선택 이력의 서명에 관찰 상태를 포함하여 새로 알게 된 사실을 반영하면서 같은 상태의 읽기에는 순서를 유지한다.

일반 탐색은 3~5개를 목표로 한다. 모두 확인한 장소처럼 실제로 의미 있는 후보가 적은 상태에서는 이전 사용자 지침에 따라 재확인·귀환 중복으로 수를 채우지 않는다. 모든 보유 물건을 다시 꺼내는 인벤토리 조작 메뉴와 별도의 배치 목적지 화면은 이번 변경에 추가하지 않았다.

## 선택 직후 읽기 흐름

이전의 행동 시작 문장 선표시는 제거했다. 선택한 줄 아래에 **상황에 맞는 짧은 독백**을 표시하면서 이전 본문을 유지하고, 결과가 도착하면 실제 행동부터 완결된 장면을 이어 붙인다. 이때 한 번만 새 장면으로 스크롤한다. 타이핑을 건너뛰어도 다시 넘기지 않는다.

- 계산대: ‘돈이 좀 있을래나.’
- 상자: ‘안에 쓸 만한 게 남아 있을까.’
- 발견한 물건 수집: ‘챙겨 두면 쓸 일이 있겠지.’

독백은 궁금증이나 가벼운 의도를 나타내며 미발견 물건·수량·성공·행동 완료를 미리 서술하지 않는다. 버튼과 그 아래의 독백은 결과 수신 전까지 남고, 다른 선택은 잠근다. 결과가 오면 독백을 지우고 다음 선택으로 바꾼다. 결과 본문은 클릭 시 표시한 속말을 반복하지 않는다.

기존 500ms 활동 대기와 지역 이동 대기를 유지한다. 최소 연출 시간 이후에도 응답을 기다리는 동안 선택한 줄에 대기 표시를 이어 간다. 오류 시 조작을 복구하며 자동 재요청은 하지 않는다. 획득 칩·타이핑·이전 문단 읽기는 유지한다.

## 생성과 저장 계약

서버는 실제 결과와 함께 확정된 다음 선택의 ID·문구·계열·대상과 안전한 기본 독백을 보낸다. 모델 출력은 `{ paragraphs: [{ text, factIds }], choiceLabels: [{ optionId, label, thought }] }`다. 선택당 요청은 한 번이며, 독백용 추가 요청이나 미래 행동의 사전 생성은 없다.

현재 선택의 속말은 `intent.thought`에 전달한다. 다음 선택의 문구와 독백은 `world.choiceLabels`에 저장해 새로고침·재조회에도 유지한다. 필수 사실 누락·잘못된 사실 ID는 장면을, 부적절한 문구·독백은 해당 선택 필드만 기본값으로 되돌린다. 기존 저장의 `choiceNarratives`는 읽을 수 있지만 탐색 화면에는 내보내지 않으며 다음 렌더링에서 정리한다. NPC 대화도 후속 개선에서 같은 대기 방식으로 전환했다. NPC 반응과 다음 답변·속말을 한 번의 요청으로 받으며, 기존 대화 저장의 선행 서사는 다시 표시하지 않는다. 자세한 계약은 docs/npc-dialogue-flow.md를 따른다. 지하철 심층 조우도 본문과 다음 속말을 기존 요청 하나로 받으며, 실제 결과를 같은 층의 본문에 이어 붙인다. docs/subway-choice-thoughts.md를 따른다.

## 이전 세계·선택지 구현의 검증 기록

변경과 연결된 테스트를 나누어 실행했다: 세계 시뮬레이션 17건, 기존 역무실 22건, 편의점 10건, Studio 방 정의 4건, 호출 예산 3건, 선택지 시작 문장·문구 4건, 상황 기반 선택 7건, 본문·대기 흐름 26건. 빌드와 수정한 JavaScript의 구문 검사도 통과했다.

384×824 인앱 브라우저에서 입장·개방·문 앞에 밀기·가림·수집과 본문 연결을 확인했다. 같은 페이지에 시작 문장과 결과가 남고 가로 넘침·콘솔 오류는 없었다. 가림 뒤에 ‘앞에 머문다’고 쓰던 기본 서사 모순은 회귀 테스트로 수정했다.

새 선택지 흐름도 별도 메모리 세션에서 입장 → 상자 개방 → 수집 → 시선 전환으로 확인했다. 집중과 조작에 따라 선택지가 달라지고 배치는 하나만 노출되었다. 384×824에서 가로 넘침과 콘솔 오류는 없었다.

실제 Gemini는 이번 검증에서 호출하지 않았다. 프롬프트·요청 횟수·사실 전달 계약은 모의 제공자로 확인했다. **B 문체의 실제 생성 품질은 아직 검토하지 않았다.** 사용자가 허용한 호출 범위에서 진행할 별도의 독서 검토 항목이며, 모의 응답을 실제 생성 검증으로 간주하지 않는다.

## 이번 대기·독백·시간 변경의 검증

- 모의 Gemini 응답으로 완결된 결과·선택 문구·독백을 한 번에 받고, 저장 후 유지하며 중복 클릭 시 추가 요청을 하지 않는 계약을 확인했다. 누락·중복 ID, 잘못된 결과 독백, 제공자 실패도 검사했다.
- 384×824 인앱 브라우저의 독립 메모리 세션에서 계산대 선택 직후 ‘돈이 좀 있을래나.’가 선택한 줄 아래에 표시되고 이전 본문이 남는 것을 확인했다. 응답 뒤 독백은 제거되고 결과 블록만 한 번 추가됐다. 가로 넘침·콘솔 오류는 없었다.
- 세계 시간 6건과 기존 시뮬레이션·건강·편의점 회귀 테스트로 부재 중 진행, 한 번만 시간 적용, 저장을 거친 소수 시간 누적, 조회 시 정지, 치명적 상태의 중단 시점을 확인했다.
- 상황 선택 8건과 새 게임 생존 경로 1건을 통과했다. 생존 경로는 지역 탐색 → 재료 수집 → 벌목 → 화로·냄비·장작 제작 → 쌀죽 조리 → 섭취 → 재조회까지 실제 GameService의 선택으로 진행한다.
- TypeScript 빌드와 클라이언트 JavaScript 구문 검사를 통과했다. 실제 Gemini 생성은 호출하지 않았으며 자연어 품질 검토를 통과했다고 주장하지 않는다.
