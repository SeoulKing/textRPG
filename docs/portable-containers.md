# 휴대 용기와 재료 소유권

`portable`과 `container`를 함께 가진 사물은 내용물을 유지한 채 통째로 옮길 수 있다. 이미 수집한 재료를 휴대 용기에 담아도 제작·요리에 사용할 수 있으며, 방에 내려놓으면 해당 재료가 인벤토리에서 빠진다.

## 발견과 수집

물리적으로 지니고 있는 것과 인벤토리에 수집한 것을 구분한다. 런타임의 `inventoryRegistered`는 직접 수집한 물건임을 기억한다. 방 정의를 읽는 스키마에서는 이 런타임 필드를 받지 않는다.

- 닫힌 용기 자체를 챙겨도 미수집 내용물의 이름·수량을 인벤토리나 서사에 노출하지 않는다.
- 열어 내부를 확인하면 발견 단계에서 멈춘다. 내용물을 챙기는 결정은 다음 선택에 남긴다.
- 한 번 수집한 물건을 지닌 용기에 다시 담으면 수량을 유지한다. 다시 꺼낼 때는 새로운 보상을 지급하지 않는다.
- 용기를 방에 내려놓거나 바깥 보관함에 넣으면, 용기 자체와 이미 수집한 내용물의 수량을 함께 차감한다. 통째로 다시 챙기면 같은 물건만 되돌린다.

배치 전후의 소유 관계를 비교해 수량 차이를 한 번 적용한다. 안쪽 용기, 내부 물건, 위에 올린 물건도 같은 사물 그래프를 따른다. 용기 ID나 지역 ID별 보상 처리를 추가하지 않는다.

## 제작·소비·저장

제작과 요리로 인벤토리가 줄면 수집한 물리 사본에만 소비를 반영한다. 남은 물건의 수량과 용기 내부 위치를 유지하고, 전부 소모된 물건은 부모의 내용물 목록에서도 제거한다. 미수집 내용물은 같은 아이템 종류라도 대신 소비하지 않는다.

용기 자체가 소모되면 남은 내용물은 플레이어 소유로 보존한다. 그중 미수집 물건은 인벤토리에 자동 지급하지 않고, 이후 탐색에서 수집할 수 있는 상태로 남긴다. 이 경우를 포함해 저장 복원과 반복 보완으로 재료를 다시 지급하지 않는다.

기존 저장은 이미 지니던 낱개 재료를 현재 인벤토리 수량에 맞춘다. 옛 용기 안의 미수집 내용물을 임의로 보상으로 전환하지 않는다. 지역 이동 시 포함 관계·수집 여부·수량을 함께 옮기고, ID 충돌에는 기존 원본 식별자를 사용한다.

## 선택과 서술

휴대 용기로 관심을 옮기는 행동은 플레이어의 공간 위치를 바꾸지 않는다. 이미 손에 든 재료를 그 용기에 담을 때는 ‘용기 안에 넣는다’라는 한 의도로 실행한다. 필요한 손 조작은 내부 행동 묶음에 포함한다. `placementTargetId`는 그 과정의 배치 대상을 기억하며 물리 위치와 구분한다.

이미 소유한 내용물을 꺼낼 때는 ‘꺼내 손에 든다’와 ‘휴대 물건 꺼내기’로 표시한다. 새 발견이나 추가 보상처럼 표현하지 않는다. 용기 위에 올린 물건도 실제 선택지로 다시 집을 수 있다.

이벤트의 `inventoryDelta`는 실제 수량 변화를, `containedItems`는 함께 옮긴 이미 수집한 내용물을 전달한다. 모델에 숨은 내용물은 전달하지 않는다. 기본 서사도 단순한 위치 변경과 새 수집을 구분하며, 기존 요청 외에 생성 호출을 추가하지 않는다.

## 확인한 범위

신규 테스트 9건은 다음 경계를 확인한다.

- 닫힌 용기 휴대 → 개방·발견 → 별도 수집
- 지닌 용기에 담기와 꺼내기의 수량 보존
- 중첩 용기의 내려놓기·재수집·저장·지역 간 이동
- 실제 장작 제작으로 용기 내부 재료의 일부·전부 소비
- 용기 자체 소비 시 내용물 보존과 미수집 상태 유지
- 이전 저장 보완의 반복 안정성
- 현재 선택 목록을 통한 한 번의 담기 의도와 지지면 위 물건 재수집

기존 휴대·제작·선택지·물리 시뮬레이션·지하철·편의점 회귀 테스트와 첫 생존 제작·식사 경로도 검사했다. 관련 실패를 해결한 뒤 해당 경로를 다시 통과했다. TypeScript 빌드와 컴파일된 콘텐츠 검증을 통과했다.

384×824의 별도 메모리 게임에서 용기 수집 → 목재 수집 → 용기 보기 → 담기를 진행했다. 선택 직후 이전 본문과 독백을 유지하고 입력을 잠갔으며, 네 번의 선택 뒤 본문 블록은 입장을 포함해 다섯 개였다. 담기 결과는 시간만 표시했고 아이템 메뉴의 목재 x2를 유지했다. 가로 넘침과 콘솔 오류는 없었다. 이미 소유한 내용물의 꺼내기 문구는 이 확인 후 선택지 테스트로 검증했다.

브라우저 검증은 기본 서사와 격리된 재고를 사용했다. 사용자 저장과 실제 Gemini 할당량을 사용하지 않았다. 전체 목표의 다음 범위는 다른 지역의 탐색·고유 사건을 공통 엔진에 연결하고 실제 플레이에서 생존 선택의 재미를 검토하는 것이다.
