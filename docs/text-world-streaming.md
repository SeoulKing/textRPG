# 탐색 서사의 지연과 스트리밍

## 적용 범위

`text_world` 행동은 기존 `POST /api/games/:gameId/actions`에 `Accept: application/x-ndjson`과 `X-Action-Id`를 보내면 문단 스트리밍을 사용한다. `optionId + revision` 규칙은 유지한다. 일반 JSON 클라이언트, NPC 대화와 일반 지역 이동 응답도 호환된다. 새 지역 입장 과정의 일반 이동 요청은 기존 완성 응답을 사용하며, 입장 이후 텍스트 탐색 선택에 스트리밍이 적용된다.

클릭 직후 독백과 1초 채움 연출을 시작하고 요청도 바로 보낸다. 검사를 통과한 문단을 같은 본문에 타이핑하며, 뒤 문단이나 완료 응답에 다시 스크롤하지 않는다. 네트워크 읽기와 타이핑 큐는 분리하고, 최종 저장과 본문 표시가 끝난 후 선택지를 활성화한다. 먼저 읽은 문단은 최종 응답에서 다시 출력하지 않는다.

## 생성과 검증

- 본문 `paragraphs`를 먼저, 다음 선택지 문구와 독백을 나중에 작성하는 한 번의 Gemini 요청이다. 별도 선행 서사나 선택하지 않은 분기 생성은 없다.
- 소설 문체와 최근 세 장면은 유지한다. 수납·이동·조명·서비스·중단 규칙은 관련된 장면에만 추가하고, 현재 대상과 무관한 과거 관찰은 제외한다. 발견과 수집의 수량·단위 규칙은 공통으로 적용한다.
- 이미 가진 물건 꺼내기, 챙겨 두기, 시선 돌리기 등 단순 조작에 새 정보나 위험이 없으면 기본 서사를 사용한다. 아이템의 조명 제어는 기존 무호출 경로를 유지한다.
- 완성된 문단 객체의 사실 ID·시점·행동 표현을 검사한다. 아직 출력하지 않은 필수 사실을 기본 서사로 연결해도 전체 검증을 통과할 수 있을 때만 문단을 먼저 보낸다. 보완을 위한 문단 한 자리를 남긴다.
- 중간 오류·잘린 JSON·잘못된 ID가 있으면 이미 보낸 문단은 유지하고 남은 사실만 기본 서사로 보완한다. 문단별 출처를 저장해 재접속 시에도 혼합 서사임을 표시한다. 추가 생성 재시도는 없다. 자연어 의미 검사는 일부 규칙 검사이며 모든 의미적 오류를 판별하는 것은 아니다.
- 생성 제한 시간은 기존 20초를 유지한다. 측정 없이 임의로 더 짧게 잘라 기본 서사를 늘리지 않는다.

## 저장·재접속

게임별 기존 잠금 안에서 행동을 실행하고 마지막 성공 요청의 ID·행동·revision을 텍스트 월드와 함께 저장한다. 동일 요청의 즉시 재전송은 저장 결과를 반환한다. 다른 행동을 같은 ID로 보내거나 오래된 revision으로 선택하면 거부한다.

연결이 끊겨도 서버 처리는 저장까지 이어 간다. 클라이언트는 행동을 다시 POST하지 않고 `GET /api/games/:gameId/actions/:requestId`로 완료 기록을 조회한다. 조회도 네트워크 문제로 실패하면 세션 저장소에 요청 식별자를 남겨 새로고침 후 복원한다. 저장 전 서버 자체가 종료돼 기록이 없으면 새 행동으로 재실행하지 않는다. 이전 단계의 게임 상태가 남는다.

## 지연 기록

서버 `game action latency` 로그와 스트림의 완료 이벤트에 다음을 기록한다. 요청 본문이나 API 키는 지연 로그에 넣지 않는다.

| 필드 | 의미 |
| --- | --- |
| `queueMs`, `loadMs`, `rulesMs` | 요청 시작부터 잠금 진입, 저장 로드 완료, 서술 시작까지의 누적 시간 |
| `firstChunkMs` | Gemini 요청 시작부터 첫 텍스트 조각까지 |
| `firstParagraphMs` | 행동 요청 시작부터 첫 검증 문단까지 |
| `generationMs`, `saveMs`, `totalMs` | 생성 소요, 저장 소요, 전체 처리 시간 |
| `providerCalls`, `inputTokens`, `outputTokens`, `thoughtTokens` | 호출 수와 제공자가 반환한 토큰 사용량 |
| `narration`, `fallbackReason`, `replayed` | 생성·기본·혼합 여부, 대체 이유, 재전송 결과 재사용 여부 |

클라이언트의 `lastActionTiming`에는 첫 문단 수신·표시, 최종 응답, 이미지 준비, 표시 완료 시간을 추가로 기록한다. 일반 플레이 로그에서 지연 분포를 비교할 수 있으며 별도 측정용 생성 요청은 필요 없다.

## 검증 결과 — 2026-09-07

자동 검증은 UTF-8/SSE 분할, JSON 조각, 첫 문단 선전달, 중간 실패 보완, 잘못된 사실 ID, 중복 수집 방지, 저장 정규화 및 새 서비스에서 복원, 오프라인 요청 보존, 단순 조작 무호출을 포함한다. 기존 탐색·아이템·서사 이어붙이기 테스트도 확인했다.

384×824 인앱 브라우저에서 모의 응답의 뒷부분을 보류한 채 독백과 첫 문단, 입력 잠금을 확인했다. 완료 후 스크롤은 529.5px로 유지됐고 문단 중복·가로 넘침·콘솔 오류가 없었다.

실제 Gemini 생성은 총 2회였다. 첫 호출에서 단위가 없는 쌀을 ‘한 봉지’라고 쓴 사례를 발견해 발견 장면의 프롬프트와 검사를 보완했다. 수정 후 동일 장면은 첫 문단 1,278ms, 두 번째 문단 1,526ms, 전체 생성·검증 완료 2,431ms였다. 모델은 `gemini-3.5-flash-lite`, 입력 3,240 토큰, 출력 235 토큰, 요청 1회였다. 발견 뒤에도 인벤토리는 비어 있어 수집이 자동 실행되지 않았다. 이 값은 해당 장면의 단일 측정이며 서비스 전체 평균이나 기존 버전 대비 속도 개선율이 아니다.
